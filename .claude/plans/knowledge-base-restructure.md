# 知识库中文目录重构实施计划

## 目标

将仓库从 `docs/` 与根目录混合承载的结构，迁移为中文一级目录：

- `知识/`：稳定技术与领域知识
- `研究/`：产品、公司、案例与外部事实研究
- `洞察/`：个人判断、战略、行业与职业思考
- `项目/`：家庭营养师与 SPC × DeepSeek Harness 实战项目
- `个人/`：个人档案、职业资料、简历和证书
- `资料/`：仅保留暂时无主题归属或跨主题公共原始资料
- `管理/`：全仓库规范、模板、索引、迁移记录和仓库级计划

具体项目的设计、计划、规格、决策和专属资料跟随项目，不放入全局管理目录。主题专属原始资料跟随研究、洞察或项目；原始资料目录只接收暂时未归属或公共资料。

## 执行策略

1. 先创建目标目录骨架和导航 README。
2. 使用 `git mv` 保留文件历史；不删除正文，不覆盖现有文件。
3. 优先迁移两个边界最清晰的实战项目：
   - `docs/family-knowledge-compounding-pov/nutrition-agent-pov/` → `项目/家庭营养师/`
   - `spc_dsh/` → `项目/SPC-DeepSeek-Harness/`
4. 家庭营养师项目的上层 ideas、deployment、product、spec 分别归入：
   - 项目内部 `想法/`、`部署/`、`设计/`、`计划/`
   - 尚未成项目的家庭财务点子保留在家庭营养师项目的 `../` 独立点子区域，统一落入 `洞察/草稿/应用点子/`
5. 将 `docs/technology/` 迁移到 `知识/技术/`；`docs/semiconductor-data-concepts.md` 迁移到 `知识/领域/半导体/`。
6. 将 `docs/product-analysis/` 拆分到 `研究/产品/`、`研究/案例/`、`研究/模板/`，并保留产品分析的主题层级；连山自身产品诊断与 AI Native 工程设计也作为研究文档保留，项目内部设计不与外部研究混淆。
7. 将 `docs/companies/` 迁移到 `研究/公司/`；公司求职笔记仍迁移到 `个人/职业/`。
8. 将 `docs/insights/` 迁移到 `洞察/`，并按现有主题先保留文件名，避免第一轮过度重命名；图片随对应洞察主题迁移。
9. 将个人资料迁移到 `个人/`。
10. 将 `docs/raw_material/` 和无法判断归属的根目录图片迁移到 `资料/待整理/`；项目或研究专属图片跟随所属目录。
11. 将 `docs/superpowers/` 按归属拆分：家庭营养师设计/计划进项目；全仓库级计划和迁移记录进 `管理/`；企业 AI 转型计划属于洞察主题，迁移到 `洞察/企业AI转型/` 或其过程记录子目录。
12. 批量更新 Markdown、代码配置和项目 README 中的旧路径；对链接逐项验证，不修改外部 URL。
13. 清理仅属于原目录的 `.DS_Store` 不纳入新结构；不触碰已忽略的 `node_modules`、`dist`、coverage 等生成物。
14. 运行路径扫描、Markdown 链接检查、Git 状态检查和项目测试/类型检查；如测试受环境或依赖影响，明确记录原因。

## 风险与处理

- 中文路径会影响少量绝对路径、脚本和文档示例：迁移后统一搜索旧前缀，并优先修复项目 README、部署文档和 package/config 中的路径。
- `docs/product-analysis/industrial-ai-platforms/` 同时包含外部产品、连山自身研究和 AI Native 设计：第一轮按“研究事实/架构反推”保留在 `研究/产品/工业AI/`，后续再把正式 SPC/家庭项目设计收敛到项目内部。
- 原始资料归属不明时不强行分类，统一放入 `资料/待整理/` 并在 README 中说明。
- 不在本轮批量改写正文内容；只改路径、导航和必要的文件名。

## 验收标准

- 顶层目标目录存在并有 README。
- 原有已跟踪正文全部有唯一新归属，无意外丢失。
- `docs/` 不再承载正文；如保留，仅放迁移说明。
- `spc_dsh/` 不再作为独立顶层项目目录。
- Markdown 和配置中的仓库内部旧路径不再有未处理引用，或明确属于历史引用的外部项目路径。
- 项目代码、测试、配置和部署文档相对路径可用。
- Git diff 能清楚显示迁移、README 和引用修复；不提交 Git。
