# 团队知识工程方案整体更新计划

## 目标

将方案文档统一收敛到以“创作会话”为核心的 Team Knowledge Workbench 信息架构：

```text
Team Knowledge Workbench
├─ 工作台
│  ├─ 从资料创建知识
│  ├─ 从工作流创建 Skill
│  ├─ 最近创作
│  └─ 待处理事项
├─ 知识创作会话：材料 → 梳理 → 确认 → 提交 → 发布
├─ Skill 创作会话：描述 → 建模 → 生成 → 测试 → 发布
└─ 资产与发布
   ├─ 已发布知识
   ├─ 已发布 Skill
   ├─ 发布记录
   └─ 反馈候选
```

## 原则

- “从资料创建知识”和“从工作流创建 Skill”是启动动作，不是独立后台页面。
- 每次创作都是独立、可暂停、可恢复、可并行的 Creation Session。
- 会话、草稿、资产修订、正式发布、发布记录、交接记录和 Harness Session 分层。
- 多会话隔离对话上下文、材料、草稿、异步操作、回调和审计；同一资产并行修改采用 base revision、版本冲突检测和人工合并。
- DeepSeek Harness 交接只能从已批准/已发布资产开始；Harness 的 discovery、load、run、tool call 和运行时人工审批属于下游。

## 修改范围

1. `方案/00-方案总览与关键决策.md`：产品定义、核心 IA、并行会话原则、状态分层和 MVP 标准。
2. `方案/01-问题、用户与产品范围.md`：用户从工作台进入创作会话、恢复/并行创作、待处理事项和边界。
3. `方案/02-端到端知识工作流.md`：知识五阶段、Skill 五阶段、多会话与反馈回流。
4. `方案/03-知识资产与生命周期.md`：Creation Session、Draft、Asset Revision、Release、Handoff、Feedback 的层级。
5. `方案/04-角色、治理与运营机制.md`：会话 owner、协作者、审核、冲突和交接职责。
6. `方案/05-系统架构与权威边界.md`：会话控制面、session-scoped retrieval、异步隔离和 Harness 边界。
7. `方案/06-数据、状态与可追溯性.md`：session/draft/asset/release/downstream 状态、字段、并发和追踪链。
8. `方案/07-发布、安全与故障处置.md`：从 approved revision 发布、会话权限、幂等、未知状态和回滚。
9. `方案/08-MVP实施、验证与验收.md`：P0-P3、并行会话、隔离、冲突、恢复和 DSH 交接验收。
10. `方案/09-工作台信息架构与核心对象.md`：作为 IA 权威文档重写。
11. `方案/10-Workflow到Skill的生成、测试与发布.md`：作为 Skill 创作会话专项设计重组。

## 实施顺序

- 先建立 00/09 的术语和 IA 基线；
- 再更新 01/02/10 的用户流程；
- 再更新 03/05/06 的对象、状态和架构；
- 再更新 04/07 的治理与故障；
- 最后更新 08 的实施和验收；
- 全目录检查旧导航、阶段、对象边界、DeepSeek Harness 运行时越界和 Markdown 链接/格式。

## 验收

- 支持同一用户同时处理多个知识/Skill 创作会话；
- 会话上下文和草稿不会串线；
- 同资产并行修订不会静默覆盖；
- 暂停恢复不会产生重复 MR/release；
- 反馈候选只能启动新修订会话；
- 交接只能从已发布资产开始；
- 文档不把 `published`、`handoff_verified`、`loaded`、`running`、`succeeded` 混为一谈。
