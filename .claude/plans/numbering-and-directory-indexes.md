# 文件编号与目录索引重构计划

## 目标

基于当前已经确定的知识库边界，清理历史编号带来的混乱，并为较大目录建立可持续维护的目录说明和文件索引。编号只表达**当前目录内的阅读/管理顺序**，不再表达全仓库写作历史。

## 编号规则

### 基本规则

1. 每个目录独立编号，从 `01` 开始；不使用跨目录连续编号。
2. `README.md` 保持不编号，作为目录入口和维护说明。
3. 文件名格式统一为：`NN-主题名称.md`，使用两位数字；超过 99 个文件时再扩展为三位数字。
4. 同一目录中的编号按照阅读/使用顺序排列，而不是按照创建时间排列：
   - 先总览和基础概念；
   - 再机制、案例和方法；
   - 最后比较、计划、开放问题或附录。
5. 编号只用于人类文档。代码、SQL migration、配置文件、图片、PDF、生成物和领域数据文件不强行改名。
6. 已有业务语义编号不随意覆盖：例如家庭营养师菜谱的 `001`、数据库迁移的 `0001`、截图和外部资料文件名，这些是数据或外部标识，不是目录排序编号。
7. 文件移动或重命名必须使用 `git mv`，不复制正文，不保留重复 source of truth。

### 目录级 README 规则

较大或具有独立维护边界的目录统一维护 `README.md`，包含：

- 目录职责和不应放入的内容；
- 文件命名和编号规则；
- 当前文件索引表：编号、文件名、内容概述、状态、关联目录/项目；
- 来源和验证边界；
- 后续维护入口；
- 如果目录属于产品/竞品研究，增加持续更新的比较维度和当前比较矩阵；
- 如果目录属于项目，增加项目边界、设计文档入口和实现状态。

竞争产品不在每篇产品研究中重复横向比较，而是在产品研究根目录和必要的产品类别目录维护独立的 `对比分析.md`，记录比较日期、维度、证据来源、已验证事实、推断和待补问题。

## 链接与引用修复

1. 先建立旧路径 → 新路径映射表，再批量更新 Markdown、MDX、JSON、YAML、TS/JS、Shell 和项目配置中的引用。
2. 更新相对链接、README 索引、图片链接、项目文档交叉引用和研究中的关联文档路径。
3. 对外部研究对象的仓库内部路径、产品代号和历史引用，不误改成当前仓库路径；必要时明确标注“原仓库路径”。
4. 不修改敏感信息、部署地址、Token、`.env` 和生成物。

## 验证

- 每个纳入编号范围的目录中，文档编号唯一、连续或明确留有空位说明；README 不编号。
- 脚本检查所有 Markdown 相对链接、图片和 PDF 链接可达。
- 检查 README 索引中的文件都存在，索引不遗漏纳入管理范围的文档。
- 检查重复文件名、旧编号引用和空目录。
- 使用 `git diff --stat`、`git status` 和迁移统计复核历史保留情况。
- 不提交 Git，除非用户另行明确要求。
