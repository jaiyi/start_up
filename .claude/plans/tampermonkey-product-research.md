# Tampermonkey 产品调研与归档计划

## 目标

调研 Tampermonkey（油猴）这一浏览器 Userscript Manager 产品，整理其定位、用户脚本模型、核心能力、生态、平台支持、权限与安全边界、商业/开源状态及对本项目的启发，并归档到 `研究/产品`。

## 归档位置

新建产品分类目录：

- `研究/产品/浏览器自动化/README.md`
- `研究/产品/浏览器自动化/tampermonkey.md`

将其归类为“浏览器自动化 / 用户脚本运行时”，而不是编程 Agent 或 Agent Runtime：Tampermonkey 的核心是把用户编写或安装的 JavaScript 脚本注入网页并提供脚本生命周期、权限 API 和管理界面；它本身不是面向代码仓库的 Agent，也不是通用模型运行时。

## 研究内容

1. 产品定位与用户脚本工作模型：安装/编辑/启停/匹配网页/注入执行/更新与卸载。
2. 核心功能：脚本 Dashboard、浏览器工具栏 Popup、自动更新、配置模式、脚本同步、脚本发现与安装、调试与日志能力。
3. 技术模型：UserScript 元数据块（`@match`、`@include`、`@exclude`、`@require`、`@resource`、`@grant` 等）、隔离执行环境、页面上下文与扩展上下文、GM_* API、跨域请求和菜单/通知/存储能力。
4. 平台与版本：Chrome、Microsoft Edge、Firefox、Safari、Opera Next；区分当前官方产品与 GitHub 开源仓库（仓库 README 明确仅覆盖 2.9 及以前，更新版本采用专有许可证）。
5. 生态与分发：Tampermonkey 官网、浏览器扩展商店、用户脚本站点/URL 安装，以及脚本作者、用户、站点兼容性之间的生态关系。
6. 安全与治理：脚本拥有网页操作和部分浏览器/网络能力；安装第三方脚本等同于运行不可信代码，需要审查来源、权限、更新链、域名范围、`@require` 依赖、敏感数据、同步和企业策略。
7. 产品判断：它不是单纯的“插件”，而是“网页层可编程扩展运行时 + 用户脚本分发与管理控制面”；分析其低代码/浏览器自动化、流程嵌入、确定性脚本执行与 AI Agent 工具接入的关系。
8. 对本项目启发：网页自动化应将意图解析与确定性脚本分离，建立脚本注册、权限声明、预览、人工确认、版本、回滚、审计和沙箱机制；可比较浏览器扩展、Bookmarklet、RPA、MCP 浏览器工具和 Agent Skill 的边界。

2. 检查所有来源链接与相对链接；
3. 执行 `git diff --check`；

5. 本阶段不提交、不推送，除非用户另行明确要求。

## 不在本次范围

- 不安装浏览器扩展或执行第三方用户脚本；
- 不运行任何可能访问真实业务系统、读取敏感信息或修改网页数据的脚本；
- 不把 Tampermonkey 当作 AI 产品，也不虚构其具备 Agent、RAG 或 MCP 原生能力；
- 不对官方闭源版本源码做未经证实的内部实现推断。
