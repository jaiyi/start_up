# 团队知识与 Skill 双资产方案 PDF 生成计划

## 目标

将当前方案和验证材料汇编成一个便于评审、打印和分享的中文 PDF，排版紧凑但保持层级、表格、代码块和页眉页脚可读。

## 汇编范围

按当前 README 的阅读顺序合并：

1. 方案总览与关键决策
2. 问题、用户与产品范围
3. 端到端知识工作流
4. 知识与 Skill 资产模型
5. 角色、治理与运营机制
6. 系统架构与权威边界
7. 数据、状态与可追溯性
8. 发布、安全与故障处置
9. MVP 实施、验证与验收
10. 验证材料说明
11. 平台与 Provider 能力验证
12. DeepSeek Bot 能力评估

README 作为 PDF 封面/摘要使用，不把目录说明重复放入正文。PDF 内部链接转换为章节引用或省略。

## 输出方式

- 生成一个项目内 PDF：`项目/团队知识工程/团队知识与Skill双资产AI工作台方案.pdf`；
- 生成一个临时 HTML/CSS 中间文件用于排版，不作为项目长期文档保留；
- 优先使用系统已有的浏览器打印能力（Google Chrome headless）生成 PDF，避免安装依赖；
- 中文字体使用 macOS 可用字体，优先苹方/冬青黑体等系统字体并提供无字体时的 fallback。

## 排版规则

- A4 纵向；
- 页面边距约 12–14mm；
- 正文 9.5–10.5pt，行距 1.35–1.45；
- 一级标题 17–19pt，二级标题 12–14pt，三级标题 10.5–11.5pt；
- 表格使用 8–9pt，自动换行，避免横向溢出；
- 代码块使用 7.5–8.5pt 等宽字体和浅色背景；
- 标题尽量不孤立在页尾，表格允许跨页但重复表头；
- 页眉显示项目名，页脚显示页码和“内部方案”；
- 重要架构图和状态机保留等宽布局；
- 章节之间使用紧凑分隔，不为每篇 Markdown 强制新起一页。

## 实施步骤

1. 读取所有当前 Markdown，按既定顺序拼接并生成带章节标记的 HTML；
2. 实现 Markdown 子集转换：标题、段落、列表、表格、代码块、引用和分隔线；
3. 应用紧凑中文打印 CSS；
4. 使用 Chrome headless 输出 PDF；
5. 用 `pdfinfo`/`mdls` 或文件检查确认 PDF 可打开且页数/大小合理；
6. 若有 PDF 文本提取工具，抽查标题、Skill、WeKnora、目录和末尾章节是否完整；
7. 确认临时中间文件不进入项目；
8. 运行 `git status` 和 `git diff --check`，不提交或推送 PDF，除非用户另行要求。

## 验收标准

- PDF 文件存在且可被系统预览打开；
- 中文不乱码；
- 12 个章节均存在且顺序正确；
- 知识与 Skill 双资产主线完整；
- 表格和代码块没有明显横向截断；
- 版式比逐篇 Markdown 导出更紧凑；
- 工作区只新增用户要求的 PDF，不留下临时 HTML/CSS。
