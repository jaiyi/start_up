# 兆易创新公司研究证据治理实施计划

## 目标

把 `研究/公司/11-gigadevice.md` 从混合型调研笔记收敛为可持续复核的公司研究 canonical source，同时不把未经核验的内容伪装成事实，也不删除原有研究信息。

## 范围

1. 在文档头部建立统一元数据：调研日期、观察日期、文档状态、证据覆盖状态和下一次整体复核日期。
2. 按内容类型重组章节边界：公司事实、财务与经营、产品与业务、合作关系、行业观察、AI/工业方向、招聘与岗位推测、个人求职判断。
3. 为高时效或高影响内容建立“证据登记表”，至少包含：内容区段、主张摘要、主张类型、来源、发布日期、观察日期、证据等级、适用范围、失效条件、下一次复核日期和复核状态。
4. 对当前没有明确来源的数字、股权关系、产品发布、客户名单、薪资、组织归属、工作文化和岗位职责进行显式标记，统一写成“待核验”或“推测”，不补造来源。
5. 保留个人求职判断，但明确它不是公司事实，并与 `个人/职业/面试准备/兆易数据应用面试.md` 保持单向引用关系。
6. 更新 `研究/公司/README.md` 的公司研究规则，补充证据登记表和时效信息的最低要求，使后续公司文档可复用。

## 实施步骤

1. 读取并梳理现有章节，建立主张分类和风险清单。
2. 修改 `11-gigadevice.md`：补充元数据、章节边界、证据登记表和待核验标记；只做结构和证据治理，不删除原始内容。
3. 修改 `研究/公司/README.md`：把证据登记表列为公司研究的最低交付格式，并说明高风险内容的复核规则。
4. 检查内部链接、Markdown 格式和文档中是否仍有未经标记的确定性时效表述。
5. 运行 `git diff --check`，审阅完整 diff，确认没有意外的大段删除或路径变化。

## 约束与取舍

- 当前没有可靠来源清单时，不把搜索结果或记忆写成事实；证据不足的内容只标记，不臆测补全。
- 不在本批次引入全库状态机、收件箱、自动索引或周期审计机制；长期维护机制仍按此前决定暂缓。
- 不迁移 `研究/产品/工业AI/lianshan/`，不处理家庭营养师和理想汽车案例等其他待办事项。
- 本批次不提交 Git，除非用户另行明确要求。

## 验证标准

- 兆易文档的事实、观察、推测和个人判断边界清晰。
- 所有高风险时效性区段均能在证据登记表中找到对应记录，缺来源者明确显示为待核验。
- README 的规则与实际文档格式一致。
- `git diff --check` 通过，内部链接没有新增断链，原有正文没有被意外覆盖。
