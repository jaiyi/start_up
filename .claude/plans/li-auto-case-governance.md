# 理想汽车案例安全与责任边界治理计划

## 目标

把 `研究/案例/理想汽车/` 从“案例叙述 + 顾问判断”进一步收敛为可复核的案例研究入口：保留来源中的能力描述，但不把未经授权、未经验证或高风险的自动化能力直接当作生产事实或可迁移方案。

## 范围

1. 更新 `研究/案例/理想汽车/README.md`：增加统一治理字段、风险分级、证据状态和阅读规则。
2. 新增 `研究/案例/理想汽车/案例治理矩阵.md`：按业务对象、AI 参与边界、工具权限、写入/副作用、人工门槛、审计/回滚、证据状态和未决问题横向登记全部案例。
3. 对以下高风险案例增加“安全与责任边界”小节，使用最小侵入式补充，不删除原始案例叙述：
   - 嵌入式软件智能调试工具（真实硬件、烧录、内存/寄存器写入）；
   - 工艺设计合规性智能评审系统（CATIA 直连、ECR 转单）；
   - 设计变更智能评审助手（iframe/RPA、系统鉴权、自然语言规则）；
   - 三维装配路径校核工具（专业软件脚本、人执行、工程数据）；
   - 工厂安全管理智能助手（作业许可、风险评估、法律责任）；
   - 充电业务研发全流程智能体（代码修改、部署、经验自动固化）；
   - 设备维修全生命周期管理系统（设备维修、工单、现场执行和安全）。
4. 对新增和修改内容明确区分：来源原文声称、本文分析判断、已验证能力、待核验风险和禁止直接迁移的部分。

## 统一治理字段

每个案例在矩阵中至少登记：

- 来源与证据等级；
- 案例状态（来源描述 / 设计蓝图 / 试点 / 已验证运行 / 生产落地未知）；
- 业务对象与潜在影响；
- AI 参与边界；
- 外部系统、专业工具或硬件；
- 工具权限级别（只读、生成草稿、可执行低风险动作、敏感写操作）；
- 是否产生写入或不可逆副作用；
- 人工确认、审批和责任主体；
- 审计日志、读回校验、回滚或失败补偿；
- 失败模式与残余风险；
- 当前未决问题和禁止直接迁移项。

## 关键边界结论

- iframe 穿透、RPA 和“无需鉴权”只能记录为来源描述或待核验风险，不能表述为合规方案；正式集成应优先走官方 API/数据网关、最小权限、用户身份和可审计授权。
- DebugForge 的读取、控制、烧录、内存/寄存器写入、脚本执行和真实芯片操作必须分级；默认只读，敏感操作需要显式人工确认、目标环境隔离、命令—读回—审计和失败处置。文档中未证实的防护不能补写成事实。
- 工艺评审发现不合格项后，自动生成 ECR 默认登记为候选/草稿；是否提交、审批、发布和后续设变执行必须由授权责任人完成，误报/漏报和重复转单需可追溯。
- 安全风险评估、作业许可和应急处置中的 Agent 输出只能作为辅助材料或预审结果，不能替代安全员、审批人、现场负责人和法定责任主体。
- 代码修改、数据库改动、生产部署和运维动作保留人工门槛；“prod 禁用”或 Skill 配置属于当前案例描述，不等于已完成企业级权限、审计和回滚验证。
- 经验自动沉淀为 Skill、规则或知识时，先保存原始轨迹和证据，再经 owner 审核、验证、版本登记和回滚设计后发布；错误经验不得自动升级为组织规则。
- CATIA 等专业软件案例继续采用“专业工具做确定性判断、AI 做编排、人在真实环境执行或确认”的保守边界。

## 实施步骤

1. 读取当前 README 和高风险案例，保持原始事实、分析判断和待核验问题不被混写。
2. 在 README 增加治理说明与矩阵入口。
3. 新建案例治理矩阵，覆盖当前目录全部案例；不能确认的字段填“待核验”，不推断为已落地。
4. 在七个高风险案例末尾或可信度判断后加入边界小节，分别记录授权、工具权限、人工门槛、审计、回滚/补偿和禁止迁移项。
5. 检查是否产生“绕过鉴权”“自动发布”“AI 自主完成”“审批替代”等未经限定的确定性表述；必要时以“来源描述 + 本文治理判断”修正语义。
6. 运行 Markdown 链接检查、`git diff --check`，审阅 diff，确认未删除原始案例正文和图片路径。

## 不做

- 不声称已经完成外部安全认证、生产授权核验或真实部署验证。
- 不删除或重写原始案例的核心叙述，不把案例研究改成项目实施方案。
- 不在本批次拆分设备维修长文档；拆分仍留在后续结构性收敛批次。
- 不直接实现 iframe/RPA、DebugForge、ECR、部署或维修工具。
- 不处理第四批个人研究与决策操作系统长期维护机制。
- 不提交 Git，除非用户另行明确要求。

## 验收标准

- README 提供统一治理字段和矩阵入口。
- 矩阵覆盖目录内全部案例，且每个高风险案例具备明确的写操作、人工确认和责任边界记录。
- 七个高风险案例均有安全与责任边界小节。
- 来源事实、研究判断、验证状态和待核验风险清晰分层。
- “绕过鉴权”“自动 ECR”“真实硬件写入”“安全审批”等内容不再被无条件表达为可直接迁移的生产模式。
- 原始正文、图片链接和现有案例导航未被意外删除或破坏。
- `git diff --check` 和 Markdown 链接检查通过。
