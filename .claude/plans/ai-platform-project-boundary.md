# 调整 AI 平台项目边界

## 目标

将 `项目/AI-Native任务闭环平台/` 从“独立实战项目”调整为上层方向性洞察材料，避免把尚未具备代码、测试和真实验证边界的概念性平台蓝图误标为项目；同时明确 `项目/SPC-DeepSeek-Harness/` 是 AI 平台方向下的具体试点项目。

## 处理方案

1. **迁移架构设计材料到洞察**
   - 将现有 `项目/AI-Native任务闭环平台/设计/01-总体工程架构.md`、`02-连接层与MCP工具网关.md`、`03-任务状态与动态状态层.md` 整理为 `洞察/AI原生转型/` 下的连续设计材料，采用 `19` 起的编号，避免覆盖现有 01–18 文件。
   - 将设计目录 README 的定位改为洞察补充材料说明，保留其来源、文档索引和“概念设计/待试点验证”边界；不再声称已进入项目工程实施。
   - 新文档保留原有架构内容，但在标题和导语中标明：这是平台方向的设计推演，不是已实现能力；具体验证以 SPC 试点为准。

2. **关闭旧项目目录的歧义**
   - 用 `项目/AI-Native任务闭环平台/README.md` 替换为重定向说明，而不是保留一套看似可执行的项目设计副本。
   - 重定向 README 指向 `洞察/AI原生转型/04` 及新增的 19–21 设计材料，并指向 `项目/SPC-DeepSeek-Harness/` 作为具体试点。
   - 保留目录以避免历史链接失效；不删除未产生实际实现的材料。

3. **更新项目与研究索引**
   - 更新 `项目/README.md`：只保留家庭营养师、SPC-DeepSeek-Harness、个人研究与决策操作系统等实际项目，并明确 SPC 是 AI 平台方向的场景试点。
   - 更新 `项目/SPC-DeepSeek-Harness/README.md`：说明上层洞察、试点目标、当前已验证能力、待验证假设及“通用能力只有经过试点验证才能回流”的规则；同步现有目录描述（计划和决策已并入设计时避免写出过时结构）。
   - 更新 `研究/产品/工业AI/README.md` 和 `项目/个人研究与决策操作系统/设计/06-资本与生态信号雷达.md` 中指向旧项目设计目录的链接/表述。
   - 更新 `洞察/AI原生转型/README.md`，将 19–21 纳入索引，阅读路线改为“方向判断 → 平台设计推演 → 具体试点验证”。

4. **检查引用和质量**
   - 全仓库搜索旧路径和旧项目定位，仅保留重定向 README 中的兼容说明及必要历史引用。
   - 检查相对链接、Markdown 格式和 `git diff --check`。
   - 不提交、不推送，等待用户明确要求。

## 不做的事情

- 不把 AI Native 总体平台蓝图直接并入 SPC 项目，避免把通用假设误写成 SPC 已验证能力。
- 不删除洞察中的既有 04 文档，不复制其完整正文；19–21 作为架构推演补充，通过链接与 04、06、SPC 试点建立关系。
- 不自动宣称任何平台能力已经落地，验证状态由 SPC 项目的真实实现、测试和运行记录决定。
