# 06 · 资本与生态信号雷达

## 1. 信号定位

硅谷投资机构、融资事件、基金公开投资逻辑和资本生态变化，可以作为发现未来方向的重要线索，但不能直接当作产品能力、客户采用或商业成功的证据。

```text
资本下注：投资机构认为某个方向值得配置资源
产品研究：产品实际上提供什么能力
采用证据：客户、用户和真实场景是否在使用
生态动量：开源、Release、社区、招聘和集成是否增长
```

资本信号的作用是提前暴露可能重要的能力层，再把资本叙事翻译为可验证的产品问题、架构假设和项目实验。

## 2. 为什么纳入当前雷达

GitHub 趋势可以告诉我们哪些项目正在变热，产品研究可以告诉我们它们如何工作，资本信号则提供另一种时间更早的方向线索。三者结合后，才可能识别：

- 尚未成熟但正在被连续下注的基础设施层；
- 可能从平台功能发展为独立产品的能力；
- 通用 Agent 技术正在进入哪些具体业务场景；
- 当前研究和项目可能遗漏的竞争方向。

资本雷达不是用来追逐所有融资新闻，而是用来发现与个人长期方向相交的候选。

## 3. 首批重点方向

### Agent Runtime / Harness / 执行基础设施

关注模型、沙箱、浏览器、工具调用、长任务、durable execution、权限、trace、审计和成本控制如何形成独立基础设施。

对应项目：

- `项目/SPC-DeepSeek-Harness/`：当前 AI 平台方向的具体场景试点；
- `洞察/AI原生转型/`：AI Native 任务闭环平台的上层方向判断和设计推演；
- 连山工业 Agent 方向。

### Agent Control Plane / 组织治理

关注 Agent 目标、任务分配、Heartbeat、预算、审批、组织角色、责任链和多 Agent 协作是否形成独立控制面。

重点问题：

```text
Agent 如何成为组织中的工作角色？
谁负责分配任务、限制预算和审批动作？
Agent 的产出如何进入绩效和责任链？
```

### Coding Agent / 软件工程自动化

关注代码上下文、计划、编辑、测试、长任务、失败恢复、权限、项目记忆和反馈学习。Coding Agent 是目前较早验证 Agent 任务闭环的场景，但工业现场不能直接照搬其模型。

### Agent Memory / Eval / Observability

关注运行轨迹、评测、经验蒸馏、长期记忆、错误经验治理和 Skill 复用，判断 Agent 竞争是否从“一次回答”转向“持续改进能力”。

### 知识库 / 语义层 / 本体 / 数据治理

关注企业知识、业务对象、本体、语义层、权限、血缘、数据质量和 Agent 上下文之间的关系。核心问题是 Agent 是否真正理解设备、工单、人员、产线、质量问题等业务对象及其约束。

### 工业 AI / 制造 AI

重点关注设备状态监测、故障诊断、预测维护、工业视觉、工艺质量、排产、现场工作流、边缘部署和价值归因，并与理想汽车设备维修案例、连山和 SPC 方向交叉比较。

## 4. 四信号交叉验证

对每一个资本候选对象，至少补充以下四类信号：

| 信号 | 说明 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| Capital Signal | 融资事件、领投方、投资逻辑、融资阶段 | 资本对方向的关注 | 产品一定成熟或成功 |
| Product Signal | 官方产品、仓库、文档、Release、代码行为 | 产品实际存在和能力边界 | 客户大规模采用 |
| Adoption Signal | 客户案例、用户反馈、部署证据、使用频率 | 真实使用和价值线索 | 技术机制一定可迁移 |
| Momentum Signal | Star/Issue/PR、贡献者、招聘、集成、社区变化 | 生态活跃和发展速度 | 商业模式已经成立 |

### 优先级建议

```text
立即研究：资本信号 + 产品可验证 + 与当前项目高度相关
持续观察：资本信号 + 方向相关，但产品或采用证据不足
暂不处理：只有融资新闻，没有产品细节，也缺少项目关联
```

单一大型基金、融资金额或媒体报道不能单独提高候选优先级。对早期项目可以因为新颖性进入观察队列，但必须标记证据不足。

## 5. 资本事件最小数据结构

```yaml
id: capital-YYYYMMDD-序号
company: 公司名称
product: 产品名称
announced_at: 公布日期
round: Pre-seed | Seed | Series A | ...
amount: 可选
lead_investors: []
source_urls: []
source_type: official | investor | press | database
related_topics:
  - agent-runtime
  - industrial-ai
related_projects:
  - 项目/SPC-DeepSeek-Harness/
  - 洞察/AI原生转型/
capital_thesis:
  - 投资方公开描述的方向判断
product_evidence:
  - official-docs
  - github-activity
  - customer-case
  - public-demo
adoption_evidence: []
momentum_evidence: []
evidence_level: low | medium | high
status: watching | research_candidate | researched
next_action:
  - verify-product-capability
  - compare-with-existing-research
  - design-small-experiment
```

其中 `capital_thesis` 必须区分投资方原话与自己的解释；`product_evidence`、`adoption_evidence` 和 `momentum_evidence` 不能用融资新闻替代。

## 6. 流转方式

```text
融资/投资事件
   ↓
提取公司、产品、投资方和公开投资逻辑
   ↓
映射到个人关注主题、已有研究和项目
   ↓
补充产品、采用和生态动量证据
   ↓
形成研究候选或持续观察项
   ↓
事实研究与横向比较
   ↓
洞察候选：支持、修正或挑战既有判断
   ↓
项目输入：架构问题、可验证假设或小实验
```

系统最终要回答的不是“某公司拿了多少钱”，而是：

```text
这笔投资暴露了什么能力方向？
它和哪些已有研究、洞察、项目有关？
它支持、修正还是挑战了什么判断？
应该先检查哪个产品机制？
能否设计一个低成本实验验证其可迁移性？
```

## 7. 资本信号的研究输出

一篇由资本信号触发的研究，不应只写融资新闻，至少应包含：

1. 资本事件事实和来源；
2. 投资方公开表达的市场判断；
3. 产品实际能力和证据边界；
4. 客户采用、开源活跃度或其他生态动量；
5. 与已有研究对象的差异；
6. 对当前项目的可能启发；
7. 仍然缺少的证据；
8. 建议的下一步研究或项目实验。

## 8. 反误判规则

资本信号容易造成几类认知偏差，系统必须主动提示：

- **权威转移**：知名投资机构下注，不代表个人必须接受其判断；
- **金额崇拜**：融资金额不等于技术深度、客户价值或可迁移性；
- **叙事替代**：投资备忘录和媒体报道中的市场叙事不是产品事实；
- **幸存者偏差**：只能看到被报道的融资公司，看不到未融资但有价值的项目；
- **时间错位**：资本下注可能发生在产品验证之前，不能当作成熟度证明；
- **领域错配**：面向消费或 Coding Agent 的能力不一定适合工业现场；
- **确认偏见**：只收集支持既有判断的投资新闻，忽略反例和失败项目。

## 9. 与项目的关系

资本信号只有在转译成项目问题后才真正有价值。例如：

```text
资本关注 Agent Control Plane
→ 检查 SPC Harness 是否需要任务领取、预算和审批对象
→ 设计一个最小任务控制实验
→ 验证是否比现有固定工作流更有价值
```

```text
资本关注工业预测维护
→ 对比理想汽车设备维修案例和连山方案
→ 区分预测、诊断、工单、复盘和知识沉淀的能力边界
→ 选择一个设备任务闭环进行验证
```

资本信号不应直接改变项目架构；它只能提高某个问题的研究优先级，最终是否纳入项目要由证据和实验决定。
