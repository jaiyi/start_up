# 01 · 总体架构与目标

## 1. 要解决的问题

当前知识积累链条是有效的，但主要由人工主动驱动：个人先发现信息，再把信息带入对话，随后手动决定是否研究、是否形成洞察、是否关联项目。这个流程容易出现三类断点：

1. 外部重要信号没有被发现或没有被及时记录；
2. 新研究没有自动关联到既有研究、洞察和项目；
3. 项目完成后的验证结果没有反哺知识、雷达和下一轮项目设计。

因此，本项目建设的不是一个自动写文档工具，而是一个带有状态、证据、候选判断和人工确认机制的个人研究操作系统。

## 2. 五个子系统

```text
Signal Radar       外部信号雷达：发现变化和候选对象
                    ├── 人工捕获
                    ├── GitHub / 官方发布
                    ├── 行业案例
                    └── 资本与生态信号
Research Pipeline  研究流水线：形成事实、机制和证据
Insight Engine     洞察引擎：跨对象比较并提出判断候选
Project Copilot    项目助手：生成相关上下文和设计输入
Learning Loop      学习反馈环：把实践结果转成知识和新问题
```

### Signal Radar

扫描 GitHub 项目增长、Release、官方博客、技术文档、资本与生态信号和用户主动捕获的信息。资本信号用于发现方向，不等于产品能力证据；雷达输出“候选对象”，不能直接把趋势判断当作事实。

### Research Pipeline

针对候选对象生成研究任务，区分官方事实、代码观察、公开资料和工程推断，记录来源、证据等级、未决问题和下一步动作。

### Insight Engine

把多个研究对象放在一起比较，生成洞察候选、冲突证据和决策问题。正式洞察必须经过个人确认，不允许仅凭自动相似度写入。

### Project Copilot

根据项目目标，关联高相关研究、已确认洞察、已验证知识、历史决策和未决问题，生成项目上下文包，辅助架构评估和方案取舍。

### Learning Loop

读取项目测试、实验、运行记录、Issue、决策和失败原因，生成知识候选以及对既有判断的验证/推翻结果，并更新下一轮研究优先级。

## 3. 核心数据对象

| 对象 | 作用 | 最低字段 |
|---|---|---|
| Signal | 外部信号或个人捕获输入 | 来源、时间、原文、链接、捕获者、隐私级别 |
| Capital Signal | 融资事件、投资方公开判断和资本生态变化 | 公司/产品、轮次、投资方、来源、资本论点、相关主题、证据等级 |
| Candidate | 待判断的产品、项目、案例或趋势 | 主题、相关项目、优先级、证据状态、下一步 |
| Research | 外部对象的事实研究 | 对象、来源、事实、机制、不确定性、相关节点 |
| Insight Candidate | 由研究综合出的待确认判断 | 候选判断、支持证据、反例、影响、确认状态 |
| Project Input | 可用于项目设计的研究/洞察集合 | 项目问题、输入来源、适用边界、待验证假设 |
| Validation | 项目实践反馈 | 原始假设、实验、结果、结论、可复用性 |
| Knowledge Candidate | 经过验证的方法候选 | 方法、验证来源、适用条件、限制、审核状态 |

## 4. 人工控制点

自动化可以负责捕获、去重、分类、关联、摘要、候选生成和提醒；以下事项必须保留人工确认：

- 正式洞察的采用、修改或撤回；
- 未经项目验证的内容升级为长期知识；
- 涉及敏感资料、个人数据或企业内部信息的外发；
- 任何项目代码、部署、业务写回或高风险工具执行；
- 删除原始证据或覆盖已有判断。

## 5. 成功标准

不是生成更多文档，而是逐步实现：

1. 外部信号可以低成本进入系统；
2. 每个候选对象都有明确下一步；
3. 研究可以自动找到相关历史内容；
4. 系统能够将资本信号与产品能力、采用证据和生态动量交叉验证，而不是把融资新闻直接当作结论；
5. 项目设计自动得到相关上下文；
6. 项目结果会反哺知识和研究优先级；
7. 系统持续给出教育性问题，而不是只推送链接。
