# 团队知识工程

> 面向 40 人业务团队的知识生产线：让非程序员把资料变成有来源、有人负责、可检索、可复核的团队资产。

## 当前状态

当前处于 **P0：边界与能力侦察**。本项目的核心任务不是先做一个大而全的 Agent 平台，而是先跑通一个低风险知识域的一条闭环：

```text
资料 / 会议 / 复盘
  → 收件箱
  → 知识卡片草稿
  → 贡献者确认
  → steward 审核
  → Git/CI 发布
  → WeKnora 索引确认
  → 带来源和版本的检索
  → 反馈与复核任务
```

没有经过目标环境验证的 DSH、WeKnora、SkillHub、DeepSeek Bot、Console 或 Gateway 能力，均不得视为已经集成。

## 当前决策

- 正式知识的源文件、评审、版本和回滚以 Git 为准。
- WeKnora 只做已批准知识的检索投影，不决定内容是否正式。
- DSH 是执行和运行入口，不拥有正式知识。
- 业务人员不需要直接操作 Git；平台 owner 用工作流和 coding agent 隐藏技术复杂度。
- 模型负责提取、摘要、分类和起草；脚本负责确定性门禁；人负责事实、范围、敏感性和发布责任。
- 先做模块化单体 + 持久化 worker，只有出现真实规模或复用证据才拆 Gateway、Plugin 和多 provider。
- Skill、Bot 协作和高风险生产写入不属于首期硬依赖。

## 当前阶段判定

- **已决定**：产品边界、MVP 链路、权威来源、人工控制点和阶段顺序。
- **待验证**：目标版本的 API、索引状态、插件扩展、SkillHub 发布和 Bot 集成能力。
- **延后**：完整 Console/Gateway、多 provider、Skill 生产发布、Bot 协作和高风险写入。
- **禁止**：模型直接发布知识或 Skill、Agent 直接 push/merge `main`、用网页自动化绕过审批、把运行时 Memory 当正式知识。

## 与其他项目的边界

`项目/SPC-DeepSeek-Harness/` 是验证 DSH/Agent 平台能力的业务试点；本项目沉淀可复用的团队知识生产线边界和方法。

`研究/产品/Agent资产与团队治理/` 记录外部产品事实和横向选型；本项目只记录团队自己的决策、验证和实施结果。

## 维护规则

- 方案目录回答“应该怎样设计和落地”；验证目录回答“外部能力实际证明了什么”。
- 每个关键决策只有一个权威位置；其他文档通过链接引用，不重复改写。
- 所有状态都必须有证据；provider 超时、回调丢失和状态未知不能展示为成功。
- 不提交生产 Token、Cookie、密码、业务原文或个人敏感信息。
