# 方案总览与关键决策

> 本文是方案的唯一决策摘要。它定义范围、方向和阶段；具体流程、资产、架构和验收分别见后续文档。

## 1. 一句话定义

这是一个面向 40 人业务团队的**知识生产线**，不是新的聊天机器人、向量数据库或企业 Agent 平台。

它要把资料、会议记录、复盘和业务规则转成：

- 有来源的知识；
- 有责任人的知识；
- 经过审核并可检索的知识；
- 能被反馈、复核和回滚的知识。

## 2. 当前只解决一件事

首期只选择一个低风险、可回放的知识域，服务 5–8 名真实使用者，跑通：

```text
输入资料
  → 候选收件箱
  → Agent 起草知识卡片
  → 贡献者确认事实和范围
  → steward 审核
  → Git/CI 形成正式版本
  → WeKnora 索引并读回确认
  → DSH/检索返回来源和版本
  → 用户反馈
  → 复核任务与新变更
```

首期不追求文件、Skill 或 Bot 数量，唯一要证明的是：团队是否减少了重复整理和重复提问。

## 3. 核心决策

| 决策 | 当前结论 |
|---|---|
| 产品边界 | 知识生产、发布、检索、运行反馈和复核闭环 |
| 正式源 | Git + MR/CI + 人工审核 |
| 检索投影 | WeKnora，只接收已批准内容 |
| 执行入口 | DSH；能力未验证时允许轻量 Web/API 向导 |
| 首期控制面 | 模块化单体 + 数据库任务表 + worker |
| 业务体验 | 业务人员只提交、确认、审核、查询、反馈，不直接操作 Git |
| Skill | P3 以后做非生产试点，不作为知识闭环前置条件 |
| Bot | 可选协作层，不是知识治理或企业控制面 |
| 高风险动作 | 必须人工确认、最小权限、读回真实状态并可回滚 |

## 4. 四条不可破坏的原则

1. **一类对象一个权威写入面**：Git 保存正式源文件；WeKnora 做检索投影；DSH 做执行；反馈只生成候选和任务。
2. **状态必须有证据**：请求发出、HTTP 200、模型说完成，都不等于业务成功。
3. **自动化降低成本，不替代责任**：模型起草，脚本校验，人确认事实和发布责任。
4. **任何能力都可人工接管**：依赖不可用时回到人工 MR、管理员索引或人工补偿。

## 5. 阶段顺序

| 阶段 | 要证明的结果 | 进入条件 |
|---|---|---|
| P0 | 样本、角色、schema、状态机和外部能力边界清楚 | 开始写真实集成前 |
| P1 | 一个知识域可生产、审核、索引、检索和反馈 | P0 证据齐全 |
| P2 | 复核队列和质量运营持续运行 | P1 有真实使用 |
| P3 | 一个低风险 Skill 在非生产环境可回归、pin 和回滚 | P1/P2 稳定 |
| P4 | 只有在出现规模/复用瓶颈时才演进 Console/Gateway | 触发证据出现 |
| P5 | Bot 协作、Plugin 和生产写入 | 安全、审批、回滚证据齐全 |

阶段由退出证据推进，不按日历自动升级。

## 6. 成功标准

MVP 退出时：

- 非程序员不操作 Git 也能完成一条闭环；
- 正式条目有 owner、来源、适用范围、版本和复核日期；
- 检索结果能反查来源、版本和 Git commit；
- 索引失败不覆盖旧的可用版本；
- 反馈只产生复核任务，不静默修改正文；
- 关键动作能关联 actor、job、asset、版本和审计记录；
- 故障时可回到人工流程。

北极星指标是：**有引用的有效知识使用次数**。
