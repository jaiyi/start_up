# 数据、状态与可追溯性

## 1. 三类状态

### 知识资产

```text
captured → candidate → reviewing → approved → publishing → published
```

异常/终态：`index_failed`、`index_unknown`、`stale`、`deprecated`、`rejected`、`manual_required`。

### 异步操作和运行

```text
created → queued → running → waiting_human → succeeded
                                      ├→ failed
                                      ├→ timed_out
                                      ├→ cancelled
                                      └→ unknown → reconciling → succeeded/failed/manual_required
```

`accepted` 只表示本地校验通过；`timed_out` 只表示本地等待超时；`succeeded` 必须有真实结果或人工验证证据。

### 反馈复核

```text
created → triaged → assigned → in_progress → resolved
                                  ├→ rejected
                                  ├→ deferred
                                  └→ escalated
```

## 2. 最小数据模型

早期使用关系表或等价持久化模型：

```text
workspace
actor
asset
asset_revision
source_reference
operation
job
approval
run
feedback
review_task
audit_event
```

关键字段必须能关联：`workspace_id`、`actor_id`、`asset_id`、`source_commit`、`idempotency_key`、`correlation_id`、`state_version`、`last_error_code`。

## 3. 最小追踪链

```text
actor
  → operation
  → job
  → asset revision
  → Git commit/MR/CI
  → WeKnora index job
  → run
  → feedback/review task
```

若引入 DSH/DeepSeek Bot，再追加 `dsh_session_id`、`bot_id`、`room_id`、`exchange_id`。资产版本和知识引用必须由系统注入，不能从模型文本中猜测。

## 4. 幂等和恢复

- 所有创建、提交和反馈写操作使用 idempotency key，重复请求返回原 job 或结果；
- 状态更新带 expected state 或 state version，旧回调不能覆盖新状态；
- 重试前先读回 provider 状态，禁止盲目重复创建；
- worker 崩溃后由租约扫描恢复，无法确认时进入对账；
- 事件落库后再确认接收；
- 删除优先软退役，保留旧版本和审计。

## 5. 证据规则

| 状态 | 必须证据 |
|---|---|
| candidate | 输入引用、生成 run |
| reviewing | steward、差异和待确认项 |
| approved | commit、CI、approval |
| publishing | index job ID |
| published | 真实 index confirmation、document/version |
| index_failed | 错误码、重试或补偿任务 |
| unknown | 对账记录和人工处理状态 |
| succeeded | 实际结果或人工验证 |

任何 provider 超时、Webhook 丢失、状态矛盾都不能猜测为成功。

## 6. 数据保护

业务原文、密钥、Cookie、密码、个人敏感信息和工具敏感参数不能进入 Git、WeKnora 正文、长期 Memory 或 trace。trace 默认记录 ID、版本、耗时和结果状态；正文只有在明确授权和脱敏后才采集。
