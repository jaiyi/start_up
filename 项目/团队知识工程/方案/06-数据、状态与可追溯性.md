# 数据、状态与可追溯性

## 1. 资产状态

### 知识

```text
captured → candidate → reviewing → approved → publishing → published
```

异常/终态：`index_failed`、`index_unknown`、`stale`、`deprecated`、`rejected`、`manual_required`。

### Skill

```text
requested → scaffolded → authoring → validating → reviewing → approved → beta → stable
                                                   ├→ blocked
                                                   └→ rejected
stable → withdrawn/deprecated → retired
```

### 发布/装载不能混为一谈

- `approved`：源文件、契约和审核通过；
- `published`：知识索引真实确认或 Skill package 分发真实确认；
- `loaded`：DSH profile 实际装载了固定 Skill digest；
- `succeeded`：一次运行有真实结果或人工验证；
- `stable`：Skill 经过明确治理批准，可供指定 profile 使用。

## 2. 运行和反馈状态

### 异步运行

```text
created → queued → running → waiting_human → succeeded
                                      ├→ failed
                                      ├→ timed_out
                                      ├→ cancelled
                                      └→ unknown → reconciling → succeeded/failed/manual_required
```

### 反馈复核

```text
created → triaged → assigned → in_progress → resolved
                                  ├→ rejected
                                  ├→ deferred
                                  └→ escalated
```

反馈任务必须标明目标：`knowledge_review`、`skill_regression`、`permission_review` 或 `platform_incident`。

## 3. 最小数据模型

```text
workspace
actor
asset
asset_revision
knowledge_dependency
skill_contract
skill_test_case
profile
source_reference
operation
job
approval
release
installation
run
feedback
review_task
audit_event
```

关键字段：`workspace_id`、`actor_id`、`asset_id`、`asset_type`、`source_commit`、`knowledge_version`、`skill_version`、`package_digest`、`profile_version`、`idempotency_key`、`correlation_id`、`state_version`、`last_error_code`。

## 4. 最小追踪链

```text
actor
  → operation
  → job
  → asset revision
  → Git commit/MR/CI
  → release/index job/installation
  → profile
  → run
  → knowledge refs + skill digest + tool calls
  → feedback/review task
```

若引入 DSH/DeepSeek Bot，再追加 `dsh_session_id`、`bot_id`、`room_id`、`exchange_id`。资产版本、知识引用和 Skill digest 必须由系统注入，不能从模型文本猜测。

## 5. 幂等和恢复

- 所有创建、提交、发布、装载和反馈写操作使用 idempotency key；
- 状态更新带 expected state/state version，旧回调不能覆盖新状态；
- 重试前先读回 provider 的 branch/MR/index/package/profile 状态；
- worker 崩溃由租约扫描恢复；无法确认进入对账；
- 事件落库后再确认接收；
- 删除优先软退役，保留旧版本、digest、审计和回滚 pin。

## 6. 状态证据

| 状态 | 必须证据 |
|---|---|
| knowledge published | index confirmation、document/version/source |
| skill approved | Git commit、CI、contract/test、approval |
| skill beta/stable | release、digest、profile compatibility、批准和回滚 pin |
| loaded | DSH read-back 的 profile 和 digest |
| succeeded | 实际结果或人工验证 |
| unknown | 对账记录和人工处理状态 |

业务原文、密钥、Cookie、密码、个人敏感信息和工具敏感参数不能进入 Git、WeKnora 正文、长期 Memory 或 trace。
