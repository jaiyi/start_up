# 发布、安全与故障处置

## 1. 知识发布链

```text
知识变更包
  → 服务端校验来源、路径、敏感性和幂等键
  → Git branch/MR
  → CI
  → steward/审核人批准
  → 合并受保护 main
  → WeKnora ingest
  → 真实读回 document/version/ACL
  → knowledge = published
```

## 2. Skill 发布链

```text
Skill 变更包
  → 校验 metadata、schema、依赖、effects 和路径
  → contract/golden/regression/security CI
  → Skill owner + 审核人批准
  → 合并受保护 main
  → 打包并生成 digest
  → SkillHub 发布或管理员发布
  → 目标 profile 安装/装载读回
  → beta/stable 或 blocked
```

SkillHub 不可用时，不取消 Skill 管理：使用 Git package、管理员发布、固定 digest、DSH 非生产 profile 和人工回滚，直到自动分发能力验证完成。

## 3. Plugin 发布链（P4 起）

```text
Plugin manifest/适配器
  → 校验工具 schema、权限、网络/数据范围、凭据引用和宿主兼容性
  → security/dependency/license/SBOM/sandbox CI
  → Plugin owner + 平台/安全审核
  → 合并受保护 main
  → 打包并生成 digest
  → 安装并授予最小权限
  → health/版本/工具注册读回
  → enabled 或 blocked
```

首期不建设开放 Plugin Registry/Marketplace；可以保留受控内置适配器或 fake provider contract，但不能把“存在工具接口”报告为 Plugin 已安装或可用。
## 4. 分发发布链（TeamAI/SkillHub，验证后）

```text
已批准 Skill/Agent Manifest/受控配置
  → package/digest 和目标 profile
  → TeamAI distribution adapter、SkillHub 或管理员流程
  → target workspace pull/install
  → dsh 文件清单、installed revision、profile 和权限读回
  → beta/stable 生效
```

TeamAI 的 `push` 只能进入个人分支或变更请求；任何 Hook、自动 pull 或本地映射都不能绕过 protected main、CI、人工审核、版本 pin、Secret 扫描或权限授予。自动同步只消费已批准版本，不能把未审核草稿直接注入所有成员的 dsh。

### 分发门禁

目标仓库和分支保护、路径/删除安全、secret 和敏感信息扫描、依赖锁定、profile 兼容、版本 pin、Hook 权限限制、幂等、安装/删除清理、文件清单读回、回滚和审计。外网或跨安全域只允许脱敏/公开样本，不得同步正式敏感知识、生产凭据或高风险工具。

TeamAI 不可用或目标能力未验证时，使用 SkillHub 或管理员发布，保持 package、digest、profile、安装读回和回滚语义。

## 5. CI 门禁

### 共同门禁

格式、schema、ID、路径、owner、sensitivity、来源、secret、个人敏感信息、重复 canonical key、链接、CODEOWNERS、受保护分支和变更范围。

### Skill 门禁

input/output schema、知识依赖、effects 和 profile 权限兼容、依赖锁定、许可证/SBOM、golden/regression、digest 生成和危险权限变更。

### Plugin 门禁

manifest、tool input/output schema、最小权限、Secret Manager 引用、网络/数据范围、依赖锁定、许可证/SBOM、宿主兼容性、沙箱/进程隔离、超时/重试/幂等、health、digest、安装/卸载清理和危险权限变更。

CI 判断机器可验证事实，不能代替业务 steward、Skill owner 或 Plugin owner 判断事实、任务价值和外部系统责任。

## 6. 审核规则

- 知识结构/格式变更：至少 1 名 steward；
- 知识事实、范围、敏感等级变更：steward + 领域审核人；
- Plugin manifest、权限/凭据、宿主兼容性、health 或安装变更：Plugin owner + 平台/安全审核；
- 跨域、机密、权限和生产写入：双人审核或额外 owner 批准；
- beta/stable、撤回、退役和回滚：明确责任人和审计理由；
- 合并前重新检查 head SHA、CI 和 approval。

## 7. 权限和数据保护

Skill 只能声明能力需求，实际权限由用户、workspace、profile、tool policy、环境和运行时授权共同决定。普通 Agent 默认看不到高风险工具；工具调用必须重新校验 schema、ACL、risk 和 approval。

Git 只保存脱敏内容、Skill 源码、测试和引用；WeKnora 按文档、空间、用户和业务域过滤；Secret 通过受控 Secret Manager 提供，不进入 Prompt、Skill、Git、Memory 或 trace。

## 8. 审计

发布、安装、装载、运行、权限变更、索引、审批、回滚和撤回至少记录：actor、action、resource/type、version、source commit、package digest、profile、request、reason、result、时间和 correlation。

审计必须能关联 Git MR/CI、WeKnora index job、SkillHub release、installation、approval、run 和最终真实状态。

## 9. 故障处置

- CI 失败：不发布；
- WeKnora 索引失败：保留旧索引，进入补偿；
- SkillHub/TeamAI/仓库不可用：继续使用已固定 package 或管理员发布，禁止漂移；
- TeamAI pull/install 半成功、版本漂移、注入失败或 Hook 冲突：标记 unknown/reconciling，停止新启用，读回目标文件清单并人工对账；
- 删除或回滚清理失败：保留旧 profile pin，隔离残留文件并升级人工处理；
- Plugin runtime/外部 provider 不可用：工具标记 unhealthy/unknown，禁止新运行使用，读回或人工对账；
- Plugin 权限、凭据或兼容性变更失败：禁用并保留旧 package/profile pin；
- provider 超时：unknown，读回或人工对账；
- Webhook 丢失：轮询或人工确认；
- 权限服务不可用：敏感工具拒绝；
- 回滚失败：冻结后续发布并升级人工处理。

## 10. 回滚

### 知识

定位错误版本 → 冻结/退役 → Git 回到上一有效版本 → 重新索引 → 读回检索结果 → 审计和复盘。

### Skill

定位 Skill/package/profile 版本 → 停止新装载 → 回到旧 digest/profile pin → 运行 smoke/regression → 读回实际装载 → 审计和复盘。

### 分发

停止新同步/启用 → 定位 target、package/digest、installed revision 和 profile → 回到旧 package/digest/profile pin → pull/install 读回 → 清理新文件或残留 → smoke/regression → 审计和复盘。

### Plugin

定位 Plugin/package/installation/profile 版本 → 停止新调用 → 禁用或撤回 → 回到旧 digest/profile pin → health/smoke/regression → 读回实际权限和工具注册 → 审计和复盘。

取消 HTTP 请求不代表外部动作已取消；所有取消和超时都必须补查真实状态。
