# 发布、安全与故障处置

## 1. 知识发布链

只有 `Knowledge Creation Session` 中的 approved draft revision 才能启动发布：

```text
Knowledge Creation Session
  → approved draft revision
  → 服务端校验 session 权限、base revision、来源、路径、敏感性和幂等键
  → Git branch/MR
  → CI
  → steward/审核人批准
  → 合并受保护 main
  → WeKnora ingest
  → 真实读回 document/version/ACL
  → knowledge = published
```

## 2. Skill 发布链

只有 `Skill Creation Session` 中完成测试并获批准的 draft revision 才能启动发布：

```text
Skill Creation Session
  → contract/golden/regression/security 证据
  → approved draft revision
  → 校验 session 权限、base revision、metadata、schema、依赖、effects 和路径
  → Skill owner + 审核人批准
  → 合并受保护 main
  → 打包并生成 digest
  → SkillHub 发布或管理员发布
  → 真实 release/version/digest 读回
  → 生成 DSH handoff metadata
  → 下游 Harness 自行验证 discovery/load
```

SkillHub 不可用时，不取消 Skill 管理：使用 Git package、管理员发布和固定 digest，直到自动分发能力验证完成。下游 Harness 的 profile、工具权限和运行状态不由本工作台伪造。

## 3. Plugin 发布链（P4 起）

```text
Plugin manifest/适配器
  → 校验工具 schema、权限、网络/数据范围、凭据引用和宿主兼容性
  → security/dependency/license/SBOM/sandbox CI
  → Plugin owner + 平台/安全审核
  → 合并受保护 main
  → 打包并生成 digest
  → 安装并授予最小权限
  → health/版本/工具注册读回
  → enabled 或 blocked
```

首期不建设开放 Plugin Registry/Marketplace；可以保留受控内置适配器或 fake provider contract，但不能把“存在工具接口”报告为 Plugin 已安装或可用。
## 4. 分发与交接链（验证后）

```text
已批准 Skill/知识 release
  → package/digest 和目标 handoff metadata
  → SkillHub、分发适配器或管理员流程
  → 目标 DeepSeek Harness Provider/discovery/load
  → 返回交接验证或反馈引用
```

任何自动同步都只能消费已批准版本，不能绕过 protected main、CI、人工审核、版本 pin、Secret 扫描或权限授予。交接成功不等于 Harness 已加载、任务已运行或业务结果已成功。

### 分发门禁

目标仓库和分支保护、路径/删除安全、secret 和敏感信息扫描、依赖锁定、profile 兼容、版本 pin、Hook 权限限制、幂等、安装/删除清理、文件清单读回、回滚和审计。外网或跨安全域只允许脱敏/公开样本，不得同步正式敏感知识、生产凭据或高风险工具。

TeamAI 不可用或目标能力未验证时，使用 SkillHub 或管理员发布，保持 package、digest、profile、安装读回和回滚语义。

## 5. CI 门禁

### 共同门禁

格式、schema、ID、路径、owner、sensitivity、来源、secret、个人敏感信息、重复 canonical key、链接、CODEOWNERS、受保护分支和变更范围。

### Skill 门禁

input/output schema、知识依赖、effects 和 profile 权限兼容、依赖锁定、许可证/SBOM、golden/regression、digest 生成和危险权限变更。

### Plugin 门禁

manifest、tool input/output schema、最小权限、Secret Manager 引用、网络/数据范围、依赖锁定、许可证/SBOM、宿主兼容性、沙箱/进程隔离、超时/重试/幂等、health、digest、安装/卸载清理和危险权限变更。

CI 判断机器可验证事实，不能代替业务 steward、Skill owner 或 Plugin owner 判断事实、任务价值和外部系统责任。

## 6. 审核规则

- 知识结构/格式变更：至少 1 名 steward；
- 知识事实、范围、敏感等级变更：steward + 领域审核人；
- Plugin manifest、权限/凭据、宿主兼容性、health 或安装变更：Plugin owner + 平台/安全审核；
- 跨域、机密、权限和生产写入：双人审核或额外 owner 批准；
- beta/stable、撤回、退役和回滚：明确责任人和审计理由；
- 合并前重新检查 head SHA、CI 和 approval。

## 7. 权限和数据保护

Creation Session 使用 session-scoped authorization：用户只能读取当前会话授权的 source refs、drafts、测试 fixture 和外部操作；共享来源只能以只读引用访问。所有生成、提交、发布、handoff、恢复和重试都必须带 `session_id`、`idempotency_key`、`correlation_id` 和 expected `state_version`。旧会话、旧 draft revision 或旧 provider callback 不得覆盖当前状态。

Skill 只能声明能力需求，实际权限由用户、workspace、profile、tool policy、环境和运行时授权共同决定。普通 Agent 默认看不到高风险工具；工具调用必须重新校验 schema、ACL、risk 和 approval。

Git 只保存脱敏内容、Skill 源码、测试和引用；WeKnora 按文档、空间、用户和业务域过滤；Secret 通过受控 Secret Manager 提供，不进入 Prompt、Skill、Git、Memory 或 trace。

## 8. 审计

发布、交接、权限变更、索引、审批、回滚和反馈至少记录：actor、action、resource/type、version、source commit、package digest、target、request、reason、result、时间和 correlation。

审计必须能关联 Git MR/CI、WeKnora index job、SkillHub release、handoff、approval 和反馈引用。Harness 的 session/run/tool trace 由下游保管，本项目只保存必要的外部引用。

## 9. 故障处置

- CI 失败：不发布；
- WeKnora 索引失败：保留旧索引，进入补偿；
- SkillHub/仓库不可用：继续使用已固定 package 或管理员发布，禁止漂移；
- 交接版本、digest 或目标状态不一致：标记 unknown/reconciling，停止新交接并人工对账；
- Harness/provider 不可用：由下游运行 owner 处置，本工作台保留反馈引用，不显示为发布失败或运行成功；
- provider 超时：unknown，读回或人工对账；
- Webhook 丢失：轮询或人工确认；
- 权限服务不可用：敏感能力由下游拒绝；
- 回滚失败：冻结后续发布并升级人工处理。

## 10. 回滚

### 知识

定位错误版本 → 冻结/退役 → Git 回到上一有效版本 → 重新索引 → 读回检索结果 → 审计和复盘。

### Skill

定位 Skill/package/digest → 停止新的交接 → 回到旧 digest → 重新验证发布状态和下游交接 → 审计和复盘。

### 交接

停止新的同步/交接 → 定位 target、package/digest 和 handoff status → 回到旧 package/digest → 重新提交并读回 → 审计和复盘。

### Plugin

定位 Plugin/package/installation/profile 版本 → 停止新调用 → 禁用或撤回 → 回到旧 digest/profile pin → health/smoke/regression → 读回实际权限和工具注册 → 审计和复盘。

取消 HTTP 请求不代表外部动作已取消；所有取消和超时都必须补查真实状态。
