# 发布、安全与故障处置

## 1. 知识发布链

```text
知识变更包
  → 服务端校验来源、路径、敏感性和幂等键
  → Git branch/MR
  → CI
  → steward/审核人批准
  → 合并受保护 main
  → WeKnora ingest
  → 真实读回 document/version/ACL
  → knowledge = published
```

## 2. Skill 发布链

```text
Skill 变更包
  → 校验 metadata、schema、依赖、effects 和路径
  → contract/golden/regression/security CI
  → Skill owner + 审核人批准
  → 合并受保护 main
  → 打包并生成 digest
  → SkillHub 发布或管理员发布
  → 目标 profile 安装/装载读回
  → beta/stable 或 blocked
```

SkillHub 不可用时，不取消 Skill 管理：使用 Git package、管理员发布、固定 digest、DSH 非生产 profile 和人工回滚，直到自动分发能力验证完成。

## 3. CI 门禁

### 共同门禁

格式、schema、ID、路径、owner、sensitivity、来源、secret、个人敏感信息、重复 canonical key、链接、CODEOWNERS、受保护分支和变更范围。

### Skill 门禁

input/output schema、知识依赖、effects 和 profile 权限兼容、依赖锁定、许可证/SBOM、golden/regression、digest 生成和危险权限变更。

CI 判断机器可验证事实，不能代替业务 steward 或 Skill owner 判断事实和任务价值。

## 4. 审核规则

- 知识结构/格式变更：至少 1 名 steward；
- 知识事实、范围、敏感等级变更：steward + 领域审核人；
- Skill 契约、知识依赖、effects 或 profile 变更：Skill owner + 平台/安全审核；
- 跨域、机密、权限和生产写入：双人审核或额外 owner 批准；
- beta/stable、撤回、退役和回滚：明确责任人和审计理由；
- 合并前重新检查 head SHA、CI 和 approval。

## 5. 权限和数据保护

Skill 只能声明能力需求，实际权限由用户、workspace、profile、tool policy、环境和运行时授权共同决定。普通 Agent 默认看不到高风险工具；工具调用必须重新校验 schema、ACL、risk 和 approval。

Git 只保存脱敏内容、Skill 源码、测试和引用；WeKnora 按文档、空间、用户和业务域过滤；Secret 通过受控 Secret Manager 提供，不进入 Prompt、Skill、Git、Memory 或 trace。

## 6. 审计

发布、安装、装载、运行、权限变更、索引、审批、回滚和撤回至少记录：actor、action、resource/type、version、source commit、package digest、profile、request、reason、result、时间和 correlation。

审计必须能关联 Git MR/CI、WeKnora index job、SkillHub release、installation、approval、run 和最终真实状态。

## 7. 故障处置

- CI 失败：不发布；
- WeKnora 索引失败：保留旧索引，进入补偿；
- SkillHub 不可用：继续使用已固定 package 或管理员发布，禁止漂移；
- DSH 装载失败：profile 标记 blocked/unknown，不报告 Skill 可用；
- provider 超时：unknown，读回或人工对账；
- Webhook 丢失：轮询或人工确认；
- 权限服务不可用：敏感工具拒绝；
- 回滚失败：冻结后续发布并升级人工处理。

## 8. 回滚

### 知识

定位错误版本 → 冻结/退役 → Git 回到上一有效版本 → 重新索引 → 读回检索结果 → 审计和复盘。

### Skill

定位 Skill/package/profile 版本 → 停止新装载 → 回到旧 digest/profile pin → 运行 smoke/regression → 读回实际装载 → 审计和复盘。

取消 HTTP 请求不代表外部动作已取消；所有取消和超时都必须补查真实状态。
