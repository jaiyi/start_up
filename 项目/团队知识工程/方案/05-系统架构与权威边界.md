# 系统架构与权威边界

## 1. 当前架构

```text
贡献者 / steward
       ↓
轻量 Web/API 向导或已验证的 DSH 入口
       ↓
知识生产模块化单体 + 持久化 worker
       ├─ Git provider
       └─ WeKnora adapter
              ↓
       DSH 检索/执行与运行反馈
```

第一版只有一个新增控制面：知识生产模块化单体。它负责身份映射、输入校验、草稿、变更包、任务状态、反馈、审计和 provider 调用。异步动作先使用数据库任务表、租约、重试和人工补偿，不先拆服务。

## 2. 权威边界

| 对象 | 权威来源 | 负责什么 | 不负责什么 |
|---|---|---|---|
| 原始资料 | 收件箱/受控附件/Git 引用 | 保存来源和捕获信息 | 直接进入生产检索 |
| 正式知识 | Git + MR/CI/人工审核 | 源文件、差异、版本、回滚 | 下游直接改正文 |
| 检索索引 | WeKnora | 索引、ACL 过滤、查询、引用 | 决定是否批准 |
| Skill 源码和测试 | Git | 契约、回归、版本和 digest | 运行时改写源码 |
| Skill 发布 | SkillHub（验证后）/管理员记录 | 分发和状态 | 模型自动晋升 stable |
| 执行与工具权限 | DSH profile/policy | session、工具调用、人工确认 | Skill 自行扩大权限 |
| 运行反馈 | run/trace/反馈表 | 归因和候选任务 | 直接晋升正式知识 |
| 审计和任务状态 | 生产模块数据库 | job、approval、补偿和追踪 | 用 provider 文本代替证据 |

## 3. 组件职责

### 知识生产模块

连接业务工作流和外部 provider，但不是新的知识库、向量库或 Skill Registry。

### Git/CI

保存正式知识、Skill、schema、测试、CODEOWNERS 和变更历史，执行确定性门禁。`main` 必须是受保护分支。

### WeKnora

只接收已经批准的知识，返回 document ID、版本、来源和权限过滤结果。索引失败保留旧版本。

### DSH

负责 Session、上下文、Skill 装载、工具调用、人工确认和运行结果。它不拥有正式知识，也不绕过审核。

### SkillHub

只有目标部署的 API、版本、digest、回滚和审计能力实测后，才承担自动发布；否则保持管理员操作。

### DeepSeek Bot

可选的 DSH 协作层，提供 Bot、Group、Memory 和交接；不能替代 Git、WeKnora、SkillHub、审批或企业审计。

## 4. 当前不引入的层

Console Plugin、Integration Gateway、MCP 工具面、Bot 群聊、多 provider 和服务端化 Agent 协作都不是 P1 的硬依赖。它们只有在出现真实规模或重复实现时才评估。

升级触发证据包括：两个以上知识域稳定使用、第二个 provider、人工状态查询成为明显瓶颈、集中权限/审计需求，或模块化单体无法接受地测试和发布。

## 5. 不可混淆的边界

- 向量检索不是知识治理；
- DSH Memory 不是正式知识；
- Skill 不是知识正文；
- MCP 不是异步控制面；
- Webhook 是事实通知，不是授权；
- HTTP 200 不是业务成功；
- 一个 Agent 的成功回答不是组织规则；
- 统一页面不等于统一权威系统。
