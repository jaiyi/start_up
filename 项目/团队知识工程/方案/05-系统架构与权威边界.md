# 系统架构与权威边界

## 1. 当前推荐拓扑

```text
贡献者 / steward / Skill owner
            ↓
轻量 Web/API 向导或已验证的 DSH 入口
            ↓
双资产生产与治理模块化单体 + 持久化 worker
  ├─ Knowledge catalog / review / change
  ├─ Skill catalog / contract / test / release
  ├─ operation / job / approval / audit / feedback
  ├─ Git provider
  ├─ WeKnora adapter
  └─ SkillHub adapter（验证后；否则管理员流程）
            ↓
DSH profile / loader / tools / human gate / run
```

第一版只有一个新增控制面，但它同时是一等管理知识和 Skill 的资产控制面，不是只管理知识的服务。异步动作先用数据库任务表、租约、重试、读回和人工补偿。

## 2. 权威边界

| 对象 | 权威来源 | 负责什么 | 不负责什么 |
|---|---|---|---|
| 原始资料/任务需求 | 收件箱/受控附件 | 保存输入和捕获信息 | 直接成为正式资产 |
| 正式知识 | Git + MR/CI/人工审核 | 正文、来源、差异、版本、回滚 | 下游直接修改 |
| 知识检索 | WeKnora | 索引、ACL、查询、引用 | 决定批准或管理 Skill |
| 正式 Skill | Git + MR/CI/人工审核 | 源码、契约、测试、依赖、版本 | 运行时自行改写 |
| Skill 注册/分发 | SkillHub（验证后）/管理员记录 | package、digest、beta/stable、撤回 | 决定业务事实是否正确 |
| 执行和工具权限 | DSH profile/policy | 装载、工具、人工确认和运行 | 改变 canonical source |
| 运行反馈 | run/trace/反馈表 | 归因、质量和候选任务 | 直接发布资产 |
| 资产/任务/审计状态 | 工作台数据库 | catalog、job、approval、补偿和关联 | 代替 Git/WeKnora/DSH 的专业能力 |

## 3. 组件职责

### 工作台控制面

提供业务人员的统一入口和平台 owner 的控制面：资产目录、知识/Skill 草稿、变更包、审核、任务状态、profile 选择、发布状态、反馈、审计和人工补偿。

它不存放未经治理的正式正文，也不绕过下游真实状态。

### Git/CI

保存知识、Skill、schema、测试、metadata、依赖锁定、CODEOWNERS 和变更历史。执行格式、secret、契约、权限冲突、链接、依赖和回归门禁。

### WeKnora

只接收批准后的知识，提供权限过滤、检索、来源和版本引用。它不能管理 Skill 的契约、测试、发布或运行权限。

### SkillHub

提供 Skill package 的注册、分发、版本和 digest（目标部署验证后）。未验证时由管理员流程保证同样的版本、审批、装载和回滚语义。

### DSH

提供 profile、Skill loader、Session、工具调用、人工确认和运行结果。它不拥有知识/Skill 的正式源，也不自动批准发布。

### DeepSeek Bot

可选的 DSH 协作层，提供 Bot、Group、Memory 和交接；不能替代资产治理、SkillHub、Git、WeKnora 或企业审批。

## 4. 当前不引入的层

完整 Integration Gateway、Console Plugin、MCP 高风险工具、多 provider、服务端 Bot Host 和多租户不是 P1 的硬依赖。它们只在两个以上知识域/Skill 稳定使用、第二 provider、人工瓶颈、集中权限审计或模块化单体无法接受地发布时评估。

这不影响知识和 Skill 管理是当前产品核心；延后的是更重的实现层，不是资产能力。

## 5. 不可混淆的边界

- WeKnora 是知识检索，不是 Skill 管理；
- SkillHub 是 Skill 分发，不是知识事实审核；
- DSH 是执行面，不是资产 canonical source；
- MCP 是调用协议，不是异步控制面；
- Webhook 是事实通知，不是授权；
- HTTP 200 不是业务成功；
- 一个 Agent 的成功回答不是通用规则；
- 一个统一页面不等于系统统一。
