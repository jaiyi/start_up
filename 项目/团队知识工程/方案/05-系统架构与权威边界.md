# 系统架构与权威边界

## 1. 当前推荐拓扑

```text
贡献者 / steward / Skill owner
            ↓
轻量 Web/API 创作发布工作台
            ↓
双资产生产与治理模块化单体 + 持久化 worker
  ├─ Creation Session manager
  ├─ session-scoped retrieval / source access
  ├─ draft / revision manager
  ├─ operation / job / approval / audit / feedback reference
  ├─ Git provider / CI
  ├─ WeKnora adapter
  └─ SkillHub / 分发交接 adapter（验证后；否则管理员流程）
            ↓
已批准资产、版本/digest 和 handoff metadata
            ↓
DeepSeek Harness Provider / discovery / load（下游）
            ↓
Harness Workspace / Session / tools / human approval / run

业务系统 / SPC 后端
  └─ 业务事实、动态状态、计算、告警、工单和生产运行
```

第一版只有一个新增创作发布控制面，负责 Creation Session、知识和 Skill 的草稿、资产生产、审核、发布和反馈分流。它必须按 `session_id` 隔离检索范围、草稿和异步 job，拒绝过期 `state_version` 的回调，不复制 DeepSeek Harness 的完整 Runtime。异步动作先用数据库任务表、租约、幂等键、重试、读回和人工补偿。

## 2. 权威边界

| 对象 | 权威来源 | 负责什么 | 不负责什么 |
|---|---|---|---|
| 原始资料/任务需求 | Creation Session 的受控来源引用 | 保存输入和捕获信息 | 直接成为正式资产 |
| 正式知识 | Git + MR/CI/人工审核 | 正文、来源、差异、版本、回滚 | 下游直接修改 |
| 知识检索 | WeKnora | 索引、ACL、查询、引用 | 决定批准或管理 Skill |
| 正式 Skill | Git + MR/CI/人工审核 | 源码、契约、测试、依赖、版本 | 运行时自行改写 |
| Plugin package | Git + CI + package digest（P4 起） | manifest、工具 schema、适配器、依赖和权限声明 | 直接获得运行权限 |
| Plugin 注册/安装 | Plugin registry/管理员记录（P4 起） | package、digest、安装、启停、撤回和兼容性 | 决定业务任务质量 |
| Skill 注册/分发 | SkillHub、TeamAI distribution adapter 或管理员记录 | package、digest、beta/stable、撤回、目标安装和版本切换 | 决定业务事实或直接授予权限 |
| TeamAI 分发/同步 | Git 批准版本 + TeamAI adapter 运行记录（验证后） | init、pull、变更分支 push、本地映射/注入、版本切换和安装读回 | 审批知识/Skill、管理知识索引、决定 Plugin health 或授予运行权限 |
| Agent Manifest | Git + CI + 人工审核（后续） | 多个 Skill、知识 profile、模型/工具策略的组合和分发描述 | 替代依赖资产的 owner、审核、ACL 或回归 |
| 执行和工具权限 | DeepSeek Harness profile/policy + Plugin runtime/tool registry（下游） | 会话装载、工具、人工确认和运行 | 改变 canonical source |
| 运行反馈 | Harness/业务系统的反馈引用 | 归因、质量和候选任务 | 直接发布资产 |
| 资产/发布/审计状态 | 工作台数据库 | catalog、job、approval、handoff、补偿和关联 | 代替 Git/WeKnora/Harness 的专业能力 |

## 3. 组件职责

### Plugin 管理（P4 起）

Plugin 提供工具能力或外部系统适配，不提供业务任务方法。Plugin catalog/registry 管理 manifest、版本、digest、兼容性、安装、启停、健康、撤回和权限授予；Plugin runtime/gateway 负责隔离执行、凭据注入、超时/重试/幂等、tool registry 和真实状态读回。Skill 通过 profile 使用 Plugin 工具，但 Plugin 管理不替代 Skill 管理。

进入 P4 的触发条件包括：出现第二个外部系统或重复适配、多个 Skill 复用同一工具、需要集中权限/凭据治理、需要沙箱/进程隔离，或模块化单体无法接受地管理安装和运行。

### 工作台控制面

提供业务人员的统一创作发布入口和平台 owner 的控制面：工作台首页、Creation Session、session-scoped source/retrieval、知识/Skill 草稿、变更包、审核、测试、发布状态、交接记录、反馈和审计。

会话上下文、Draft 和外部发布操作必须使用不同标识；回调必须校验 session、draft revision、expected state version 和 correlation id。它不存放未经治理的正式正文，不绕过下游真实状态，也不承载 Harness 的 Session/Run 控制。

### Git/CI

保存知识、Skill、Plugin manifest/适配器、schema、测试、metadata、依赖锁定、CODEOWNERS 和变更历史。执行格式、secret、契约、权限冲突、链接、依赖和回归门禁。

### WeKnora

只接收批准后的知识，提供权限过滤、检索、来源和版本引用。它不能管理 Skill 的契约、测试、发布或运行权限。

### TeamAI 分发适配层（验证后）

TeamAI 只负责已批准团队 AI 资产的分发和本地同步：仓库镜像、`init`、变更分支上的 `push`、`pull`、版本切换、目标 workspace 映射/注入和安装读回。它可以承载 Skills、Rules、Agent Manifest 和受控 Plugin manifest 的分发，但不负责知识事实审批、Skill 业务质量、WeKnora 检索、Plugin runtime、权限授予或统一 run 的最终归因。

自动同步不等于自动批准或自动生效。TeamAI 只能消费已通过 MR/CI/人工审核的版本；实际运行前必须确认 target、profile、installed revision 和权限状态。不可用时必须回到 SkillHub 或管理员 fallback。

### SkillHub

提供 Skill package 的注册、分发、版本和 digest（目标部署验证后）。未验证时由管理员流程保证同样的版本、审批、装载和回滚语义。

### OpenCSG 运行层（验证后）

参考方案将 OpenCSG 定位为模型推理、Agent 编排、AI Gateway 和多 Agent 协作运行层；本项目只把它作为待验证 provider，不因外部方案描述而视为已集成。其资产托管、AgenticHub、CSGClaw 或本地模型能力必须分别验证，不能替代工作台、Git、WeKnora、Skill 分发或 Plugin 治理。

### DSH

提供 profile、Skill loader、Session、工具调用、人工确认和运行结果。它不拥有知识/Skill 的正式源，也不自动批准发布。

### DeepSeek Bot

可选的 DSH 协作层，提供 Bot、Group、Memory 和交接；不能替代资产治理、SkillHub、Git、WeKnora 或企业审批。

## 4. 当前不引入的层

完整 Integration Gateway、Plugin Registry/Runtime、Console Plugin、MCP 高风险工具、多 provider、服务端 Bot Host、多租户和 TeamAI 自动分发不是 P1 的硬依赖。TeamAI 先只做能力侦察或可选 adapter，只有双资产稳定且出现真实分发触发证据后才进入 P3；Plugin 只有出现外部系统复用、集中权限或运行时隔离需求后才进入 P4。

这不影响知识和 Skill 管理是当前产品核心；延后的是 TeamAI 自动分发、Plugin 等更重的实现层，不是 Skill 资产能力。

## 5. 不可混淆的边界

- WeKnora 是知识检索，不是 Skill 管理；
- SkillHub/TeamAI 是分发实现，不是知识事实审核；
- TeamAI 的 pull 成功不等于 Skill stable、Plugin enabled 或运行成功；
- DSH 是执行面，不是资产 canonical source；
- MCP 是调用协议，不是异步控制面；
- Webhook 是事实通知，不是授权；
- HTTP 200 不是业务成功；
- 一个 Agent 的成功回答不是通用规则；
- 一个统一页面不等于系统统一。
