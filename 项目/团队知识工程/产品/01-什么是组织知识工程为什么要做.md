# 1. 为什么组织需要知识工程

## 组织每天都在付出“弄清楚”的成本

员工遇到问题，会查文件、翻群聊、问熟人；说法不一，就请专家核实、开会讨论。这些做法有其必要性：遇到新情况、利益冲突或需要承担责任的决定，本来就该由人讨论。

但其中有一部分工作在反复发生：上次已经找过依据、对过口径、作过取舍；换一批人、换一个类似任务，又得重找材料、重讲背景、重问一遍。即使找到了旧结论，也不一定知道当时针对什么条件、今天还算不算数。组织不仅重复付出了**找到信息**的成本，还重复付出了**判断是否适用**的成本。

客户答疑、设备故障、采购规则、设计选择、新人接手工作，都可能发生这种重复。这里不是说每个问题都有现成答案，而是说：**已经付出过的调查、判断和协作劳动，为什么没能成为下一次工作的起点？**

## 基本单元不是文件，而是可以重新检验的判断

> **知识工程服务于组织高效、可靠地做判断和协作。它把已经确认过的信息、判断依据和适用边界留下来，让人和 Agent 在下一次工作中用得上、用得对。**

要做到这一点，得分清四种东西：

- **资料**：制度、记录、案例、聊天等，说明“当时有什么信息、谁说过什么”；有来源不等于当下适用。
- **可复用的判断**：说明“在什么条件下，依据什么，可以怎样理解或处理；例外是什么；由谁确认、谁负责更新”。这是知识工程优先让人和 Agent 找到的内容。
- **当前业务决定**：面对这一次的具体条件，由有责任的人作出判断、批准或承担后果。已有知识可以提供起点，不自动替他们决定。
- **执行动作**：在获得必要授权后做某件事。它的权限、失败处理和结果记录不能仅凭一条知识自动推导出来。

并非所有有用经验都值得变成正式知识。一次性事项和实时业务状态，应留在原工作流程或业务系统里；来源不清的经验可以提供线索，但不能冒充已确认的结论。知识工程做的是**有选择地保留、供人辨认和不断修正**，不是把所有信息搬进一个库。

## 为什么叫“复利”

如果一个判断经过一次查证和确认，之后被多次正确使用，后面的人就不必每次从零开始。下一次使用又可能带回新的例外、冲突和改进，使它在新的条件下更清楚。这样的积累，才有可能成为组织能力，而不只是某个人记得多。

复利不是条目越来越多，而是要看两边：后续工作少花的查找、解释、等待和返工成本，是否覆盖最初整理、审核和持续维护的成本；同时错误使用有没有增加。问题不重复、边界说不清或维护负担太高时，明确联系人、改一份模板，可能比建正式知识更好。

## Agent 为什么改变机会，也改变风险

过去即使留下了可靠记录，下次使用的人仍要知道它在哪、猜对关键词、自己读懂上下文。Agent 有机会从当前问题出发，在获授权的资料中查找、比较说法、提示依据和缺口，让已有判断更容易在工作时被看见。它也能减轻初步整理的劳动。**这改变的是查找、整理和调用的成本，不是判断的责任归属。**

如果依据过期、两份资料冲突，或新情境超出旧结论的范围，Agent 也可能把错误说得十分流畅。使用成本下降，意味着正确知识更容易传播，错误也更容易传播。因此产品需要同时支持“该用的时候用得上”和“不能用的时候看得出来、停得下来”。

## 为什么它是一项平台级组织能力

各领域判断的内容不同：采购规则、设备处置与设计决策不能套同一份答案。但组织都有一些相似的问题：结论从何而来，针对哪种情况，由谁确认，谁能看，发现变化找谁，旧说法何时停用。这些**让判断可以安全复用的机制**可能由同一平台提供；判断本身仍属于领域和业务负责人。

是否真的具备平台性，要看第二类、第三类工作接入时，能否复用这些机制，而不是每换一个场景就重新造一套流程。具体怎样划分平台与领域的责任、哪里最容易断，见[下一篇](02-知识工程难在哪里.md)。

以上是从组织工作方式出发提出的**产品判断**，不是基于本团队真实访谈得出的结论，更不是已证实的收益。现阶段先以它设计初版，随后用真实使用检验、修正甚至推翻它。采购、设备等仅是解释问题的示意场景，不代表已确定的试点。
