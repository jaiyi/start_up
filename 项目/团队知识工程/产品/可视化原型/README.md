# Team Knowledge Workbench · 团队共创产品概念稿

[打开交互原型](index.html)：下载或克隆本目录后，用浏览器直接打开 `index.html`。不需要构建、安装依赖、连接服务器或登录；刷新后演示状态重置。

**这不是已安装的 DeepSeek Harness Desktop 插件，也不连接企业资料、团队仓库、业务系统、Tool 目录、Git/CI 或 Provider。** 团队、资料 A/B、知识版本、Skill 建议、库存/价格 Tool 与审核发布结果均为虚构。输入仅在当前页面内存中用于演示；请勿填写真实产品/部件 ID、库存、价格、生产凭据或其他敏感内容。

## 建议演示路线

1. 打开原型默认进入 **DSH Desktop → 对话与任务**：原生会话的位置是视觉主线，但这里的对话仍只是预置示意，**不是插件重新实现的 DSH Session**。任务仍由宿主和原业务系统完成；知识结果、候选 Skill、外部 Tool 都放在次级可展开示意中。展开后选择「已确认／只有资料／资料冲突」仅切换虚构结果；推荐不等于 Skill 已安装、加载或执行，Tool 列表可见不等于已调用。静态对话不接受任务输入或提交。
2. 当用户认为本次任务值得回顾时，主动点 **「演示调用任务复盘 Skill」**：先看任务目标、资产使用证据与用户额外调整（未有记录则标「无法确认」）；再逐条选择「可复用／有条件可复用／特殊处理／证据不足」，决定待核线索去向：核工作记录来源、核项目／产品线事实、提炼经验、更新／新建知识、讨论 Skill、核外部 Tool，亦可「暂不沉淀」。最后回答是否有报告/PPT、能否分享。未讨论完不会生成交接结论；特殊处理／证据不足时不建立通用资产。
3. 在复盘结论处**手动选中并复制**获准分享的最小脱敏示例文本，按选择进入工作记录、业务对象、知识或 Skill 页面，自行粘贴并点「模拟提交候选供核查」。复盘讨论和打开页面不自动转交；粘贴而未提交也不算本地已收到。来源页只收定位与核证线索，不登记整份纪要；业务对象页只收待核事实线索，不认定当前分工。即使模拟提交，也不创建正式知识、修订或运行日志。受限报告/PPT 不显示标题或原文、不上传；即使用户称可以分享，仍需核实来源、权限和实际资料库入口，**资料提交与正式知识发布是两条不同流程**。
4. 打开左侧 **团队资产**，依次切换 **最新进展／全局概览／智能诊断**。最新进展顶部是知识/Skill/Tool 三组虚构指标：可用存量大字、本周发布或开通及引用/执行/调用次数与使用人次小字；下方左列是项目/产线的事实进展与风险线索，右列是经验/技能更新。可从标题或正文**直接点击文字**进入团队资产内的只读详情，返回原 tab；不是另外一排“看只读详情”按钮。经核准的原材料可以整理为项目/产品的成果、风险和有依据的后续安排，知识/Skill 动态可供团队周报引用。**全局概览不重复数字**：默认同时看见项目 A/B/C 与产品线 P/Q/R 的工作主题和交叉关系，接着看按 ID/版本去重的知识与 Skill 落点；其中 B/C、Q/R 及多数关系是待核的演示占位，不能当作真实归属或能力覆盖率。智能诊断用三条固定虚构巡检候选分别示意事实说法冲突、约定进展复核和限定业务流衔接缺口；可点进证据详情，主动反馈待补证或不适用。它并未扫描真实来源，反馈也不派单。固定样例不读仓库，也不随模拟发布按钮或 Tool 试参重算；浏览详情不会自动派单或进入带审核控件的页面。
5. 在 **全局概览** 先从全队业务版图看三条产品线、三个项目以及它们的交叉主题：项目 A 同时连到产品线 P 的演示知识关联和产品线 Q 的待核关系，后者不能当成已核归属。选项目或产线可高亮关联、在同页看简短上下文；选择“看全团队”恢复全局。下方 K-01 v1 只出现一次，关联项目 A 和产品线 P；点 K-01、K-02 或 SK-02 进入团队资产内的精简只读详情，返回保留所选对象。K-01 v1 是有条件的演示可用版，R-02 可并行整理，不能用修订候选覆盖正式版；SK-02 的发布不等于已安装或实际执行。只有在详情明确选择「继续处理」后才进入相应的知识/Skill 创作或事实核证会话；真实目的页必须重验身份、来源 ACL、对象 ID 与版本基线。若要修订和发布，从知识详情进入**知识创作会话**，针对 v1 选中文段、留下讨论评论、提出 R-02，再在创作会话内模拟确认、审核与目标读回。审核/发布按钮不在团队资产页。
6. 在选中项目 A 或产品线 P 后，从上下文里的 **历史出处** 点击 S-01 来源摘要，进入团队资产内的来源只读详情。正式产品若已核对这份文档的 WeKnora 文档 ID/版本、权限和具体深链，才在它旁边出现「在 WeKnora 阅读 ↗」，直接在新页面打开**对应文档**，而非整个知识库首页。原型未读取登录后文档，也没有可核实的 S-01/K-01 深链，故只显示“原文未接入”，**不提供虚构跳转或独立 Wiki 区块**；概览也不复制历史原文。
7. 从左侧独立的 **业务接口目录** 入口进入：在**团队可发现**默认看到首条 ERP 库存接口的右侧详情，列表的每条 Tool 都显示「本团队实际调用次数：暂无法统计」，不再单列一块用量面板。按虚构目录的 ERP / MES 标签筛选、搜索“库存”可改变结果与默认详情；输入唯一允许的脱敏示例 `DEMO-001`，点击「模拟参数测试」查看固定本地结果。库存详情里可展开**本地试参情景**：仅演示这一个测试按钮在“条件就绪／待授权／未接入／状态未知”下能否点击，不表示真实接入、授权或调用，也不影响其他 Tool 或宿主任务。随后切换 **待申请**，默认看首条可发现但未开通接口的详情，搜索“价格”或选择采购标签查看采购价格接口的参数结构与外部申请去向；未开通项**没有试调入口**，「模拟记录申请意向」仅在内存中记意向。列表/标签/详情并不连接真实数据中台；目录实际分类应取提供方 API，正式搜索要按团队权限在服务端分页执行。原型没有 PG 聚合或宿主成功调用回执，浏览、试参和推荐均不算真实调用；宿主任务里的外部 Tool 查询也是单独的固定虚构值，不可当 ERP 调用或复盘运行证据。
8. 打开 **Workbench 工作台**：顶部「需要我处理／我关注的进展」是两张**固定的虚构情景卡**，用于讨论“明确补证请求才是我的行动，提议者等待核对只是关注”；卡片不会随当前评论、提议或模拟发布动作迁移。工作台不汇总真实身份、指派和生命周期，模拟未绑定时隐藏情景标题而不把不可见当作零待办。已发布且无新动作的事项应退出个人进行中，正式版本到团队资产只读查看；详情见[工作台事项机制](../界面功能设计/02-Workbench工作台.md)。
9. 在左侧 **团队资产 → 智能诊断** 看 AI 巡检雷达的三类预置演示发现：核清单 A 与模板 B 是否在同一任务及生效时间冲突；核项目 A 的约定复核点之后能否取得权威进展；核限定交接流程中 Skill 实际运行、Tool 授权与人工判断的衔接。逐条进入只读详情看来源、未知点及建议动作，可本地标「待补证／不适用」，返回卡片能看到反馈；没有真实扫描、通知或自动个人待办。流程衔接的详情还可**主动**打开一类虚构任务的四个判断点；候选能力地图不是全团队自动覆盖率。

## 刻意保留的边界

- 同一 Workbench 可以被不同团队安装，但每个团队的 `team-knowledge-asset`、Git 仓库、草稿及授权各自独立；本产品体验不设计跨团队分享。团队内可贡献，不等于所有敏感来源或正式审批动作无条件开放。
- 选中内容评论是低门槛协作方式的**产品假设**，并未通过用户测试证明最优。真实实现需要稳定锚点、旧版快照、重新定位／冲突处理及审计；首版不做多人实时协同编辑。
- 没有角色视角切换，但仍需对具体确认、审核、发布和 Skill 运行做真实身份与权限校验；本页的模拟绑定或模拟确认都不是授权事实。
- 团队仓库可以记录获准展示的 Tool 目录引用及 Skill 依赖，不能创作 ERP/MES/数仓生产接口、批准价格/库存数据访问或保存查询结果。列表、分类标签、参数结构应从外部提供方/数据中台的目录 API 按可见权限取得；本原型仅用虚构预置条目。实际接口由外部提供方接入，数据责任方限定字段、对象和用途，DSH 运行时再次检查用户/服务身份与工具策略；低风险只读试参也须有经批准的测试通道，广场无试调。若增加团队调用次数，应依据授权的宿主成功调用回执做最小化 PostgreSQL 时间窗聚合，不存参数、结果或完整 trace，不以本地按钮点击冒充调用；无证据显示暂无法统计。申请不等于获批，查询能力仍待目标环境验证。写入业务系统的 Tool 不采用查询示意的门禁。
- Creation Session 不等于 DSH Runtime Session；Market 安装和面板加载不等于正式资产发布。真实发布仍须 Git 审核、CI、人类批准、Provider 读回及下游门禁。Skill 建议不代表宿主已支持自动匹配，该宿主能力尚待目标环境验证。
- 本页不持久化、不上传输入、不请求远端；复盘中的自由文本更正不进入示例交接，知识、Skill、来源核对与业务事实核对的粘贴草稿分别留在当前页面内存，刷新或模拟撤权即清空。没有文件选择或上传、Clipboard 自动读写，也不收集生产凭据、敏感原文、完整 Prompt 或 Tool Call trace。模拟提交候选、评论和状态不能充当交付、真实业务结果或收益证据。
