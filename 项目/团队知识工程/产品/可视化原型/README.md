# Team Knowledge Workbench · 团队共创产品概念稿

[打开交互原型](index.html)：下载或克隆本目录后，用浏览器直接打开 `index.html`。不需要构建、安装依赖、连接服务器或登录；刷新后演示状态重置。**获准材料的主路径仅有四步：导入来源 → 事实梳理 → 经验总结 → 加入知识库。** 不设独立「能力体检」页、按钮或必经分流；「改进已有能力」意图也沿同一路径带入已有版本疑点。事实梳理和经验总结分别处理本项待核内容：桌面每项约 **2/3 为当前事实点或经验议题的待核稿与评论，1/3 为已有知识的准确版本对照**；移动端对照排在本项之后，而非把事实和经验拼成两栏。逐项区分已核／来源自述待核／冲突／未取得／不适用；仅有实际可核依据才标已核。事实梳理中遇影响判断的数字，就地核指标定义、时间窗与有权报表；只有**当前身份、用途、字段／对象、时间窗、指标口径和只读通道均获授权**才可能提供 Tool 核验入口，未满足则待授权／待核或回原系统，不增设数字步骤。加入知识库时预览各类独立去向及门禁，在此条件性比较合成 Skill 写法与人工写法、正常／边界／异常示例；**不是实际运行或判定优胜**，也不另设 Skill 体检页。当前待核稿的选段评论和已有知识对照已在事实梳理／经验总结中；只有指定正式知识版本需受控修订或确有稳定可测的 Skill 缺口时才按条件进入深层工作区，并非默认下一站。页面只识别固定虚构样例；**没有运行模型、subagent、Tool，也没有查询真实资产版本**；自由文本不匹配时显示无法判定，不编造结论。

知识创作的事实画线评论、经验评论后查看完整下一版待核稿、旧稿对比／回退及来源覆盖下钻，分别归入事实梳理与经验总结的待核讨论；指定正式知识版本的受控修订仍按门禁进入深层工作区，不是另一条必经流程。原型回复按有限关键词选本地预置稿，非模型输出或任意文本生成；未覆盖的评论保留原稿并提示失败。分别核事实与经验的待核稿及已有知识对照，折叠的 111 显示行／22 条处理线索仅作证据下钻，不能代替两步各自的评论和依据状态。内置脱敏缩写与指定本地周报完整 SHA-256 指纹只用于命中人工编排结果；非样本不实际抽取或检索。文件只在本地读取，未登记来源、上传、归档或生成 Wiki；不要输入无权分享的原件。**静态页面没有后端核验、仓库提交或发布能力。**

**这不是已安装的 DeepSeek Harness Desktop 插件，也不连接企业资料、团队仓库、业务系统、Tool 目录、Git/CI 或 Provider。** 团队、资料 A/B、知识版本、Skill 建议、库存/价格 Tool 与审核发布结果均为虚构。输入仅在当前页面内存中用于演示；请勿填写真实产品/部件 ID、库存、价格、生产凭据或其他敏感内容。

## 建议演示路线

1. 打开原型默认进入 **DSH Desktop → 对话与任务**：原生会话的位置是视觉主线，但这里的对话仍只是预置示意，**不是插件重新实现的 DSH Session**。任务仍由宿主和原业务系统完成；知识结果、候选 Skill、外部 Tool 都放在次级可展开示意中。展开后选择「已确认／只有资料／资料冲突」仅切换虚构结果；推荐不等于 Skill 已安装、加载或执行，Tool 列表可见不等于已调用。静态对话不接受任务输入或提交。
2. 当用户认为本次任务值得回顾时，主动点 **「演示调用任务复盘 Skill」**：先看任务目标、资产使用证据与用户额外调整（未有记录则标「无法确认」）；再逐条选择「可复用／有条件可复用／特殊处理／证据不足」，决定待核线索去向：核工作记录来源、核项目／产品线事实、提炼经验、更新／新建知识、讨论 Skill、核外部 Tool，亦可「暂不沉淀」。最后回答是否有报告/PPT、能否分享。未讨论完不会生成交接结论；特殊处理／证据不足时不建立通用资产。
3. 在复盘结论处**手动选中并复制**获准分享的最小脱敏示例文本，按选择进入工作记录、业务对象、知识或 Skill 页面。知识页可粘贴或从本地文件读入文字；复盘交接、材料定位加问题和旧版异议不需要不同入口。不过，可在同一输入区域载入脱敏周报结构示例，在「事实梳理」分别对照项目／产品线事实与已有知识，在「经验总结」分别对照人工编排的两条方法经验与已有知识，并按需展开矩阵与逐段清单；普通自由输入**不会自动提取事实或经验**。其他页面仍是「模拟提交候选供核查」。复盘讨论和打开页面不自动转交；来源页只收定位与核证线索，不登记整份纪要；业务对象页只收待核事实线索，不认定当前分工。即使模拟提交，也不创建正式知识、修订或运行日志。受限报告/PPT 不显示标题或原文、不上传；即使用户称可以分享，仍需核实来源、权限和实际资料库入口，**资料提交与正式知识发布是两条不同流程**。
4. 打开左侧 **团队资产**，依次切换 **最新进展／全局概览／智能诊断**。最新进展顶部是知识/Skill/Tool 三组虚构指标：可用存量大字、本周发布或开通及引用/执行/调用次数与使用人次小字；下方左列是项目/产线的事实进展与风险线索，右列是经验/技能更新。可从标题或正文**直接点击文字**进入团队资产内的只读详情，返回原 tab；不是另外一排“看只读详情”按钮。经核准的原材料可以整理为项目/产品的成果、风险和有依据的后续安排，知识/Skill 动态可供团队周报引用。**全局概览不重复数字**：默认同时看见项目 A/B/C 与产品线 P/Q/R 的工作主题和交叉关系，接着看按 ID/版本去重的知识与 Skill 落点；其中 B/C、Q/R 及多数关系是待核的演示占位，不能当作真实归属或能力覆盖率。智能诊断用三条固定虚构巡检候选分别示意事实说法冲突、约定进展复核和限定业务流衔接缺口；可点进证据详情，主动反馈待补证或不适用。它并未扫描真实来源，反馈也不派单。固定样例不读仓库，也不随模拟发布按钮或 Tool 试参重算；浏览详情不会自动派单或进入带审核控件的页面。
5. 在 **全局概览** 先从全队业务版图看三条产品线、三个项目以及它们的交叉主题：项目 A 同时连到产品线 P 的演示知识关联和产品线 Q 的待核关系，后者不能当成已核归属。选项目或产线可高亮关联、在同页看简短上下文；选择“看全团队”恢复全局。下方 K-01 v1 只出现一次，关联项目 A 和产品线 P；点 K-01、K-02 或 SK-02 进入团队资产内的精简只读详情，返回保留所选对象。K-01 v1 是有条件的演示可用版，R-02 可并行整理，不能用修订候选覆盖正式版；SK-02 的发布不等于已安装或实际执行。只有在详情明确选择「继续处理」后才进入相应的知识/Skill 创作或事实核证会话；真实目的页必须重验身份、来源 ACL、对象 ID 与版本基线。若要演练原有 K-01 v1 的评论与 R-02 修订，可进入**知识创作会话**底部的可展开 K-01 记录：选中旧版文段发表评论，进入修订提议和指定修订核对，再回到这份记录模拟审核和目标读回。它不是新周报议题提炼流程的发布结果，也不能绕过已有审核门禁；审核/发布按钮不在团队资产只读页。
6. 在选中项目 A 或产品线 P 后，从上下文里的 **历史出处** 点击 S-01 来源摘要，进入团队资产内的来源只读详情。正式产品若已核对这份文档的 WeKnora 文档 ID/版本、权限和具体深链，才在它旁边出现「在 WeKnora 阅读 ↗」，直接在新页面打开**对应文档**，而非整个知识库首页。原型未读取登录后文档，也没有可核实的 S-01/K-01 深链，故只显示“原文未接入”，**不提供虚构跳转或独立 Wiki 区块**；概览也不复制历史原文。
7. 从左侧独立的 **业务接口目录** 入口进入：在**团队可发现**默认看到首条 ERP 库存接口的右侧详情，列表的每条 Tool 都显示「本团队实际调用次数：暂无法统计」，不再单列一块用量面板。按虚构目录的 ERP / MES 标签筛选、搜索“库存”可改变结果与默认详情；输入唯一允许的脱敏示例 `DEMO-001`，点击「模拟参数测试」查看固定本地结果。库存详情里可展开**本地试参情景**：仅演示这一个测试按钮在“条件就绪／待授权／未接入／状态未知”下能否点击，不表示真实接入、授权或调用，也不影响其他 Tool 或宿主任务。随后切换 **待申请**，默认看首条可发现但未开通接口的详情，搜索“价格”或选择采购标签查看采购价格接口的参数结构与外部申请去向；未开通项**没有试调入口**，「模拟记录申请意向」仅在内存中记意向。列表/标签/详情并不连接真实数据中台；目录实际分类应取提供方 API，正式搜索要按团队权限在服务端分页执行。原型没有 PG 聚合或宿主成功调用回执，浏览、试参和推荐均不算真实调用；宿主任务里的外部 Tool 查询也是单独的固定虚构值，不可当 ERP 调用或复盘运行证据。
8. 打开 **Workbench 工作台**：首屏「带来一份材料」与「改进已有能力」进入同一四步材料工作区，而非另开独立体检页或按钮；先导入获准来源并限定任务，在事实梳理和经验总结各自看当前待核稿／评论（桌面约 2/3）与已有知识准确版本对照（约 1/3；移动端排在本项之后）；事实梳理中必要时核数字的报表口径及 Tool 授权条件，最后在「加入知识库」预览独立去向、门禁和合成 Skill／人工写法的假设比较。只有明确证据缺口或稳定流程值得继续时，才从结果按条件进入知识／Skill 深层工作区。后续「需要我处理／我关注的进展」是两张**固定的虚构情景卡**，用于讨论“明确补证请求才是我的行动，提议者等待核对只是关注”；卡片不会随当前评论、提议或模拟发布动作迁移。工作台不汇总真实身份、指派和生命周期，模拟未绑定时隐藏情景标题而不把不可见当作零待办。已发布且无新动作的事项应退出个人进行中，正式版本到团队资产只读查看；详情见[工作台事项机制](../界面功能设计/02-Workbench工作台.md)。
9. 在左侧 **团队资产 → 智能诊断** 看 AI 巡检雷达的三类预置演示发现：核清单 A 与模板 B 是否在同一任务及生效时间冲突；核项目 A 的约定复核点之后能否取得权威进展；核限定交接流程中 Skill 实际运行、Tool 授权与人工判断的衔接。逐条进入只读详情看来源、未知点及建议动作，可本地标「待补证／不适用」，返回卡片能看到反馈；没有真实扫描、通知或自动个人待办。流程衔接的详情还可**主动**打开一类虚构任务的四个判断点；候选能力地图不是全团队自动覆盖率。此处的 SK-02 v1.1 是另一份虚构 Skill，与「加入知识库」中用于比较的 SK-01 v1 周报整理示例不是同一资产或修订链。

## 材料主路径与按需进入的深层会话

四步材料主路径是「导入来源 → 事实梳理 → 经验总结 → 加入知识库」。事实梳理和经验总结各自以当前事实点／经验议题的待核稿与评论为主，桌面约占 2/3，另 1/3 对照已有知识准确版本；移动端对照在本项之后。每项区分来源自述、已核、冲突、未取得和不适用，并标可访问的出处／时间。数字口径在事实梳理中先核有权报表，只有身份、用途、指标定义、字段/对象、时间窗与只读通道均获授权时才可就地试行 Tool 核验；固定数值和按钮不证明真实调用。「加入知识库」分别预览来源、事实、经验、已有知识与 Skill、Tool、一次性事项的去向及门禁，并可并列比较**两种合成写法**的条件/反例；比较不是生成/测试/批准 Skill，按证据缺口才有深层工作区入口。

**事实梳理／经验总结中的讨论**：在相应当前待核稿上选段评论、查看固定完整下一版待核稿（v2、v3……）、差异、旧稿与回退；无选区可评论整段。只有指定参考周报完整 SHA-256 字节匹配或内置脱敏缩写才提供这套人工编排议题；粘贴全文或其他输入不触发抽取，文件指纹不证明分享资格。来源当时说法、正式知识及原件均不被覆盖；需核查才按需展开 32 段／111 显示行与 22 条处理线索（附件未读、尾部非正文排除），不能逐格推断已核。项目 A 备选料与跨场景需求整合两段经验只是不同的待核议题，可继续待核或不沉淀；只有有权、可核的准确旧版及确实新增条件满足，才预览原 ID 修订或新目录 `knowledge/<domain>/<topic>/<slug>/`，不等于已写仓库。来源、事实、规则、KPI／计划／一次性处置各归其有权去向，不强迫都成为知识。本地评论仅命中有限预置方向；未覆盖则保原稿并允许重试，换材料／议题或撤权使未提交选区失效。旧 K-01 v1 → R-02 在另一可展开记录中独立演示，不能当本周报已发布。详见[知识创作规格](../界面功能设计/03-知识创作会话.md#材料主路四步与指定版本深层操作的分工)。
**完整周报覆盖合同（静态原型已人工编排逐段去向，非实时解析）**见[知识创作规格的逐区块表](../界面功能设计/03-知识创作会话.md#完整周报的覆盖合同静态原型已逐段人工编排非真实抽取)：固定参考周报的来源元数据、五类 KPI、主料/包装、MRO/IT、SRM/培训、供应商开发、质量与月度评估、三条彼此独立的降本路径（需求整合、货代竞价、VMI）、价格风险中已复核与拟锁价、产品线 C 的预测/处置/待验证替代、下周四组计划及未读附件引用均在范围清单中有去向；107–111 的围栏、`eof` 等尾部非正文排除。矩阵每格可有多条，也可无条目并给理由；**22 条线索不等于 22 篇知识**，完整覆盖不等于逐行入知识，不复制受限原始数据。`index.html` 的内置材料是**脱敏结构缩写而非完整原文**，文件 SHA-256 `85018947cb5bd65e694b4f2a1e3f31769abc51c4f61fd8a6a96e30b93b4301c2` 命中时仍展示同一套人工编排覆盖与候选，指纹仅证明字节一致，不证明已解析、授权、核证或查重；粘贴原文亦不会命中。两条完整议题仍只是由这些线索人工综合的待核判断，而非自动抽取或已发布知识。无真实集成或自动提取，Git 正式版与 WeKnora 来源阅读／正式知识检索仍须分别授权和读回。

- **静态原型与真实插件集成不是一回事**：双击 `index.html` 只调用本地预置回复，评论触发的“生成中／失败／下一版”都在浏览器内存中演示，不发网络，也不能证明已接入模型。本轮交付的是产品文档与静态页面，并未实现或验收 DSH Client 的原生 Session 修订。若将来使用公开 `ctx.sessions`，目标 Profile 的插件权限、成功 turn 的唯一关联、宿主历史可回看及模型去向／留存策略仍须另行实测；这里不安装或运行真实 DSH／Provider，也不发送生产材料。评论、草稿 v2 或本地 `accepted` 都不算正式知识版本或发布回执。
- **Skill 改进工作区（仅在「加入知识库」时发现已有版本的具体质量缺口、且有权继续核证时进入）**：默认围绕外部任务中调试所得或已有 Skill 的来源、准确版本、适用范围及问题做质量核验。本地虚构的 SK-01 v1 周报整理 Skill 在“实际／预计”方面留下改进线索；按需核来源与适用、已有步骤、待核差异及受控共享门槛，不另设四步导航。合成的 Skill 写法与合成人工写法既非真实试跑，也非标准答案；可切换正常／边界／异常 fixture、标记本地“设计待补”，但**没有真实测试、没有保存 Skill 包或通过记录**。新建 Skill 仅限没有适用已有版且重复稳定、可复测的流程；一次性工作或知识／Tool 证据不足不强行封装。最后一步只说明真实测试、审核、SkillHub 读回、分发与宿主安装／加载／执行各自需要的证据。

## 刻意保留的边界

- 同一 Workbench 可以被不同团队安装，但每个团队的 `team-knowledge-asset`、Git 仓库、草稿及授权各自独立；本产品体验不设计跨团队分享。团队内可贡献，不等于所有敏感来源或正式审批动作无条件开放。
- 选中内容评论是低门槛协作方式的**产品假设**，并未通过用户测试证明最优。真实实现需要稳定锚点、旧版快照、重新定位／冲突处理及审计；首版不做多人实时协同编辑。
- 没有角色视角切换，但仍需对具体确认、审核、发布和 Skill 运行做真实身份与权限校验；本页的模拟绑定或模拟确认都不是授权事实。
- 团队仓库可以记录获准展示的 Tool 目录引用及 Skill 依赖，不能创作 ERP/MES/数仓生产接口、批准价格/库存数据访问或保存查询结果。列表、分类标签、参数结构应从外部提供方/数据中台的目录 API 按可见权限取得；本原型仅用虚构预置条目。实际接口由外部提供方接入，数据责任方限定字段、对象和用途，DSH 运行时再次检查用户/服务身份与工具策略；低风险只读试参也须有经批准的测试通道，广场无试调。若增加团队调用次数，应依据授权的宿主成功调用回执做最小化 PostgreSQL 时间窗聚合，不存参数、结果或完整 trace，不以本地按钮点击冒充调用；无证据显示暂无法统计。申请不等于获批，查询能力仍待目标环境验证。写入业务系统的 Tool 不采用查询示意的门禁。
- Creation Session 不等于 DSH Runtime Session；Market 安装和面板加载不等于正式资产发布。真实发布仍须 Git 审核、CI、人类批准、Provider 读回及下游门禁。Skill 建议不代表宿主已支持自动匹配，该宿主能力尚待目标环境验证。
- 本页不持久化、不上传输入、不请求远端；复盘中的自由文本更正不进入示例交接，知识、Skill、来源核对与业务事实核对的粘贴草稿分别留在当前页面内存，刷新或模拟撤权即清空。知识页可以选择本地小型 UTF-8 TXT／MD／CSV 并读入同一文字框，但**没有**网络文件上传、PDF／Office／邮件解析、知识库授权检索或查重、任意材料自动提取、提取 Skill 执行、Git 归档/提交、WeKnora 索引或正式发布。也没有 Clipboard 自动读写；不要输入生产凭据、敏感原文、完整 Prompt 或 Tool Call trace。模拟提交候选、评论和状态不能充当交付、真实业务结果或收益证据。
