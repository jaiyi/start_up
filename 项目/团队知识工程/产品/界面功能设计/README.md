# 界面功能设计：先推敲工作，再决定画面

这里是逐页讨论稿，不是[当前可视化原型](../可视化原型/index.html)的功能说明书，更不是 DSH 已实现能力清单。设计起点是：**让本团队的人在当前任务中找到可核对的依据；发现不对时，能把问题带到具体资产与有权处理的人那里；经确认的修订才进入后续任务。** Workbench 在 DSH Desktop 内承接资产协作和治理，不复制宿主对话、任务执行和业务审批。初版只设计一个团队、一个 `team-knowledge-asset` Git 仓库；不设计跨团队流通。围绕限定任务情境的「提供获准材料或描述需要的能力」是**一个四步材料入口：导入来源 → 事实梳理 → 经验总结 → 加入知识库**，没有独立「能力体检」页或按钮。事实与经验分别以当前项待核稿／评论为桌面约 2/3、已有知识准确版本对照为约 1/3；移动端对照接在本项后，证据逐项区分已核／来源自述待核／冲突／未取得／不适用。事实梳理中数字先核指标口径，只有当前身份、用途、对象/字段、时间窗与只读 Tool 通道获授权才就地核验，不单设数字步骤。「加入知识库」预览独立去向及门禁，条件性比较合成 Skill 与人工写法的正常/边界/异常示例，并非真实试跑或独立体检。当前待核稿的选段评论和已有知识对照均已在事实／经验两步，只有指定正式版受控修订或稳定可测 Skill 缺口才按条件进入深层会话；一个入口不等于批准所有去向。入口在工作台承接，知识与 Skill 会话分别处理被核证后的分流；原生 DSH 任务仍在宿主中，不在静态原型里运行模型、子 Agent、文档解析或业务 Tool。

上表“一页”指一个需要单独核对功能逻辑的页面/视图，不一定意味着独立技术路由；12 是宿主中主动调用的 Skill 产品规格，13 是**跨入口骨架规格**，两者都不是 Workbench 新导航页。当前静态原型的工作入口是一条「导入来源 → 事实梳理 → 经验总结 → 加入知识库」材料主路；事实与经验两步各自对当前待核稿评论并对照已有知识，指定知识修订和 Skill 改进仅为有具体缺口后的深层工作区，**不是并列侧栏入口，更没有独立「能力体检」页面或按钮**；下文页名是拟议功能位置而非已实现导航。业务对象页和工作记录详情是 13 所定义的拟议视图，原型已有虚构示意、尚无真实资料接入。Tool 两个 tab 单独写，是因为**已经开放的目录**和**尚待申请的目录**不是同一种状态。讨论、提议、核对和地图虽非左侧一级入口，也分别有自己的判断任务。

## 单入口的判别与场景评估（拟设计）

成员只表达一件事：**给出获准使用的材料，或描述在某类任务中缺少的能力**；在同一四步中先导入获准来源，再分别梳理事实与总结经验：每项当前待核稿与评论对照已有知识；数字的口径及 Tool 逐次授权在事实梳理就地核；最后在「加入知识库」预览独立去向及合成 Skill 比较。没有中间独立体检分流或「已体检」成功状态；可输入文本／获准文件定位、当前任务情境与期望结果；不要求先选知识、Skill、Tool 或“是否有候选”。界面随后给出「材料可处理性与分享资格」「已有知识／Skill／Tool 在该场景是否适用」「还欠什么证据」的分层结果：来源/归档去向、已有准确版本引用或修订、新知识待核议题、已有 Skill 修订或新 Skill 设计、Tool 的目录/授权申请、仅原任务人工处理、证据不足暂不资产化。一个意图可有多个独立去向，但没有哪条去向自动批准下一条。能力缺口不等于缺知识；要求实时数据或逐次审批时不得转写为静态知识/Skill。

**场景评估卡**贯穿 DSH 复盘、工作台索引、知识/Skill 会话与候选能力地图，绑定限定任务、判断点、样本/时间窗、适用对象及场景 owner（待指派时明示）、核证责任人和最近复核时间；列出每项获准来源、具体知识 ID／版本及有效起止、Skill 版本／发布与安装加载执行状态、Tool 接口/接入和逐次授权状态、真实任务结果或缺口、反例及下一次复核/失效日期。项目负责人、材料作者、资产维护人和业务批准者不能相互代替；生效日期须来自有权依据，未知不能默认“至今有效”。每个判断按证据标「暂定／待补证／已核证可在该范围引用／失效」，场景卡的结论不替代正式资产版本状态、业务批准或实时执行结果。不能取到原件、版本、授权或调用回执时显示无法确认及负责核对者，不从无命中推断不存在。

正式路径须分别拿到来源授权和格式/锚点能力核验、已有资产准确版本和适用边界核对、知识 Git 审核及索引逐文档读回、Skill 指定草稿的脱敏测试与 Git/SkillHub 读回、Tool 提供方及运行时授权/真实调用回执；展示每道门槛的证据出处、时点、状态及阻断/下一责任人。**当前静态原型只展示人工 fixture 和本地交互，没有真实 Tool 指标核验、合成 Skill 对比的试跑，也没有原生 DSH 或未来数字员工/员工 Agent 使用接入**；其使用归因只可标为待验证，不得把浏览、推荐、粘贴、模拟回复当引用/加载/调用。

## 导航与返回约定（拟设计）

1. **原生任务 → 自愿复盘 → 讨论确认 → 人工复制。** DSH 对话与任务为主线；任务后成员可主动调用[任务复盘 Skill](12-任务复盘Skill.md)回看步骤、现有知识/Skill/Tool 的使用证据与额外调整，逐条讨论哪些可复用、哪些仅当次处理及是否新建/更新资产。经用户核对、脱敏的结论才可复制到有权访问的知识或 Skill 创作会话。报告/PPT 等产物只在来源和分享权限获核对后，引导成员去**经验证**的团队资料库入口提交；资料入库与正式知识修订分开，复盘不会自动上传、建待办或发布。初版不依赖任务结束事件、自动卡片、插件嵌入会话或自动传参。
2. **最小线索 → 核来源 → 主动发现增量 → 对照已知。** 粘贴到 Workbench 仍是“用户提供、待核实”；只有检查可分享范围并明确提交、得到真实受理回执后才显示“已收到”。[团队知识骨架](13-团队知识骨架与工作记录.md)把获准分享的工作记录、待核项目/产品事实、描述性经验与稳定可测试的 Skill 区分开；知识创作再由产品主动识别 0..N 张候选，按有权访问的版本/边界核既有知识，只对真实缺口提问，明确无增量、重复覆盖、修订、冲突和查重不可核的去向。原件版本和事实核对另行进行，不让复盘片段冒充纪要全文或当前事实。没有资产可先记录最小化任务疑点，不伪造可评论的知识条目。未来若 DSH 提供获验证的结果卡/最小上下文深链，可优先落到具体对象；直接从左侧入口进入则按团队习惯搜索/选择项目、来源或内容。
3. **问题 → 修订 → 发布 → 展示。** 内容讨论归档线索、处理回执；修订提议确定基线与差异；核对页判定特定草稿；知识或 Skill 创作会话按类型完成正式审核、发布及目标读回；团队资产的「最新进展／全局概览／智能诊断」先进入同路由只读详情，成员主动选择补证、讨论或创作后才跨页。经批准的知识可在获授权的 WeKnora 阅读层检索并展示版本引用，Git 仍为正式版本权威；不能凭知识库 URL 嵌入异源页面或推断具体文档已索引。任何一步都不能因为前一步“完成”而自动生效。关联只在授权范围内可见。
4. **Workbench → 原任务。** 初版由成员在宿主手动返回原生会话；待导航能力验证后可保留不含对话原文的可失效返回定位，返回时 DSH 重验任务、团队和内容权限。任务关闭、链接过期或被撤权时，不恢复内容，提供宿主任务列表或受控的人工处理入口。处理结果可回访，但“问题有人受理”“知识版本已更新”“当次业务问题已解决”要分开显示。
5. **Tool 的两条路。** 已开通和广场都按提供方/数据中台目录返回的业务域及系统标签查找，服务端在本团队可发现范围内搜索、筛选和分页；从宿主或 Skill 依赖可定位已开通 Tool 详情，或去广场了解申请路径。详情参数结构不等于调用权；低风险只读试参必须由受控宿主/提供方测试通道逐次授权执行，广场不可试调。申请由外部提供方/数据责任方处理；回到 DSH 任务查询仍须宿主接入、调用身份、环境、字段/对象/用途授权、接口健康与运行时策略逐次核验。若日后展示团队调用次数，须据宿主授权回执另行做最小化 PG 聚合，不从目录浏览、试参或推荐推算。Workbench 不代发生产请求或存密钥。

人工复制的候选只带用户核对、获准分享的**最少内容**，不把整段对话或受限产物粘进团队仓库；产物仅在真实入口和授权核实后由成员另行提交为来源资料，不能自动变为正式知识。未来自动跳转若实现，也只能携带最小授权上下文：团队空间标识、源任务的可失效返回定位、资产 ID / Git 版本、段落稳定定位与文字快照（若有）、反馈类型、相关修订/问题 ID；不携带完整聊天、完整 Prompt、Tool Call trace、实时库存/价格或敏感业务原文，目的页重新授权。选区定位是待验证的交互方案，旧版锚点不能静默贴在新版相似文字上。

## 统一的状态与权威边界

- **资料/工作记录**有来源但不代表已确认；**Agent 整理/复盘原材料**是线索；**评论/任务疑点**已收到不代表已处理；**草稿修订**已提出不代表已确认；**针对特定草稿的确认**不代表已发布；**正式可引用版本**还须 Git/CI、人审、Provider 读回及授权范围确认。内容版本前台用“整理中／待核对／团队可用／已停用”，后台门禁证据不能丢；来源记录、原材料回执、Skill 安装/加载/执行各有自己的状态。当前项目分工等事实还须核来源、生效时间及业务权威；当前任务是否获批仍以原业务系统/有权人判断为准。
- 目录可见、组织开通、团队可发现、用户/服务身份获数据授权、宿主接入、运行时查询成功，都是不同事实。任何外部状态 `unknown` 要待对账，不能写成成功。
- 团队成员在能访问的范围内均可指出问题、补背景和建议；确认、审核、发布、Tool 数据调用与业务审批按各自策略授权，不按“员工/专家/管理者”拆页面。
- 初版只围绕一类低风险、证据可查的任务。真实 DSH 集成、搜索和推荐能力、接口目录及授权状态、回访链路、维护成本和收益都须验证；未经真实访谈，不以本稿证明需求或效果。

## 用来逐页 review 的标注

每页包含场景与目标、页面信息、主要功能的流转、异常与权限、跨页去向、与现有原型差距和待讨论点。**拟设计**表示希望检验的功能逻辑；**原型已示意**仅指 `../可视化原型/index.html` 中的虚构内存交互；**待验证**表示要从目标宿主、提供方或真实任务取得证据，不能先承诺可用。建议按 01 → 02 → 03 → 04 → 05 → 06 → 10，再看 07、08、09、11；评审时逐页保留、修改或删减，不急着把所有假设画进原型。
