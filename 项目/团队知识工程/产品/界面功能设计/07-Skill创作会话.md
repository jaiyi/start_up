# 07 · Skill 创作会话（拟议页面规格）

> 供 PM 与团队评审的设计提议，不代表已实现、已验证宿主能力或已上线的业务流程。页面按“创作一条可复用工作方式”的任务组织，不按创作者、审核人另拆页面。返回[页面索引](README.md)。依据：[产品蓝图](../03-Workbench如何解决.md)、[初版假设](../04-初版假设与迭代.md)、[交互原型](../可视化原型/index.html)及[Workflow 到 Skill 的边界](../../方案/10-Workflow到Skill的生成、测试与发布.md)。

## 场景与目的

本团队成员从[团队知识骨架](13-团队知识骨架与工作记录.md)中的描述性方法或真实工作流中发现一套**稳定且值得复用**的步骤，可从[工作台](02-Workbench工作台.md)发起“从工作流创建 Skill”，或从已发布 Skill 的反馈/版本发起独立修订会话。也可由成员在 DSH 主动运行[任务复盘 Skill](12-任务复盘Skill.md)，先核对任务过程与实际使用证据，再与 Skill 讨论“同类任务能否重复使用、哪些只是当前特例”，并将用户确认、脱敏的**候选结论**手动复制到本页。复盘条目是待核原材料，不是原纪要全文，也不自动成为 Skill；描述性经验可以独立存在，不为凑 Skill 而封装。该讨论不证明既有 Skill 曾加载、执行或失败，更不是指定草稿的正式确认；进入本页仍须选择具体 Skill 版本、合法来源和可复核样例。目的是把可执行部分变为可核对的 Workflow Draft、Skill Draft 和脱敏测试证据，再受控提交；不是从[DSH 对话与任务](01-DSH对话与任务.md)的一次推荐直接生成、安装、加载或运行 Skill。流程不稳定、依赖当前逐次审批时，应停在人工路径。

## 页面内容

- 顶部：服务端核验的当前团队/资产空间、会话 ID、草稿修订、基线资产版本（如有）、面向成员的内容状态“整理中／待核对／团队可用／已停用”、当前步骤提示“描述→建模→生成→测试→受控发布”，以及保存/等待/未知提示；步骤不是正式资产发布状态。同一 Skill 可有团队可用的旧版及整理中的新修订，未发布候选被拒绝也不等于旧版已停用。
- 对话区：Agent 追问目标、触发、输入、步骤与判断、人类确认点、例外/停止条件、输出及成功标准；每次建议注明来源、假设、变更差异和未确认项。
- 结构区：Workflow Draft 的步骤与分支、Skill Draft 文件/契约/所依据的团队经验及具体知识版本、关联项目/产品线（多对多引用，不复制正文）、外部 Tool 能力**需求声明**及待确认条件；Agent 建议须逐项采纳/拒绝，不静默覆盖。来源记录和复盘原材料只能在授权范围内作待核依据，不能因 Skill 引用就升级为已确认事实。
- 证据与动作区：脱敏样例、正常/边界/异常/回归/安全测试的期望与实际差异，失败原因，审核/发布证据与责任人；提供“保存、暂停/恢复、生成草稿、试跑、预览提交、查看审核/发布读回”，只显示当前身份和状态允许的动作。

## 功能流程与状态

| 触发与前提 | 用户 / 系统步骤 | 状态变化与成功去向 | 失败、权限或未知去向 |
| --- | --- | --- | --- |
| 点击“从工作流创建 Skill”；当前团队资产空间绑定且有创作权限 | 服务端校验身份、团队与仓库绑定；建立独立 `Skill Creation Session`、Workflow Draft、`session_id/draft_revision_id`，进入描述区 | 会话 `active`、草稿未确认；回本页原会话继续 | 未绑定/无权则不读取团队草稿，提示联系责任人；创建结果未知先按操作记录查回，不盲目再建会话 |
| 描述流程或从正式版本/反馈候选修订；有权引用原资产 | 用户补输入、步骤、人工节点与例外；系统提出候选结构、显示采纳差异；保存新草稿修订，修订已有版本时固定 `base_asset_id/base_revision` | 草稿“未保存→保存中→已保存（修订/时间）”，可暂停后由原位置恢复；保存不等于确认 | 保存失败保留本地内容；旧会话/回调、基线版本变化时标 `revision_conflict`，由获授权且承接该修订的成员对照合并或分叉，不覆盖正式版本 |
| 草稿具备可测试契约与脱敏 fixture | 用户选测试并查看期望/实际、权限和失败断言；系统将结果绑定当前草稿修订与依赖版本；人选择修订并重测 | `draft→tested（有证据）`，留在本页“测试/差异”；样例通过不等于 stable 或业务成功 | 缺字段、依赖不可访问、Tool 权限未知或测试失败：标阻断与原因，补证/修订/维持人工，不用真实生产数据试跑 |
| 用户预览提交；具备提交资格、当前修订测试合格且基线未漂移 | 系统复核知识/Tool 依赖仅为声明、路径和风险；受控 Git MR/CI，由对该对象与修订具有审核权限的人按现行策略批准；从批准 merge commit 构建固定 digest，请求 SkillHub release 并核对读回 | `待审核→approved（Git）→released（SkillHub 版本/digest 读回）`；审核、发布、读回和异常对账都在**本 Skill 创作会话**的指定修订流程中进行；到只读[团队资产](10-资产与发布.md)查看正式版本，交接证据仍留在会话 | 驳回/CI 失败回草稿新修订重新过门禁；发布或 digest 读回未知进入对账，禁称已发布或重复发布；无人有权承接则待安排而非默认批准 |

暂停不发起新操作；归档/只读只保留查看，分叉产生新会话。已发布 Skill 的修改也在本创作会话基于固定资产版本发起独立修订，而不是在[团队资产](10-资产与发布.md)直接覆盖正式版本；工作台仅在成员对这份修订有明确当前动作时显示待办，创建者在别人审核期间只关注进展，详见[工作台事项规则](02-Workbench工作台.md)。每次保存、提交与异步回调重新校验会话、草稿修订、权限和幂等状态。发布后的分发/安装、DSH profile 加载、真实任务运行与业务成效是**独立状态和权威**；Workbench 不提供宿主运行按钮。失败的业务任务只形成可追溯的反馈候选，不直接改写现有 Skill。本地 `knowledge-compounding` 是用户工作区实例；它的收件箱 `accepted/merged` 回执不代表本页已有团队版、安装或运行。

## 跨页路径

[工作台](02-Workbench工作台.md)发起/恢复本会话；[DSH 对话与任务](01-DSH对话与任务.md)的 Skill 推荐只提示范围与依赖，不能一键视为已有创作会话或已安装。知识引用到[知识创作会话](03-知识创作会话.md)核对来源；需外部只读能力时查看[已开通 Tool](08-已开通Tool.md)或[Tool 广场](09-Tool广场.md)，但目录可见与能力需求均不授予运行时权限；[候选能力地图](11-候选能力地图.md)仅将稳定步骤作为判断点证据。从只读[团队资产](10-资产与发布.md)的正式版本或缺口线索可发起并定位本 Skill 创作会话；发布/反馈处理仍在本会话的特定修订中进行，而非在团队资产页操作或在宿主运行会话中编辑正式资产。

## 访问与数据边界

每团队独立 Git 仓库、草稿、测试、job 和审核；服务端基于 DSH 身份映射校验 `team_id/asset_space_id/session_id` 与来源 ACL，不能用客户端路径或宿主 ownership 当授权。真实确认、审核、发布责任人和执行服务身份分列。Skill 的 Tool 依赖不等于 Tool 注册、接入、数据授权；提供方/数据责任方与 DSH 运行策略决定可否调用。Git 仅纳入受控脱敏文件与引用，不保存 Token、生产输入、敏感原文或完整 Prompt/Tool Call trace。

## 与当前原型的差距及待确认

原型[Skill 创作会话](../可视化原型/index.html)只以虚构数据示意步骤、Tool 依赖、返回任务及手工粘贴候选的浏览器内“已收到”；无真实收件箱受理、创建/恢复会话、草稿版本、测试、审核、Git/SkillHub 读回或 DSH handoff。以上均是拟议交互，不能把模拟页当集成证明。

- 首批哪一类稳定流程确有 owner、合法来源、脱敏测试和可复核成功标准？不满足是否不做 Skill？
- 目标 Skill schema/loader、SkillHub 发布路径与 DSH handoff 哪些已在目标环境验证，哪些应保持管理员 fallback/未知？
- Tool 依赖无法授权、正式基线冲突或无审核容量时，谁决定缩小范围、暂缓或终止？
