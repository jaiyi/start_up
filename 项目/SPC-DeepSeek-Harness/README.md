# SPC × DeepSeek Harness

SPC × DeepSeek Harness 是 AI 平台方向下的具体试点项目：以工业质量异常闭环为真实场景，验证 DeepSeek Harness（管理面）、通用计算节点（运行面）和 SPC 领域 profile 如何共同支撑可审计、可恢复、可迭代的任务执行。

它不是“AI Native 任务闭环平台”总体蓝图的实现宣称，而是一个有明确场景边界的试点。上层方向判断和通用设计推演见 [`洞察/AI原生转型/`](../../洞察/AI原生转型/)；本项目只记录 SPC 试点自己的架构决策、实现计划、代码、测试、集成和验证结论。

## 试点目标

1. 用 SPC 质量异常场景验证事件到任务的触发、分派、执行和关闭链路。
2. 验证 DSH 管理面与通用计算节点运行面的边界，以及插件、profile 和领域能力的组装方式。
3. 验证工具调用、权限控制、状态持久化、人工确认、审计、失败恢复和反馈记录等平台能力是否能在真实场景中成立。
4. 记录哪些能力可以抽象为通用平台能力，哪些仍然只是 SPC 场景假设。

## 当前阶段

项目当前处于**设计收敛与验证准备**阶段：架构正文记录目标形态，验证矩阵记录首个垂直切片的验证项、通过标准和证据位置。除矩阵中明确登记为“通过”的项目外，其他能力都不能视为已实施或已验证。

## 当前验证边界

| 能力 | 当前定位 |
|---|---|
| DSH 管理面与计算节点运行面 | 试点架构核心，需通过实现和运行验证 |
| SPC 领域 profile | 第一个具体业务边界，不等同于通用领域模型 |
| 任务状态、事件和执行留痕 | 面向 SPC 异常闭环验证，不宣称已形成通用平台 |
| 工具调用、权限和审计 | 以实际接入的工具和权限场景为准 |
| AI 诊断、建议和反馈学习 | 通过样例、评测和人工确认逐步验证 |
| 跨业务复用 | 当前仍是待验证假设，不能从 SPC 试点直接推导 |

## 回流规则

每项通用能力都要区分三个状态：

- **试点假设**：只有设计推演或待实现，不写成已验证能力；
- **试点验证**：有实现、测试或运行证据，记录范围、条件和限制；
- **可复用方法**：经过多个场景或充分证据验证后，才回流到平台洞察或 [`知识/`](../../知识/)。

高风险动作必须保留明确责任人、人工确认和可追溯记录。
