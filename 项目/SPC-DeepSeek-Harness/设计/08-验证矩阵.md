# SPC × DeepSeek Harness 验证矩阵

> 本文是项目设计与实施的验证总入口，不替代 `00–07` 的架构、契约和风险正文。矩阵只记录当前要验证什么、如何验证、通过标准、证据位置和下一步；没有实现或运行证据的项目不得标记为“通过”。

## 1. 使用规则

### 1.1 状态

统一使用以下状态：

- `未开始`：已登记，尚未执行验证；
- `进行中`：已有验证动作或实现正在进行；
- `通过`：满足通过标准，且证据位置已登记；
- `失败/需重评`：验证未通过，需要调整设计或退化方案；
- `待触发`：当前不阻塞首个 SPC 垂直切片，等真实客户、第二个 profile 或真实连接出现；
- `暂不处理`：已明确不纳入当前阶段。

### 1.2 证据要求

“设计上可行”不等于“已验证”。验证记录至少应包含：

- 执行日期、版本和环境；
- 输入样例或测试数据引用；
- 命令、日志、响应或测试报告；
- 实际结果与预期结果的对比；
- 失败、降级和重试情况；
- 责任角色和后续动作。

证据统一回链到具体 Spike、测试报告、实现目录、日志或 receipt；在证据尚未产生前使用 `待补证据`，不得填写“已验证”。

## 2. 首个垂直切片

本阶段只验证一条最小闭环，不依赖完整 UI、飞书、ops 或企业系统集成：

```text
假告警
  → 计算节点/测试入口落库 alert_events
  → DSH 唤醒或轮询补偿
  → 创建单事件诊断会话
  → 产出证据、候选根因和待查证项
  → 人工推进五个 gate
  → 结论、反馈和审计记录落库
```

成功标准不是“平台所有模块都完成”，而是这条链路可以在限定环境中重复运行、遇到失败不会伪造成功，并且能够指出哪些环节仍是手工或模拟实现。

## 5. 暂不处理

- 旧四仓最终封存、迁移和历史数据迁移：等 MVP 跑通后再裁决；
- 完整多租户、多工厂和组织级权限中心：首版单租户不实现；
- 通用 pipeline DSL、完整连接器注册表和多服务并发治理：没有第二 profile 或真实连接前不实现；
- 代码级候选算子进入生产节点：没有经过沙箱与算法工程流程，不开放；
- 真实生产参数写入、lot release、PCN 发布、异常自动关闭：不属于本试点首版自动化范围；
- 真实飞书群、真实业务系统和生产数据库：Spike 与首个最小验证使用隔离环境或假数据。

## 7. 更新规则

每完成一项验证，必须同时更新：

1. 本矩阵的状态、证据位置和下一步；
2. 对应设计文档中的限制、契约或失败分支；
3. 项目 README 的当前验证边界；
4. 若结论可跨场景复用，再评估是否回流 `洞察/` 或 `知识/`。

没有证据的“通过”应视为无效状态。
