# AI-Native 任务闭环平台

这是一个面向企业 AI Native 任务闭环的工程架构项目，用于把 `洞察` 中的方向性判断转化为可实现、可拆分、可验证的产品与工程设计。

它不是外部产品资料库，而是自己的长期实战项目：围绕真实业务场景，设计任务对象、状态流转、连接层、AI Skill、知识调用、权限审计、人工确认、反馈学习和经营归因，并在后续迭代中逐步实现和验证。

## 目录

- [`设计/`](./设计/)：总体工程架构、连接层与 MCP 工具网关、任务状态与动态状态层等设计文档。
- 后续可根据实现阶段增加 `实现/`、`测试/`、`部署/`、`运行记录/` 等目录；新增目录应有明确职责，避免把外部调研重新放回项目。

## 项目来源

- 方向判断来自 [`洞察/AI原生转型/`](../../洞察/AI原生转型/)；
- 技术方法来自 [`知识/技术/`](../../知识/技术/)；
- 场景启发来自 [`研究/案例/`](../../研究/案例/)；
- 外部产品能力对比来自 [`研究/产品/工业AI/`](../../研究/产品/工业AI/) 及其他产品分类。

## 与研究目录的边界

`研究/产品/工业AI/` 记录外部工业 AI 产品、厂商能力、公开案例和证据；本项目记录自己的架构决策、实现计划、代码、测试结果和迭代结论。外部资料可以作为设计输入，但不能把“参考了某产品”写成“已经实现了该能力”。

## 与 SPC-DeepSeek-Harness 的关系

- `项目/SPC-DeepSeek-Harness/` 是面向 SPC 场景的具体 Harness / Agent 实战项目；
- 本项目抽象跨业务任务闭环平台的通用工程能力；
- 两者可以共享连接层、工具权限、任务状态、审计和评测方法，但业务对象、交付节奏和验证范围分别维护；
- 只有经过具体项目验证的通用能力，才应回流到本项目或 `知识/` 中沉淀。

## 当前推进边界

优先围绕一个高价值任务流完成最小闭环：业务对象与任务状态 → 只读连接 → 受控写入 → AI Skill → 人工确认 → 审计与补偿 → 反馈和知识沉淀。高风险动作必须保留明确责任人和可追溯记录。
