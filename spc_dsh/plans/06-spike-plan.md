# 第一刀技术 Spike：DSH 常驻与外部唤醒验证

> 上游：[00-overview.md](00-overview.md)

## 1. 为什么这是第一刀

整个"后端 POST → Agent 瞬间唤醒 → 推理 → 飞书"架构成立的前提是：

**DSH 能以 server 模式常驻，暴露 HTTP 接口，被外部 POST 唤醒一个推理会话。**

当前仅验证过：CLI `dsh --version` = `0.2.0-rc.2`、`@deepseek-ai/dsh`/`dsh-tools` 包已安装、插件注册 API 类型声明存在。
**未验证**：server 模式、HTTP 路由能力、外部触发会话、回调执行。这一刀失败，唤醒机制退化为轮询，架构需重评。

## 2. Spike 范围（最小可证伪）

用一条**假告警数据**跑通四个动作：

```text
① DSH 以 server/daemon 模式启动并常驻
② 插件注册的 HTTP 路由可被外部 POST 命中
③ POST 触发一个推理会话,会话内调用一个注册的工具
④ 工具执行结果以某种方式离开进程（写文件/回调 HTTP 均可,证明外部可见）
```

飞书推送不进 spike（依赖网络与群配置，且非架构风险点）。

## 3. 验证步骤

| # | 步骤 | 通过标准 | 失败含义 |
|---|---|---|---|
| 1 | 查 DSH 文档/CLI 帮助确认 server/daemon 形态 | 找到官方支持的常驻方式 | 无常驻方式 → 唤醒架构不成立 |
| 2 | 启动常驻实例 | 进程存活、有监听端口或 IPC | — |
| 3 | 加载最小测试插件（apply + defineTool + HTTP 路由,如文档支持） | 插件加载成功、路由注册 | 插件不能带 HTTP → 插件 D 形态要改 |
| 4 | `curl POST` 假告警 | 收到非 5xx 响应,进程日志可见 | — |
| 5 | 确认 POST 触发了推理会话 | 会话记录/日志中可见一次模型调用 | 无会话触发 API → 需查 DSH 是否提供编程式会话入口 |
| 6 | 确认会话内工具被调用且结果外部可见 | 文件/回调收到数据 | 工具执行不可达 → 链路断 |
| 7 | 重复 POST 同一 event_id | 第二次被识别为重复（如插件内做了幂等） | 幂等需在插件层自建 |

## 4. Spike 产出

- 可行/不可行结论 + 证据（命令、日志、响应）。
- 若可行：确定插件 D 的路由注册方式、会话触发 API、鉴权挂载点。
- 若不可行：给出退化方案评估（后端队列 + DSH 轮询 / 定时批处理诊断），并重新讨论告警链设计。

## 5. 边界

- spike 不连真实数据库、不发真实飞书、不部署后端。
- 假数据字段按 [03-backend-compute.md](03-backend-compute.md) 投递契约构造，为后续平滑替换做准备。
- spike 代码是一次性验证物，不直接进生产插件。
