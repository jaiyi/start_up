## 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| DSH 无 server/唤醒能力，唤醒架构不成立 | **高** | spike 先行；退化方案已备（轮询/批处理） |
| rc 版 API 变动导致返工 | 高 | 锁定版本；插件层薄、核心逻辑在后端与 Postgres，可整体迁移 |
| 全盘替代工作量被低估（UI、飞书、工单流全要新建） | 中高 | MVP 分期：调试模式工作台先行；运营面板第二步 |
| 工作台前端成为新的"跨仓对齐"负担（违背初衷） | 中 | 前端薄：优先只做 gate 推进 + 回放对比，复杂分析仍在 Agent 会话内 |
| 迁移文件与插件 F runner 的版本漂移 | 中 | checksum 记录；迁移文件随 profile 同仓同发布 |
| 告警投递丢失（后端 POST 失败且重试耗尽） | 中 | 投递状态落库 + 死信记录 + 运维告警；不静默 |
| 专家审批环节成为发布瓶颈 | 中 | 调试模式回放对比降低审批心理成本；审批可批量 |
| 单人依赖（目前设计-实现集中于一人） | 低 | 本文档集即为知识沉淀 |

## 已识别但暂不处理

- 旧四仓的处置（封存/归档）时机——等新体系 MVP 跑通后再定。
- 旧系统线上数据是否迁移——当前旧链路无线上流量（e2e NOT RUN），暂无迁移对象。
