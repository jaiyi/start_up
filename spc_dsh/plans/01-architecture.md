## 2. 模块职责

### 2.1 工作台 UI（独立前端）

- DSH 不提供 Web UI，此为独立工程。
- MVP 优先做调试模式：故障树编辑、历史事件回放、候选根因对比。
- 运营面板（五-gate 推进、告警列表）第二步上。

### 2.2 DSH 宿主与 profile

- `spc-station` profile 打包全部插件与默认配置。
- 会话内 todo/jobs 不是业务真相源；业务状态全部在 Postgres（对齐 17 号文档结论）。

### 2.3 后端计算服务

- 无 DSH 依赖，独立进程，systemd/docker 守护。
- 计算内核从 lads SPC 算法层平移（判异 Nelson/EWMA/CUSUM/T²、控制限训练、能力指数）。
- 详见 [03-backend-compute.md](03-backend-compute.md)。

### 2.4 数据库

- 全新 PG 实例，不碰旧库。
- schema 从 lads 迁移文件起步，由插件 F 的迁移 runner 管理。
- 详见 [04-data-and-schema.md](04-data-and-schema.md)。

## 3. 关键数据流

### 3.1 运营模式告警链（目标态）

```text
测量数据 → 后端判异 → 异常点确认
  → 后端 POST 插件 D（带 event_id、window_id、process_key、business_alert_time）
  → 插件 D 校验签名与幂等 → 唤醒推理会话
  → 插件 C 查证据（控制图、控制限历史、故障树分支）
  → 生成排障建议（区分事实/候选/待查证）
  → 发飞书群 + 落库为告警事件
  → 人在工作台走五-gate → 措施 → 效果观察 → 闭环
```

### 3.2 调试模式迭代链

```text
工艺专家在工作台编辑候选故障树/Pack
  → 插件 C 用候选 Pack 对历史事件回放
  → 对比候选根因与已知结论
  → 满意后提交发布 → 校验 → 专家批准 → 版本号递增 → 进运营模式
```

### 3.3 计算任务链

```text
插件 B 派单（任务类型 + 参数 + 幂等键）
  → 后端执行器入队、执行、写结果表
  → 回调插件 B（或插件 B 轮询）
  → 状态与 receipt 落库
```

## 4. 失败语义

全链路 fail closed：

- 插件 D 收到未签名/重复/缺字段的 POST → 拒绝并记审计，不触发推理。
- 插件 C 查不到 Pack 或 process_key 未注册 → 返回"该工艺未支持"，不回退默认工艺。
- 插件 B 任务失败 → 状态机标记 failed + 原因，不静默重试超过上限。
- 插件 F 迁移失败 → 停在当前版本，不半途改库。

对齐现有系统的 fail-closed 传统（state 校验、pack_loader 拒绝、advance bridge 审计持久化失败不伪造成功）。
