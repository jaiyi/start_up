# 12｜执行环境与隔离：把生成代码当成不可信工作负载

> 调研/复核：2026-10-28。适用：Agent 可运行代码、调用命令、解析文件或操纵桌面客户端时的架构、安全、平台与运维团队。防御性教育材料；不是任何沙箱产品的安全证明，也不包含可用于脱离隔离环境的操作指令。

## 定义与信任边界

**执行环境**是承接模型提出的命令、脚本或工具调用的进程、容器/虚拟机、文件系统、网络与宿主设备的组合；**隔离**是把这些工作负载的可见资产、权限和副作用限制在经批准范围，并在失败时阻止影响扩散。模型会生成看似帮助用户完成任务的代码，但生成内容和上传文件都应被视为不可信；“用户允许分析表格”并不等于授权读取宿主密钥或发送文件。资产包括源代码与私有文档、会话令牌、服务账号、其他租户工作区、共享缓存与宿主资源。

```text
用户意图/任务 ─→ 策略与身份决策 ─→ 任务队列 ─→ 一次性 Runner（低权身份）
                            ↑                        │ 只挂载批准输入、临时空间
网页/Skill/文件 ─→ 非可信指令/数据 ───────────────────┤ 受限 CPU/内存/时长
                                                     ├─ 代理出站：默认拒绝，按任务放行
密钥管理器 ─→ 有时限且用途受限的凭据边界 ─────────────┤
                                                     ↓
业务 API（再次核权） ← 请求/结果 ── 受控回传/扫描/人工确认 ─→ 用户
主机内核、桌面会话和其他租户处于 Runner 的外侧，不能随任务自动暴露。
```

代码执行、文件解析、浏览器自动化、桌面文件操作虽然入口不同，却共享“低可信内容获高权限处理”的风险。容器提供进程/文件系统等隔离能力，但共享宿主内核；虚拟机通常提供更强隔离边界，但并非消除配置与设备交互问题。没有一种机制能代替业务对象权限和数据出站限制。

## 两条典型失效链（均为无害示意）

1. **分析任务扩大文件权限**：用户仅让 Agent 汇总隔离目录中的测试表格；检索材料建议“先扫描整个工作区寻找辅助数据”，执行器若默认挂载用户主目录，代码便可能读到与任务无关的测试私有文件。失效不是“模型是否善意”，而是将任务描述误当文件系统授权，且 Runner 没有只读、按对象挂载。
2. **文档解析变成执行边界**：用户上传虚构演示文档，解析服务拥有和主服务同样的系统身份、缓存及外网权限。即使文件看似正常，复杂格式、嵌入内容或解析器缺陷可导致预览流程越过“只提取文本”的授权范围；若隔离与限额缺失，还会干扰其他任务。这里不提供任何恶意文件或漏洞利用步骤。
3. **共享 Runner 留下跨任务状态**：前一任务写入临时文件或缓存；后续任务复用同一个工作目录与凭据，导致相互读取或错误使用先前授权。即便每次调用有审批，进程复用和恢复机制也可能让过期授权继续有效。

## 分层防护与局限

- **入口及策略层**：区分“需要代码执行”和“仅需解释”，优先选非执行型工具；将允许的输入、输出、工具、工作目录、身份、时限写成机器可校验的任务票据。高风险动作由系统侧审批并复核参数，不依靠生成的解释自证安全。业务目的无法只靠黑名单关键词判定，仍需明确负责人与授权模型。
- **进程与操作系统层**：每任务独立低权身份与短生命周期隔离环境；禁用特权模式、非必要设备与宿主进程接口，收紧系统调用/能力；工作目录临时且只挂载批准资源，输入只读、输出显式回收，限制 CPU、内存、进程数、时长与磁盘。把解析器和可执行工具分别放进隔离环境并保持补丁更新。容器配置错误和内核/运行时缺陷仍有逃逸及旁路风险；隔离等级应随资产敏感度升级，必要时采用独立虚拟化或专用环境。
- **身份与密钥层**：不在镜像、提示词、环境变量快照或用户可读目录内长期存放高权凭据；按任务从密钥服务临时注入可撤销、用途/范围受限的身份，服务端核权；禁用到期后重试继续使用旧权限。短期凭据仍可能在有效窗口被滥用，日志及进程转储也可能泄漏。
- **网络与数据回传层**：默认断出站、隔离云元数据及宿主/本地管理端点，确需外部访问时通过可审计的请求代理单独授权；输出文件须做类型/大小校验、敏感级别判断和必要的人工审核再回传。网络封闭不能阻止已挂载文件在允许的回答渠道泄露，也不能阻止滥用已放行的 API。
- **桌面客户端本机权限层**：屏幕读取、剪贴板、辅助功能、键鼠控制、本地文件选择及跨应用会话应分别授权，不把一次系统级权限提示等同于用户对每个业务对象或后续动作的批准。默认关闭非必要的本机能力；按任务和目标应用收窄可见窗口与文件、限定执行时段，并在有副作用的点击/输入或跨应用传输前由宿主展示目标和内容、由目标服务再次核权。系统权限通常授予整个应用进程，不一定能原生细分至单次 Agent 任务；如果无法技术隔离，应停用相应自动化能力或改为人工操作，不可宣称已实现任务级沙箱。
- **检测与恢复层**：把任务票据、镜像/代码版本、挂载清单、限额、出站决策、退出码及输出哈希与审计关联；桌面操作另记最小必要的目标应用、窗口/文件范围、权限状态和业务回执，避免默认存储完整屏幕或剪贴板内容。异常资源用量或越权请求立即中止，撤权、隔离产物并重建环境；桌面会话还应停止自动化、核查系统权限与已产生的跨应用副作用。仅凭沙箱退出码为零不能证明结果正确或无越权。

## 非生产负例和验收观察

| 隔离测试 | 期望结果及证据 |
|---|---|
| 测试代码试图打开未挂载的另一个测试项目文件 | 权限/挂载层拒绝；审计可见任务及失败类别；无文件内容出现在输出 |
| 在模拟解析器中提交格式不匹配或异常大、深层嵌套的无害文件 | 配额/类型校验触发隔离失败，其他任务延迟不显著扩大，临时空间可回收 |
| 任务申请调用未放行的测试外部域名或本机模拟服务 | 出站代理/网络层拒绝，连接记录与拒绝理由可关联 |
| 任务到期后再排队重试，或另一任务读取旧工作区 | 旧授权不再生效；Runner、工作目录和凭据不被后续任务继承 |
| 在隔离桌面测试账户中授予模拟屏幕/剪贴板权限，让 Agent 尝试读取未批准窗口或剪贴板测试标记 | 任务级边界拒绝读取或停止自动化；记录拒绝类别，不记录测试标记正文 |
| 用虚构应用和文件演练自动文件选择、辅助功能键鼠操作及跨应用粘贴 | 未获当前目标和动作批准不得选择非任务文件、操作其他应用或粘贴；即使系统权限已授予，也由宿主和目标 API 核权并记录实际结果 |

测试须使用合成文件与模拟身份，不在生产环境尝试系统隔离突破；还要做镜像配置核对、失败注入和跨租户边界回归，不能把“跑通负例”当成对运行时零日的保证。

## 误区、剩余风险与一手来源

“在 Docker 里跑”“环境变量不是文件”“前端隐藏执行按钮”均不代表资源不可达。宿主内核、共享缓存、用户已授权的真实数据、解析器缺陷、合法输出通道与供应链依赖仍是风险；按负载敏感性核验隔离强度与可恢复性。

**资料与证据状态**：2026-10-28 对以下官方入口做了公开只读可达性核验，并抽样标题/文字；未逐条验证运行时产品实现。[NIST SP 800-190 Application Container Security Guide](https://csrc.nist.gov/pubs/sp/800/190/final) 提供容器安全背景；[Kubernetes Pod Security Standards](https://kubernetes.io/docs/concepts/security/pod-security-standards/) 提供工作负载限制参考；[OWASP Docker Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Docker_Security_Cheat_Sheet.html) 及 [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) 提供配置与文件处理参考。票据、隔离等级和验收要求属于本文实施建议，须按所用内核、云环境、桌面客户端及供应商版本实测。
