# 19 架构选型与可验证主权

> 范围与时点：2026-10-28 的企业选型方法，面向含模型、Agent、检索与工具连接的工作负载。实际价格、可用性、遥测、法域及退出条款取决于供应商、合同、部署与验证日期；不能根据“公有云/私有化”标签推导合规或安全保证。以下比较表、验收阈值是**本章原创工程方法**，非 NIST 或欧盟标准的强制指标。

选型前先写清楚业务约束：哪些数据允许离开哪个信任域，哪些业务动作必须同步审批，停服多长时间可接受（RTO）、允许丢失多少最新状态（RPO），谁实际控制密钥与最高权限，模型替换后最低业务正确性是什么。不能只比较 token 单价；总成本还包括算力预留、离线维护、密钥管理、迁移重建、应急能力和人员值守。

## 全链边界和候选架构

```text
终端/业务系统 → 身份与密钥 → Agent/工具网关 → 模型服务 → 业务 API
    │                                │               │
    └→ 文档/RAG/索引 → 缓存/评测 → 日志/遥测/备份 → 审计与删除
            └─────── 导出/替换/停服恢复链 ─────────────┘
```

| 模式 | 常见优势与待核控制点 | 必须验收的失效条件 |
|---|---|---|
| 公有云托管 | 弹性、服务丰富；核对真实推理区域、密钥持有、管理员访问、分包及跨域日志 | 区域选择之外的遥测/备份与停服后的导出 |
| 专有云/专用租户 | 计算隔离或合同定制可能增强；确认控制面、模型升级、密钥是否仍由服务商管理 | 控制面故障、远程维护、专有 API 锁定 |
| 私有化/自建 | 运维和网络可自行配置；须负担补丁、容量、权重许可、硬件及固件依赖 | 断网许可失效、无人修复漏洞、误配置特权 |
| 混合 | 敏感流程留内、一般任务按策略外调；重点验证路由和数据最小化 | 错误路由、跨域缓存、策略更新未覆盖备用线路 |
| 边缘/离线 | 有利低时延、弱网络持续工作；受容量、物理安全与升级约束 | 设备丢失、日志回传时泄露、离线模型版本漂移 |

不要将五类理解为固定安全等级；同一供应商也可能对不同模型、Embedding、向量库、推理缓存和诊断日志采用不同边界。逐条登记“承诺—配置—请求/回执证据—独立复验”，无法观测的环节注明对供应商证明的依赖程度。

## 两个架构失败案例

1. **假离线**：机房自建推理与知识索引，厂商许可、证书吊销检查和错误上报却依赖互联网；割断出口时 Agent 不再受理关键任务，恢复又产生积压重试和重复业务写入。离线性只在断网、密钥到期和恢复重放三个状态下才可验证。需要本地有界队列、幂等键和人工接管；不能擅自绕过许可。
2. **假可迁移**：托管模型提供“导出聊天记录”，却不能导出文档 ACL、向量索引元数据、Prompt/工具配置、记忆或审计关联；切换模型后工具调用语义不同，审批流程被跳过。部分数据可取回不等于业务可退出。迁移验收需业务功能、权限、安全审计和删除回执同时通过。

## 预防、检测、处置

**预防**：以敏感性与动作危害做工作负载分层；将业务授权置于模型外的资源系统；出站代理默认拒绝未登记目的地，密钥设置由企业核对的访问策略；模型、工具与数据采用版本化导出格式；签约前谈迁移支持、导出时限、留存/删除和事故协助。**检测**：定期检查 DNS/出站、管理员登录、模型版本漂移和备用路由，核验数据路径与合同一致，测定演练 RTO/RPO 和替代模型的高风险动作拒绝率。**处置**：故障时降级为只读或人工处理，阻断错误路由，撤销旧供应商令牌、导出并校验数据，按业务回执恢复，保留必要证据后请求删除证明。加密或本地密钥不解决被授权应用错误外发；某些第三方底层遥测不可独立观测，退出亦可能受许可与语义兼容约束，应列为剩余风险。

## 可复验选型门槛和退出测试（仅合成数据）

- 写出每类数据的输入、缓存、嵌入、日志、评测、备份、遥测去向；用合成标记和网关日志核实际路径，对看不到的分包流标记未验证。
- 用测试密钥隔离管理员角色，模拟撤权和密钥轮换；检验旧凭证不能继续访问检索索引、工具和备份。
- 在隔离环境模拟断网、模型服务超时和重试，量测只读降级、队列积压、幂等写入、RTO/RPO；不要以演练数值充作生产 SLA。
- 执行**真正的退出演练**：导出合成数据及 ACL/配置/日志关联，校验格式与数量，在第二种实现上重建索引、替换模型、回放负例，确认未授权操作仍被拒绝，计时迁移及重新索引；最后用合同约定程序验证旧端删除或记录无法证明之处。
- 评价成本时同时列出迁移窗口、回滚、培训、服务停用通知与适用地区的数据处理评估，不把“能下载文件”判为退出合格。

## 一手资料与未验证项

- [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)：治理与持续风险管理的参考；不提供上述部署方式的固定排名。
- [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final)：身份和资源访问边界参考；零信任不等于模型/供应商可替换。
- [欧盟委员会 Data Act 政策说明](https://digital-strategy.ec.europa.eu/en/policies/data-act)：可作为了解相关数据/云服务切换议题的官方入口；具体服务是否适用、时间要求与例外必须核法条及合同。
