# 16 治理制度与责任边界

> 范围与时点：2026-10-28 的防御性学习框架；面向企业采购、设计、上线和运营含模型、RAG、Agent 与外部工具的应用。不构成某家企业的责任分配、合同或法律意见；角色、司法辖区、供应商条款和监管状态须按实际项目复核。

## 责任不是把风险“外包”出去

**治理**是决定哪些用途可接受、谁有权批准、凭什么证据上线、发生异常谁能叫停以及何时复核的持续过程。**责任边界**区分决策责任（谁接受剩余风险）、实施责任（谁建控制）、运行责任（谁处理告警）和证据责任（谁证明控制生效）。模型供应商可能管理基础模型和其托管设施，却看不到企业的对象 ACL、业务审批或工具交易结果；业务方懂损失，却未必能配置网关。采购合同上的“安全承诺”不等于应用权限已验证。NIST AI RMF 的治理思路及 NIST CSF 2.0 可作为风险管理参考；下述表格是**本章自拟的组织分工示例**，不是 NIST、法规或所有合同规定的 RACI。

```text
业务提出用途/损失上限 → 数据所有者定分类与授权 → 产品/平台画数据与动作流
       ↓                           ↓                       ↓
法务/隐私核适用义务与合同 ← 采购核分包/迁移/审计条款 ← 安全核技术边界
       ↓
上线批准（版本、例外、证据） → 运营监测/响应 → 定期复核、撤权或下线
```

| 关键决定/证据 | 建议主责与参与者 | 不应被什么替代 |
|---|---|---|
| 目的、允许动作、可承受损失 | 业务负责人主责；最终操作者确认任务范围 | 用户一句“我同意”不能覆盖数据主体、其他客户或企业资产的授权 |
| 数据源、使用目的、保留与删除 | 数据所有者决定；隐私/法务核实际适用义务 | 模型提供商声称“不训练”不能证明日志、备份、评测数据未留存 |
| 身份、工具权限、生产部署 | 平台/开发实施；安全验证；系统所有者批准接入 | 模型拒答、Prompt 约束不能代替 API 对对象与操作的再次核权 |
| 供应链、服务边界、事故通知 | 采购/法务协商；供应商交付可验证证据；平台监控依赖 | 采购单或 SOC 类报告不能证明某租户配置与分包链实际生效 |
| 上线与例外接受、持续复核 | 授权的业务/风险责任人签收；安全提出反对与复核条件 | “安全团队通过”不能自动转移业务决策和剩余损失责任 |

“主责”须在项目章程中落实为姓名、替补、响应期限、授权范围；合同中供应商承担什么取决于实际服务范围、责任条款和适用法律，不能由此表反推法定义务。发生操作时同时保存**请求者—委托主体—执行账号—受影响对象—审批人—工具回执**的关联标识，以免将操作者、模型与资源拥有者混成一个主体。

## 两条不同失效链

1. **外部托管的错误归责**：企业接入外部模型后将客户工单摘要送入提示词；供应商负责模型服务，企业未核数据类别、地区、日志处理及二级服务商；事故时双方都以“对方控制”为由无法定位数据副本。缺口主要在采购边界、数据流盘点和合同可审计性，不必先假设供应商违约。
2. **内部自动化的审批空洞**：业务要求 Agent 自动关闭客服退款工单；平台用共享服务账号接工具，测试仅验证回答正确；生产中错误关闭高价值工单。业务以为安全批准了“整个 Agent”，安全实际上只审核模型接入，数据所有者也未批准写操作。这里是动作授权与上线范围不一致，而非简单的模型幻觉。

## 防止、发现、处置与剩余限制

**防止**：每个用例形成一页记录：用途和禁用用途、数据类别与流向、模型/工具/插件清单、外部处理者与分包范围、写操作阈值、保留与删除策略、审批人、可回退方案。采购阶段核服务条款、数据处理协议、审计与通知机制、变更告知、停用及导出权；上线门禁要求系统侧最小权限、隔离测试和业务回执，重大变更（模型版本、工具、用途、地区）重新审批。**发现**：版本与资产清单对照实际请求目的地、服务账号权限、分包变更、异常工具写入和审批记录；以指标监视未授权动作、缺失回执、过期例外。**处置**：优先停用高危工具和吊销令牌，保全必要且最小化的日志及回执，由业务核实影响、平台恢复、安全排查、法务判断是否需要通知并按合同联络供应商。恢复后复核补救证据和责任表。日志可能缺失、供应商可见性有限，审批无法消除模型误判；需明确风险所有者接受这些残余条件的时限。

## 安全验证清单（隔离测试环境）

- 用虚构工单和最小权限账号，模拟未经批准的“新增写工具”：上线门禁应拒绝，且变更人不能自行审批自己的例外。
- 用不同租户/不同数据所有者的样本，测试同一操作者对非授权对象的查询与写入均被资源系统拒绝；核对拒绝原因和审计关联号，不保存真实客户原文。
- 模拟供应商地域、子处理者或日志策略变更通知：谁接收、何时评估、何种情况下暂停流量？逐项留下决定和回执。
- 桌面演练供应商不可用与误关闭工单：验证停用权限、通知责任人、恢复时限及客户影响核算；不要在生产中制造事故。
