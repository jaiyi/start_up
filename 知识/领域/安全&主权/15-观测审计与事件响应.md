# 15｜观测、审计与事件响应：以最少数据重建实际行动

> 调研/复核：2026-10-28。适用：Agent 产品、平台、安全运营、隐私与应急负责人。本文讨论防御性、可测试的审计与响应设计；不表示某一项目满足法定留存或事故通报要求，地区和合同义务应另行核实。

## 三种证据及边界

**可观测性**帮助理解正在发生什么并发现异常；**审计**应能以可信关联链说明是谁、在什么版本和授权下对何对象做了什么及其结果；**事件响应**在怀疑已越界时识别范围、遏制影响、保全证据并恢复。Agent 中“模型说已经提交”不等于 Tool 调用成功，更不等于业务数据库状态已改变。日志本身也是高价值敏感资产：完整 Prompt、网页原文、文件片段、工具参数及输出可能含客户数据、密钥和商业秘密；不能以“为了安全”无限复制。

```text
用户/业务入口 ─ 身份/租户/目的 ─→ Agent 任务/会话（版本/关联 ID）
                                       │ 推理决策：建议调用
RAG/网页/外部 Tool（低可信） ───────────→ 工具网关（授权决策）
                                       │ 请求、批准/拒绝、幂等键
                                       ↓
                                 业务 API / 出站代理
                                       │ 实际回执及对象状态
                                       ↓
事件收集 → 完整性保护/敏感字段最小化 → 告警/调查（受控访问）
                                      └→ 停用工具、撤权、隔离会话、复盘
```

最小事件模式包括：发生时间与时区、租户/主体/委托链、任务与轨迹关联 ID、资产/对象的受控标识、模型与 Prompt/工具/Skill/MCP/策略版本、动作类别、批准或拒绝及规则 ID、审批票据引用、调用状态与后端业务回执、目标类别、数据分类/体量，以及数据存储和保留策略标记。精确时间、链路传播与签名/哈希保护便于对齐多系统，但标识符不是授权依据，哈希也未必能保护可猜测的短敏感值。

## 两类失效链和无害示例

1. **“成功”只有对话记录**：Agent 在测试空间答复“演示工单已创建”，日志只保存对话，没有工具请求 ID 或业务端回执；实际可能审批拒绝、网络超时或任务重试生成两个工单。审计无法回答“谁批准，哪些对象真正改变”。应把执行器决策、工具网关和后端回执按同一关联链记录，重试用幂等键区分“同一操作再次请求”和“新操作”。
2. **安全日志变成第二份泄漏源**：为了复盘，调试模式把虚构客户档案的全文、测试令牌和外部网页都写进可长期查询的日志；另一个不需要访问原文的排障角色可以看到它们。即使业务 API 的读权限正确，日志权限仍可破坏目的限制。优先留分类、摘要引用及拒绝原因，需要原文时在单独受控加密证据仓按审批短期留存。
3. **有告警却没有停用路径**：监控发现某测试 Skill 被标记撤回，生产流水线只通知人工但异步队列仍加载缓存旧版本，重复任务持续申请高风险操作。发现不等于遏制；禁用配置必须覆盖新任务、存量任务、重试、缓存和令牌。

## 分层控制：预防、发现、遏制与恢复

- **采集与关联**：由网关与业务端产生权威动作事件，而非仅采纳模型自述；明确客户端/服务器时间误差、追踪上下文跨工具传播、成功/拒绝/失败/部分成功的语义。事件收集失败时，高风险动作应明确采取“阻断/缓冲/审批”策略，不允许默默继续而完全无证据；日志过量会影响可用性和成本。
- **隐私与完整性**：按数据分类定义字段白名单、脱敏、采样例外、最小保留期、访问审批、加密与删除流程；安全证据仓与一般监控分开，限制搜索与导出并记录调查者操作。不可变存储和校验可减少篡改，却不能纠正原始事件错误；采样日志不得用于证明未发生罕见事件。具体留存期限依法律、地区、合同和事件处理要求决定。
- **检测与分级**：监测跨租户拒绝激增、未授权出站、审批对象漂移、版本不匹配、异常工具调用链及关键审计事件缺失；以业务结果与身份上下文判定误报，区分“被模型提议但已阻断”与“已执行且可能外传”。固定阈值会漏报低频问题，也可能把合法批处理误判为攻击。
- **响应路径**：预设值班角色与升级条件，先保全受控证据并确认影响对象，再停用高风险工具/Skill 或相关租户会话、阻断出站、撤销短期令牌和审批票据，核查异步队列及恢复任务；必要时通知数据/法务按适用规则评估外部通报。若需保全业务连续性，选已验证回退方案，避免仓促删除关键证据。
- **复盘与恢复**：按关联链回放决策、实际调用、对象版本、访问范围和回执，判断是否误答、误读、误执行或对外暴露；修复后用合成负例回归，分阶段恢复，并确认已撤回版本不会因缓存再次装载。完整链路也不一定能重建模型内部原因，应记录证据缺口与不确定结论。

## 非生产负例与演练证据

| 注入的模拟故障 | 必须观察到的响应 |
|---|---|
| 模型声称完成但模拟业务 API 拒绝写入 | 用户看到真实状态；审计含拒绝原因及无状态变化回执 |
| 模拟重试造成重复写入请求 | 幂等键关联单一业务结果或明确标注多个操作并升级调查 |
| 日志入口收到含合成敏感字段的材料 | 常规日志无原文，证据仓按审批访问且有可检索审计轨迹 |
| 暂时中断审计收集或切断轨迹 ID | 高风险动作依预定策略停止/缓冲并告警；缺失被标注而非误判安全 |
| 撤回测试 Skill 后触发后台任务及缓存调用 | 调用被停止，令牌/队列被处理，复核覆盖存量任务 |

演练用假身份、假工单和隔离出站端，记录发现时间、确认时间、遏制范围与证据缺失。演练通过并不能证明未来事故必被发现；供应商托管日志、跨区域存储和实际保留期需要单独核对。

## 误区、残余风险与来源

“全量存 Prompt 才能审计”和“有 tracing 就等于合规审计”都不成立；仅有摘要也可能缺少必需的因果证据，要按风险分级平衡。关联 ID 可丢失，后台调用可能绕开网关，收集代理可能停摆；设计阶段就应建立证据覆盖表和响应演练，而不是事故后补日志。

**一手资料/证据边界**：2026-10-28 对官方链接作公开只读可达性与标题抽样核验，未验证具体监管留存期限或产品默认值。[NIST SP 800-61 Rev.3](https://csrc.nist.gov/pubs/sp/800/61/r3/final) 是事件响应与 CSF 2.0 关联的官方资料；[NIST Cybersecurity Framework](https://www.nist.gov/cyberframework) 提供识别/防护/检测/响应/恢复等风险治理框架；[OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) 提供日志设计参考；[OpenTelemetry Traces 文档](https://opentelemetry.io/docs/concepts/signals/traces/) 说明分布式追踪概念而非审计保证。事件模式与告警阈值是本章的实施建议，不是标准原文强制规定。
