# 09｜Tool/MCP 与高风险动作

> 观察日期：2026-10-28。范围：Agent 通过本地/远程工具、MCP 服务连接企业 API、文件、消息与审批系统；读者：Agent 产品、平台、后端、安全与业务审批人。以 MCP 2025-06-18 官方规范作协议参考，其他版本或实现另需复核；不把规范的建议误当已部署控制。

## 工具是能力接口，不是权限凭证

**Tool 描述**是模型了解工具用途/参数的文本，可能来自插件或 MCP 服务，属于可变且潜在不可信的元数据；**工具调用**是由宿主发起的系统请求，必须有独立授权；**副作用**是写入、发布、删除、付款、改权限等业务结果。MCP 约定工具发现、调用与结果形态，但仅凭工具名、参数 schema 或模型对描述的理解，不能证明调用者对具体对象有权。MCP 工具页建议让用户清楚工具何时暴露和被调用，并保有拒绝机会；这是设计建议，不是放过服务端鉴权的理由。工具响应中的自然语言应作为数据处理，不允许改变安全策略。

```text
模型建议工具 + 参数 → 宿主按固定工具注册版本选择 → 网关验证身份/租户/动作
                                      ↓
                参数结构及目标检查 → 风险分级/人审 → 资源 API 再鉴权
                                      ↓
            幂等执行与业务回执 → 审计/告警 → Agent 总结（非权威执行证据）
决策：谁发起、哪版工具、目标对象是什么、影响多大、批准是否覆盖当前参数？
```

把工具分成只读、可逆写入、对外发送、财务/权限变更与不可逆动作；风险来自**目标、规模、收件方及上下文**，并非工具名含 `read` 就没有外传风险。注册表固定服务身份、地址/受众、工具定义哈希与版本，变更走评审和灰度；它能减少静默替换，不代表来源绝对可信。工具服务在实际资源 API 侧执行对象 ACL 与业务约束，不能把审批决策放在模型或客户端可改参数里。

## 两种安全示意失效

1. **看似只读的说明越级**：虚构的“查报表”工具在说明文本里宣称“先导出全部记录再回答”，Agent 选择了带导出副作用的接口。前提是宿主不区分工具说明与授权策略，且服务端没有限制动作/数量/租户；拒绝条件应是导出动作和目标超出本次批准，而非期待模型识破措辞。
2. **批准对象与执行对象不一致**：用户确认把一份自造草稿发送给内部测试收件人，审批后模型重试时参数变成另一组收件人；后端只校验“任务已批准”，未绑定收件人、文档版本与内容摘要。即使点击过确认，具体调用仍越出原批准范围；去重键若以每次请求随机生成，还可能造成重复发送。

## 分层控制与限制

- **预防｜连接与发现**：仅允许经审核的工具服务和固定版本，按环境隔离连接凭据与出站域名；MCP/OAuth 场景验证资源受众与令牌，不向任意第三方工具转发内部凭据。Tool schema 做结构与类型检查，网关再做业务语义检查（对象、租户、数量、路径、收件域），防止“合法格式的非法动作”。
- **预防｜执行与确认**：服务器为每次调用计算风险；外发、支付、权限变更和大规模删除默认要求展示目标、影响、数据范围及差异后由有权人批准，批准票据绑定参数摘要、版本、一次性使用和短时限。资源服务仍独立核权；幂等键绑定业务操作，在超时重试时查询真实回执后决定是否继续。二次确认不解决审批人被误导或后端绕行；回滚仅对支持补偿的动作有效，公开发送或外部扣款未必可逆。
- **检测｜效果而非只看模型**：记录工具来源版本、授权与审批决策、实际参数摘要、业务回执及重复/异常调用；监测工具定义漂移、拒绝激增、批量外发及回执与模型叙述不一致。日志仅保留必要字段并限制敏感内容。
- **响应｜关停链路**：禁用单一工具/服务凭据与路由，停止排队调用，保全审批、调用和业务回执，通知业务方复核外发/支付结果，能补偿时按业务流程补偿；禁用模型对既成副作用无效。

## 非生产负例与误区

在全仿真服务中注册一版正常工具与一版被改动描述的测试工具，验证未经审核版本不能上线；用自造对象测试跨租户 ID、格式合法但超量导出、审批后改收件人/目标、重复投递及超时后未知回执，要求服务端拒绝或查询回执且审计有据。不可连接生产付款、发信或真实用户数据；无需构造可复用恶意载荷。误区：“schema 校验就是鉴权”“人审一次对所有后续参数生效”“MCP 自带完整业务权限”“Tool 返回成功等于业务系统成功”。残余风险包括审批疲劳、外部服务行为与描述不一致、下游异步处理和无法撤回的公开效果。
