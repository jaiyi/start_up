# 11｜网络、浏览器与本地端点：把可访问范围留在系统侧

> 调研/复核：2026-10-28。适用：允许 Agent 浏览网页、调用 URL 获取工具、下载材料或访问本机/企业服务的架构、安全和运营人员。本文是防御性设计学习资料，不是针对某个系统的测试报告。下文的验证仅使用隔离测试环境与虚构数据。

## 定义、资产与边界

**服务端请求伪造（SSRF）**指一个能影响目标地址或请求目标的输入，使有更高网络可达性的服务代为访问未获批准的资源。Agent 的新增难点在于 URL 可能不由用户直接给出，而由模型从网页、邮件、检索片段或工具结果中提议；**文本建议不是网络访问授权**。要保护的资产包括内部 API、本地管理端点、云环境的元数据/身份服务、浏览器会话、下载后的文件及对外传输的数据。网络出站控制和读取权限是两项不同的判断：即使网络可达，仍需应用身份、对象和目的授权。

```text
用户任务/目的 ─→ Agent 决策（可能建议打开链接） ─→ URL 获取/浏览器代理
                     ↑ 非可信网页、RAG、工具返回   │ ① 请求策略/审批
                                                   ↓
浏览器会话/下载器 ←─ 响应内容 ←─ 受控解析器 ←─ 出站代理/解析器 ② DNS、目标 IP、路由与重定向复核
    │ Cookie/凭据属于另一边界                    │
    └─ 本地设备、企业内网、云服务 ← 网络边界 ─────┘
          外部公开站点与接收端 ← 出站策略/内容分级 ─┘
```

同源策略限制普通网页脚本跨源读取响应，CORS 是浏览器告知脚本能否读跨源响应的机制，**两者都不是服务器端 URL 获取工具的防火墙，也不等于阻止浏览器携带既有登录态发起操作**。导航到已登录站点、表单提交、某些已认证请求或自动化点击仍可能触发业务副作用；跨源读取受限与能否发起请求是两回事，具体 Cookie 属性、站点 CSRF 防护和浏览器上下文会影响结果，不能假设每种请求都必然携带凭据。浏览器导航、下载、表单、扩展和本地回环服务各有不同访问面；本机端点虽叫“本地”，不应默认只被可信调用。DNS 查询本身和出站连接均可能暴露敏感标识，不能只检查 HTTP 正文。

## 失效链与无害示例

1. **链接被当成任务指令**：一份无害的公开网页在说明中建议“为补全报告请读取内部状态页”。模型将这段非可信描述当成用户授权，URL 工具由可访问内网的宿主执行；若只在提示词里写“不要访问内网”，未在工具入口和网络层实施策略，便可能把内部内容带入回答。教学用的“内部状态页”仅为本地模拟服务，不使用真实企业地址。
2. **首跳合规但后续目标变化**：测试域名的初次解析/首个响应满足允许策略，解析结果或重定向的最终目标却不在批准范围；仅在接收原始 URL 时检查一次域名，无法代表真正连接的地址。策略不能把“首个请求获准”继承给下一跳；同时要考虑 IPv4/IPv6、代理转发和缓存造成的观察差异。
3. **浏览器会话与下载误用**：代理使用带企业登录态的浏览器打开外部页面，随后把下载的文件直接交给具有较高文件系统权限的解析器。网页不能天然读取其他站点 Cookie，不等于已下载文件、扩展、桌面客户端或已认证操作都安全；若解析器意外处理危险格式，隔离边界又被跨越。

## 分层控制及失效条件

- **入口/任务层**：定义允许的业务目的、允许的域名/服务类别与数据分类；URL 工具只接受经过结构化校验的目标和方法，不接受网页或 Tool 文本赋予的新权限。人工确认应展示规范化后的最终目标、身份及可能发送的数据；高风险动作不能只凭模型自行批准。域名白名单对被允许网站自身遭污染无能为力。
- **请求实现层**：限制协议、端口、请求方法和重定向次数；对每一跳重新做目标分类，解析得到的全部地址及实际连接目标都需符合策略，拒绝环回、链路本地、私有/保留地址和其他未批准网段；部署环境有意需要访问的内部 API 改由固定服务目录与身份网关承载，而非开放任意 URL。DNS 缓存、代理和连接复用须与校验保持一致；应用层解析器无法单独覆盖底层库或其他出站路径。
- **网络/身份层**：让抓取器使用独立身份与受限网络命名空间，默认拒绝内网/云元数据/本机服务出站；集中代理做目的地址和 DNS 策略，阻断非必要的直连及未批准协议，并将实际连接与策略决策关联审计。企业 API 在服务端重新核对调用方、租户与资源 ACL；仅有防火墙不能阻断对已放行服务的越权请求。对 DNS 出站和数据外传设置最小出站范围、体量/频率阈值，但阈值不等于内容授权。
- **浏览器/内容层**：工作专用且最小会话，敏感系统与外部浏览分离；不把 Cookie、会话令牌注入任意页面，也不让外部材料驱动带企业登录态的导航、表单提交或自动化点击。需要已认证操作时，由受控工具按目的、目标、方法和参数独立授权，目标业务 API 核对用户权限并防范跨站请求伪造，不能把 CORS 当作操作许可。下载先做大小、类型、扩展名和实际内容一致性检查，再在隔离、限资源的解析器里处理；不可信文档即使扫描通过，也仍应作为数据而非指令。恶意文件、复合格式和解析器零日无法被静态检查完全排除。
- **检测/响应**：记录任务 ID、请求者、请求工具版本、规范化目标类别、DNS/重定向决策、实际目的类别、拒绝理由和出站量，避免把 URL 中的敏感查询串原文写入日志。异常时暂停抓取能力，撤销涉事会话，排查后续工具动作与外发回执；单次“请求失败”不证明没有发生其他连接。

## 隔离环境中的可检验负例

| 负例输入/模拟条件 | 应观察的判定与证据 |
|---|---|
| 模拟网页建议读取仅测试网可见的“内部状态页” | URL 工具拒绝非批准目的地；模型可解释无法读取；审计有拒绝原因且无实际连接 |
| 首跳由受控测试域名响应，下一跳指向不被允许的模拟内部类别 | 逐跳重新判定并拒绝，不能复用首跳授权；日志关联首跳和终止点 |
| 测试 DNS 回答在校验与连接间改变地址类别，或 IPv6 结果与 IPv4 不同 | 实际连接前的校验/出站策略均阻断，证明没有可绕过的解析路径 |
| 浏览器持有虚构企业测试账号会话，外部材料诱导导航、提交模拟敏感系统表单或上传测试标记 | 不得以跨源读取受限视为拒绝动作；未经授权的已认证操作由浏览器策略或目标 API 拒绝，审计区分会话是否携带、请求是否发起及后端是否写入 |
| 浏览器拥有测试账号会话，外部材料请求下载伪装类型文件 | 文件进入隔离解析流程而非直接进入主宿主 |

这些测试只运行在无生产凭据、无真实内网访问的模拟网络，不构成实测结果。还需额外检查云平台网络与代理设置、SDK 是否另有未纳管的直连路径。

## 误区、剩余风险与来源

“只允许 HTTPS”“浏览器有同源策略”“模型已拒绝”“先验域名在白名单”都不证明最终连接、文件处理和外发目的合规。允许域名遭接管、共享代理配置漂移、暂态网络变化和合法业务外发都可能造成剩余风险；按具体部署核验 IPv6、DNS、重定向、授权及日志，不把这里的设计建议称为已生效控制。

**一手资料与证据边界**（2026-10-28 公开入口只读可达性核验；部分页面作文字抽样，未逐条核对所有细则）：[OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) 提供 SSRF 设计参考；[MDN Same-origin policy](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy) 与 [MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) 用于区分浏览器跨源读取机制；[OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) 用于下载文件后处理的防护参考。分类及具体拒绝策略是本文实施建议，须按业务允许范围复核；不声称这些来源保证任何 Agent 安全。
