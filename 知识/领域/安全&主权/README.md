# Agent 智能应用安全与 AI 主权：系统学习目录

> 建立日期：2026-10-28。状态：**01–20 章研究正文已建立；属学习材料，不构成具体系统的安全验证或法律合规意见**。
> 适用范围：面向企业内使用大模型、RAG、Agent、MCP/工具、Skill、插件及多 Agent 协作的应用；关注设计、建设、运营和采购阶段。读者包括产品、架构、开发、安全、数据治理、法务与业务负责人。

## 一、核心问题与学习方法

传统应用的输入通常被当作数据，操作由预先编写的程序路径决定；Agent 系统还会把自然语言、检索材料、工具返回值和外部内容放进决策上下文，由模型选择下一步动作。因此要同时问：**它看到了什么、把谁的话当指令、以谁的身份行动、能对哪些系统产生什么后果、如何证明结果可信**。模型不确定性与传统系统漏洞相互叠加，但并非每个风险都是“模型专属”。

建议采用统一分析卡片：**资产与业务后果 → 数据流与信任边界 → 威胁主体和前提 → 攻击/故障机理 → 触发条件 → 预防措施 → 检测/响应 → 残余风险与验证证据**。每一章分别标注通用安全问题、Agent 新增风险、法律/合同约束及工程待验证项；把“有产品能力”“有权限配置”“已经生效/验证”分开。

## 二、总体心智模型

```text
人/业务系统 → 身份与授权 → Agent 宿主/任务状态 → 模型与上下文
                     │                   ↑       ↑
                     │                   │       └─ Prompt、历史、RAG/网页/文件、工具结果
                     └─ 工具网关/MCP → 企业 API/数据库/工单/文件/网络

资产发布与供应链：代码/Skill/Prompt/数据集/模型/插件 → 审核与版本 → 装载/调用
跨层控制：分类分级、权限、网络、可观测性、隔离、审计、应急与合规
```

**边界原则**：外部文本即使看起来像“系统消息”也属于不可信数据；检索到知识不意味着可读取原件或可执行动作；模型提出行动不等于系统授权，Tool 返回成功不等于业务结果成立。所有读写与对外发送动作在真实系统侧重新核权、限权并保留可追溯回执。

## 四、建议学习顺序与交付物

1. **先画图**（01–03）：选一个 Agent 场景，明确资产、身份、信任边界和三条失败路径。
2. **再追踪数据和动作**（04–12）：对每类输入/输出标明来源、分类、授权、目的、去向、版本和实际回执。
3. **补足治理闭环**（13–16）：把审核、评测、运行观测和事故处置变成可执行的验证用例。
4. **最后比较主权方案**（17–20）：用可验证的控制权矩阵而非“国产/自建/私有化”标签做选型。

各章包含架构/数据流示意、至少两条合成失效链、预防/检测/响应措施及其局限、非生产负例测试、来源与未验证问题。学习时应把案例当成验证设计，不要把期望结果当成已完成的实测结果。

## 五、入门权威参考与证据边界

以下是一手资料研究入口；各章已区分官方资料、工程解释和待验证条件，但不能据此推断所有标准条款都已逐条核实。框架版本、地区监管和合同义务须按部署时点复查。

- [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) 与 [Generative AI Profile](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence)：AI 风险治理与生成式 AI 特有关注点。
- [OWASP GenAI Security](https://genai.owasp.org/) 及 [LLM Top 10](https://genai.owasp.org/llm-top-10/)：LLM 应用风险归类与防护讨论。
- [MITRE ATLAS](https://atlas.mitre.org/)：AI 系统对抗战术与技术知识库。
- [NIST SP 800-207 Zero Trust Architecture](https://csrc.nist.gov/pubs/sp/800/207/final)：身份与资源访问的零信任思路；不可机械套用为 Agent 自动授权。
- [NIST Cybersecurity Framework](https://www.nist.gov/cyberframework) 与 [SSDF（SP 800-218）](https://csrc.nist.gov/pubs/sp/800/218/final)：组织网络安全治理及安全开发实践。
- [欧盟 AI 法规政策入口](https://digital-strategy.ec.europa.eu/en/policies/european-approach-artificial-intelligence)：只作为了解不同司法辖区义务的起点；不等于本项目适用法律判断。

**术语提示**：“主权 AI”在不同政策、厂商和企业场景下并无唯一的工程定义；这里采用“关键 AI 能力及其数据、算力、模型、运行和治理的实际控制能力”的多维分析框架，**不将其简化为安全、国产化或私有化的同义词**。涉及具体政策、IP 条款、合规地域和供应商承诺时，须另行核对时点与法律文本。
