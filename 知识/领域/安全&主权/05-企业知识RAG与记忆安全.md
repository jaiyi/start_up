# 05 企业知识、RAG 与记忆安全

> 编写日期：2026-10-28；范围：企业知识入库、向量/全文检索、摘要引用和 Agent 长短期记忆。读者：知识管理员、开发、平台、安全及业务数据所有者。本篇用虚构案例说明防御方法，不证明现有产品已实现隔离；官方资料入口已作可达性检查及部分正文抽样，具体分类版本和技术条款仍须复核。

## 检索命中不等于可读、可信、现行

**RAG**（检索增强生成）通常把文档切块、建索引，将候选片段加入模型上下文。**知识投毒**是来源、内容、元数据或索引被错误/恶意材料污染；**来源伪造**是引用显示的作者、路径或批准状态与真实文档不一致；**记忆污染**是未经验证的总结或工具输出被保存，跨任务继续影响决策。向量相似度是相关性线索，不是用户授权、文档真实性或时效性证明。长期记忆需要明确所有者、作用域、写入来源、过期/撤销与人审政策，不能与临时会话摘要混为一谈。

```text
数据所有者 → 原件（ACL/版本/有效期） → 解析/OCR/切块 → 索引/元数据
                    │                                      │
                    │对象核权                        候选召回/重排
                    ↓                                      ↓
              原件验证服务 ←主体/租户/目的────── 宿主 → 模型上下文 → 引用回答
                    ↑                                       │
             撤权/删除事件                        提议写入记忆 → 写入网关
                    │                                      ↓
                    └───────── 更新/失效队列 ─── 作用域/TTL/溯源/审批
边界：上传者到知识库；索引到原件；片段到权威事实；本轮总结到长期记忆。
```

**权限分层**：原件服务按对象、版本、租户、主体控制读；索引服务不应只靠“分库/分集合”假设隔离，也要在查询及候选返回时做请求者范围过滤，并在引用/打开原件时重新核权。搜索服务若用宽权限账号建索引，不能把该账号的可读集合直接赋予终端用户。派生物（OCR、片段、向量、缓存、摘要）应保留父文档标识和有效期；撤销后旧索引、检索缓存和已经生成的答案仍可能短时存在。回答引用的文档 ID、版本、定位范围和可读性要一致；引用失真可能来自截断、错配、改版或摘要误读，而非蓄意攻击。

## 两个不同的失效链（假数据）

1. **跨租户召回与引用遮蔽**：甲租户员工问报销规则；共享向量索引按相似度返回乙租户的另一份报销政策，UI 只显示模糊的“公司知识库”引用。模型给出看似合理、甚至完全符合乙方政策的答案，却同时暴露了乙方内容并误导甲方执行。若模型不提供引用、只改写结论，风险仍在。防护要从每个候选的父文档/租户 ACL 开始，在原件读取、生成引用和缓存命中时再次校验，而不是仅在界面隐藏标题。
2. **旧索引叠加记忆写入**：企业更新虚构的出差补贴规则，旧版仍在向量索引里；旧片段附带“这是正式的最新通知”的文字。Agent 错把其归为高可信，并把“每次都按旧额度回答”记入跨会话共享记忆。之后即使重建索引，旧记忆仍反复注入。要分开处理版本新旧与提示注入：以原件系统的生效版本判断政策，限制低信任检索结果写入长期记忆，并使记忆可溯源、可撤销和可过期。

## 从入库到遗忘的分层控制

- **入库预防**：核验上传主体和知识所有者、源站或签名（若有）、文件版本、密级、租户、适用业务范围和有效期；为低可信外部材料另设集合/标签和审批队列；解析和切块后保持父文档 ID、可校验出处及安全分类。签名可证明某个发布者与内容关联，不能证明发布者没犯错。对高度关键政策依业务主管系统确认生效状态，不能从文档自称“正式版”推断。
- **检索/使用预防**：在服务器端把授权过滤施加到索引候选和原件读取，处理跨租户缓存键、被删除/撤权文档及负权限变更；生成回答时标示来源版本、冲突和“未找到有效证据”的状态，高风险事项只给草稿供业务复核。任何片段中的动作建议都不得绕过工具端的独立鉴权；模型文本过滤只是辅助手段，不保证抵挡间接注入。
- **记忆预防**：按用户/租户/任务划定记忆范围，长期保存要经过独立写入策略；区分用户直接设定、模型归纳、检索推断和系统事实，不准无权工具返回自行提升优先级；设置 TTL、查询权、纠错/删除流程和回填版本。隔离会话能降低扩散，但也可能导致必要上下文丢失，需要业务取舍。
- **检测和响应**：周期性比对索引与原件 ACL/版本/删除清单，抽样检查引用定位和答案一致性，告警跨租户命中、被撤权资料继续出现、无批准的共享记忆写入。发现问题时隔离来源、暂停受影响索引/记忆版本、重建或失效相关缓存，以查询日志和业务回执评估影响范围。日志的可观测性受隐私最小化限制；已传播的回答或用户截图不可因重建索引自动收回。

## 非生产测试和可观测证据

在隔离的甲乙两租户放置语义几乎相同、但测试金额不同的假报销规则，验证甲方检索、回答、引用和打开原件绝无乙方内容；在甲方删除权限后立即及缓存有效期内重试。将旧版/新版并存并注入模仿“最新通知”的虚构文本，预期系统按生效时间或报告冲突，不写入共享记忆；尝试把搜索工具摘要标为“用户本人授权”，预期记忆网关拒绝。批量重建索引时检验删除/撤权事件丢失、索引滞后和查询并发；核对检索候选 ID、ACL 决策、文档版本、引用定位、记忆来源及最终业务状态。测试要用合成资料，不能因验证而复制真实跨租户文档。

**误区与余险**：检索精度高不代表权限隔离；索引独立不等于缓存独立；有引用不代表引文与主张吻合；只删除原件不等于下游派生物和记忆已被删除；“人审过”也未必查过生效日期。残余风险包括来源管理员账号被滥用、原件 ACL 同步延迟、模型组合多个可读片段推断出不应披露的事实、业务资料互相矛盾和历史回答已经被复制。应为高风险领域定义无证据时拒绝执行/转人工的明确条件，而非宣称 RAG 能消除幻觉。
