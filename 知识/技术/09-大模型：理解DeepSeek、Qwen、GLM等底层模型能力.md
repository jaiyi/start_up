# 08 · 大模型技术体系

## 1. 这个模块解决什么问题

知识复利工程师不需要从零训练大模型，但需要理解大模型能力边界，避免把业务问题误判为模型问题。

这个模块回答：

```text
大模型擅长什么，不擅长什么？
什么时候靠 Prompt / RAG / 知识工程就够了？
什么时候才需要 SFT、RLHF 或私有化模型？
```

---

## 2. 它在知识复利系统中的位置

```text
大模型能力
  ↓
Prompt / RAG / Agent / Tool Use
  ↓
知识复利系统
```

模型是底层能力，不是完整解决方案。

## 4. 典型技术路线

| 路线 | 适合场景 | 风险 |
|---|---|---|
| 直接调用通用模型 API | 早期验证、通用任务 | 数据安全、成本、依赖外部服务 |
| Prompt / 任务协议 | 任务边界清晰、知识不复杂 | 稳定性依赖设计和评测 |
| RAG | 需要接入组织知识 | 知识质量和检索质量决定上限 |
| SFT | 固定风格、格式、领域表达适配 | 数据质量要求高，容易被滥用 |
| RLHF / DPO | 偏好对齐、复杂行为优化 | 企业内部落地门槛高 |
| 私有化模型 | 数据敏感、成本可控、离线要求 | 运维和模型能力成本 |

## 5. 推荐调研的开源框架 / 工具

| 类型 | 候选项目 | 背景/特点 | 后续验证点 |
|---|---|---|---|
| 模型生态 | Transformers | Hugging Face 生态核心 | 模型加载、微调、推理基础 |
| 国内模型生态 | ModelScope | 阿里 / 魔搭生态 | 中文模型和数据集支持 |
| 训练框架 | LLaMA-Factory | 国内常用微调框架 | SFT / LoRA 实践成本 |
| 训练框架 | Axolotl | 社区常用训练配置框架 | 学习成本、硬件要求 |
| 开源模型 | Qwen | 阿里通义千问生态 | 中文、工具调用、多模态能力 |
| 开源模型 | DeepSeek | 推理和代码能力强，生态热度高 | 私有化和 API 使用边界 |
| 开源模型 | GLM / Yi / Llama / Mistral | 主流模型生态 | 中文能力、授权、部署成本 |
| 模型网关 | LiteLLM / OneAPI | 统一模型调用入口 | 成本、权限、审计 |
| 本地运行 | Ollama / LM Studio / llama.cpp | 本地模型验证 | 性能、模型选择、生产适配 |

## 6. 适合个人 / 小团队 / 企业的落地方式

| 场景 | 推荐起点 |
|---|---|
| 个人验证 | API + Ollama 本地模型对比 |
| 家庭知识库 | 外部 API 优先，本地模型用于隐私或离线验证 |
| 小团队 | 模型网关 + 多模型切换 + 成本统计 |
| 企业 | 统一模型服务、权限、审计、私有化评估 |

---

## 7. 与其他模块的关系

- Prompt 模块利用模型指令跟随能力；
- RAG 模块弥补模型知识不完整；
- Agent 模块利用工具调用能力；
- 评测模块判断模型输出质量；
- 部署治理模块决定模型调用和私有化策略。
