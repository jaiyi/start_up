# 02 · 数据清洗：训练之前先问“能不能用、该不该用”

> 一句话：数据清洗不是把数据都变得“好看”，而是按来源、授权、质量和用途筛选训练材料，并记录被保留和剔除的理由。

## 简化流水线

```text
来源登记/许可和隐私核验 → 解析与编码 → 质量过滤 → 去重/近重复
→ 敏感内容处理与政策过滤 → 混合采样 → 训练集/验证集隔离 → 审计版本
```

例如同一篇教程被十个网站转载，若十份全部保留，模型可能过度记忆这篇文本；去重能降低偏置和评测污染。但医学、工业或小语种的珍稀内容若被过度过滤，也可能损失有价值的覆盖。没有一种“通用清洗阈值”适合所有任务。

## 四种常见问题

| 问题 | 一个例子 | 处理与代价 |
|---|---|---|
| 重复与模板噪声 | 转载文章重复十次 | 规范化、精确/近重复去重；注意误删 |
| 隐私与授权 | 网页含个人联系方式或受限文档 | 先评估采集合法性与用途，需剔除/脱敏时不把原文写入日志；脱敏也不自动产生使用许可 |
| 数据污染 | 测试题及答案混入训练集 | 固定测试集来源、时间切分与相似度排查；有重合则重新设计评测 |
| 低质量或有害内容 | 截断乱码、机器刷屏、错误标注 | 保留质量规则版本，抽样复核误杀和漏检 |

**训练语料、SFT 演示数据、偏好对和 Agent 轨迹**需要不同清洗口径；工具执行轨迹还可能包含凭据和副作用，不应直接作为训练语料。合规约束不能靠模型训练“自己学会”。

## 自测

把两个来源完全相同的教程合并之前，应先核对什么？**来源与许可、去重策略、目标任务覆盖、测试集是否出现相同文本。**

## 一手资料

- [Raffel 等：Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer（C4）](https://arxiv.org/abs/1910.10683)——从大规模网页文本构建与过滤训练语料的经典例子，方法本身也有争议与局限。
- [Penedo 等：The FineWeb Datasets](https://arxiv.org/abs/2406.17557)——网页数据过滤与去重实验；结果依赖其数据与评测条件。
- [Hugging Face 数据集文档](https://huggingface.co/docs/datasets/process)——可操作的数据处理 API；API 会随版本变化。
