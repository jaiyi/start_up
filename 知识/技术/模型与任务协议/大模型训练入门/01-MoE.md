# 01 · MoE：为何不是每个 token 都调用全部专家？

> 一句话：Mixture of Experts（专家混合）用路由器为每个 token 选取少数专家网络计算；它是**模型结构**，不是 SFT/RLHF 之后的独立训练步骤。

## 直观例子

假设一层有 8 个“专家”前馈网络，路由器给每个 token 选择其中 2 个：输入“代码”和“表格”的 token 可能走不同组合。这里的“专家”是网络模块，不保证每个专家拥有可解释的领域职责，也不意味着模型里有八个可独立对话的 Agent。

```text
token 表示 → router 打分 → top-k 专家参与计算 → 汇合输出
```

注意力层和专家层的安排因模型而异。一个模型的**总参数量**可能很大，但每个 token 的**激活参数量**较小；显存仍可能需要保存所有专家，通信和负载均衡也有成本，不能由激活参数少就推断部署便宜。

## 训练时需解决什么？

路由器可能总选少数专家，导致其他专家训练不足；容量限制、负载均衡损失和分布式通信都有取舍。训练、推理时的 batch、专家放置、路由策略会改变吞吐/延迟表现。

## 与知识工程的边界

MoE 解决模型容量与计算分配问题，不决定企业知识是否经过审核、被检索或授权访问。内部资料过期，改用 MoE 不会自动更新知识；先检查 RAG 的知识版本和引用。

## 自测

- “总参数 100、每 token 激活 20”是否等于只需存 20 参数？**否**，还要考虑其余专家权重存储和运行条件。
- 路由器选择一个专家的输出，是否等于 Agent 选择业务 Tool？**否**，前者是模型内部计算，后者是真实外部动作。
