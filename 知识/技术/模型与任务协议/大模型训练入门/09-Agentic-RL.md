# 09 · Agentic RL：多步交互中的学习

> 一句话：Agentic RL 把模型放入可交互的任务环境，通过多步观察、行动与结果奖励改善策略；这个词覆盖多个研究路线，不是一个统一的优化算法或产品功能。

## 从单步问答到任务轨迹

单步任务：“给这道题作答”。多步任务：“查看一组脱敏虚构工单 → 调用查询工具 → 发现缺少依据 → 请人工补充 → 输出带引用的摘要”。轨迹可表示为：

```text
状态/观察 s0 → 动作 a0 → 工具返回 s1 → 动作 a1 → ... → 终止结果与奖励
```

奖励可以根据最终结果、每步是否合法、工具成本或人工确认设计；只有最终分数可能难以知道哪一步造成了失败（信用分配问题）。训练时应在可重置的合成环境/沙箱中探索，而不是在真实业务系统试错。

## 难点与评估

| 难点 | 为什么重要 | 最小验证 |
|---|---|---|
| 奖励作弊 | 模型可能迎合自动评分而不完成真实任务 | 隐藏测试、人工复核与反例 |
| 环境不可复现 | API 数据变化或副作用让轨迹不一致 | 固定 fixture、隔离状态、可重放调用 |
| 权限与安全 | 探索可能触及写工具/敏感材料 | 只读或无真实副作用工具、最小权限、人审 |
| 长轨迹成本 | 多次采样与工具调用昂贵 | 限时、token/工具预算、与强基线比较 |

Agentic RL 不等同于给 Agent 装“长期记忆”；后者可不更新模型权重，只在运行时持久化经审查的经验。一次轨迹“成功”也不等于知识或 Skill 自动正式发布。

## 自测

为什么不能直接用生产 ERP 的成功回执作为探索训练奖励？**真实写入有不可逆副作用，还可能泄漏业务数据；应先用隔离模拟环境与独立验收。**

## 一手资料

- [Yao 等：ReAct](https://arxiv.org/abs/2210.03629)——多步推理与行动的基本形式（不是 RL 算法本身）。
- [Zhou 等：WebArena](https://arxiv.org/abs/2307.13854)——可复现 Web Agent 任务环境的基准示例。
- [Shao 等：DeepSeekMath](https://arxiv.org/abs/2402.03300)——可验证反馈驱动的策略训练；数学单步奖励并不等于完整的 Agentic RL。
