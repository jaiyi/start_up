# 10｜工作流、多 Agent 与长任务

> 观察日期：2026-10-28。范围：带子代理、队列、定时器、人工批准、恢复、重试与长期记忆的企业 Agent 工作流；读者：编排平台、业务后端、安全、SRE 和审批人。本文为防御性架构分析，不代表任何项目已实施这些控制。

## 从单次回答转为跨时间授权

**工作流实例**是有状态的任务执行链；**子代理**是分工执行单元，不因“是主代理调用的”就获得全局权限；**检查点**保存恢复依据，但可能包括过期授权和已污染上下文；**幂等**旨在让重复请求不重复产生副作用，并不等于业务上绝对可回滚。任务从“请求时”走向“执行时、重试时、恢复时”，用户的角色、对象 ACL、原始目的和数据许可都可能变化。自然语言“停止”只有转换成有状态、可传播的系统事件才可信；模型承诺停止不能阻止已有队列消息或已发起的下游调用。

```text
用户目的/授权 → 主任务（租户/范围/期限/预算） → 子任务 A、B（权限交集）
                      │                           │
                      ├→ 持久队列/检查点 ← 重试/恢复 ┤
                      │             ↓             │
                      └→ 审批/停止状态 → 每次工具执行前核权 → 回执/补偿
判定点：该实例是否仍有效？子任务是否仍属原目的？批准涵盖此参数/版本吗？
```

编排器应为实例保存不可随意扩大的**任务契约**：发起者、租户、明确目标/用途、允许工具和对象范围、截止时间、最大调用次数/成本、审批摘要、取消版本号。子任务只能收窄这些上限；如需扩大，必须由拥有该范围权限的人发起新批准。长记忆/检索材料属低信任输入，不能改写契约；其读写也须绑定来源主体、租户、任务目的、允许复用范围和有效期。取消、委托到期或用户撤权后，旧任务不可继续写记忆，恢复流程不得仅凭旧检查点读取受限记忆；是否允许新任务继续读取既有内容，应重新按当前主体、目的、保留政策和数据所有者授权判断，必要时隔离或清除派生记忆。依靠模型自行“记住规则”无法跨进程、跨模型或重启可靠执行；契约应在编排器/网关和资源服务端验证。

## 两种安全示意失效

1. **重试造成重复副作用**：用虚构订单跑审批工作流，调用返回超时后队列自动重投；第一次实际已成功，第二次再次执行。若系统以网络超时等同失败、每次创建新幂等键，用户确认的一次动作可能变成两次。权威事实是下游业务回执/状态，而不是 Agent 自述“刚才失败”。
2. **取消后子代理续跑**：用户取消虚构的资料整理任务，主流程显示停止，但某子代理持有长期服务凭据和稍后触发的定时计划，继续向旧地址发送摘要。失败链在取消状态未传播至队列/定时器、子任务未每次重新核对授权及目的，且已发出的消息不可召回；仅撤掉前端入口无效。

## 分层防护、检测与响应

- **预防｜创建和派生**：任务契约服务端签发/保存；子代理凭证绑定任务、租户、工具、对象和短期限，权限取父任务与子代理自身能力的交集；限制递归深度、并发、总预算及外部收件人。人工接管时明确是否停止自动执行，交接须重新核验操作者身份与批准范围。预算仅限制规模，不能保证单次高危动作安全。
- **预防｜执行与恢复**：队列消费、定时唤醒、恢复检查点及每次副作用前，检查当前用户/对象权限、任务截止/取消标志、审批绑定的参数版本和剩余预算；持久状态不存长期明文密钥。使用稳定的业务幂等键和下游回执查询，未知状态先核对后重试；对不支持幂等/补偿的系统采用串行审批或人工仲裁，而非宣称可精确一次执行。检查点中的不可信文本不许变成系统指令。
- **检测｜跨步骤可见性**：记录主子任务链、触发源、租户、契约/策略版本、身份链、审批 ID、每次核权结果、下游回执和取消传播状态；监测停止后调用、无限重试、范围扩大、长时间沉睡后突然写入。只记最后一条模型回复不足以重建责任链；审计应最小化保留原文。
- **响应｜停止与收敛**：取消标志与工作负载凭据撤销双轨并行；冻结队列、禁用定时触发、阻断网关并确认在途调用，核查既成写入/外发，按下游能力补偿、通知与恢复。不能保证取消瞬时停止正在运行的外部交易；需定义终止确认超时和人工接管渠道。

## 非生产负例与误区

在隔离环境用自造任务验证：子代理申请超出父任务的工具被拒；用户撤权后排队任务和检查点恢复失败，旧任务不能写记忆，新任务在不同目的或主体下不能复用受限记忆；取消时同时检查队列、计时器、在途调用及记忆读写；模拟第一次调用已成功但响应丢失，重试查询回执不重复执行；审批后变更参数或超期唤醒须重新审批。检查任务链日志是否足以区分用户发起、代理派生和系统定时触发；不连接真实支付或消息接收方。误区：“用户曾批准就永远有效”“重试一次只是再问模型”“前端显示已停即已停”“子代理可信，因为来自可信主代理”。残余风险包括跨系统撤权时差、下游非幂等副作用、依赖项宕机和内存/检查点污染；停用与恢复需要实测，不应凭流程图宣称安全。
