# 09 · 私有化部署与轻量化治理

## 1. 这个模块解决什么问题

知识复利系统一旦承载核心组织记忆，就必须考虑部署、安全、权限、审计、备份、成本和迁移。

这个模块回答：

```text
什么时候需要私有化部署？
如何避免核心知识资产被平台锁死？
普通团队需要理解哪些模型轻量化和治理能力？
```

---

## 2. 它在知识复利系统中的位置

```text
模型 / 知识库 / Agent / 数据
  ↓
部署与治理底座
  ↓
权限、审计、备份、成本、迁移
  ↓
长期可信运行
```

工程化治理决定知识复利系统能否长期运行。

## 4. 典型技术路线

| 路线 | 适合场景 | 风险 |
|---|---|---|
| 外部 API | 个人 / 小团队早期验证 | 数据合规、成本和服务依赖 |
| API + 模型网关 | 多模型切换、统一计费和审计 | 网关治理复杂度 |
| 本地轻量模型 | 隐私、离线、低成本验证 | 能力可能不足 |
| 私有化大模型 | 高敏数据、企业级合规 | GPU、运维、模型更新成本高 |
| Docker Compose | 单机部署知识库 / RAG / Agent | 扩展性有限 |
| Kubernetes | 企业级弹性和治理 | 学习和运维成本高 |

## 5. 推荐调研的开源框架 / 工具

| 类型 | 候选项目 | 背景/特点 | 后续验证点 |
|---|---|---|---|
| 推理引擎 | vLLM | 高性能 LLM 推理框架，社区活跃 | GPU 要求、部署复杂度 |
| 推理引擎 | SGLang | 面向高性能推理和 agent 场景 | 成熟度、生态 |
| 本地推理 | llama.cpp | CPU / 边缘设备常用 | 中文模型效果、性能 |
| 本地模型 | Ollama | 易用，本地验证友好 | 生产化能力 |
| 推理优化 | TensorRT-LLM | NVIDIA 生态，高性能 | 硬件依赖和复杂度 |
| 模型网关 | LiteLLM | 统一多模型 API | 权限、日志、成本统计 |
| 模型网关 | OneAPI / Portkey | 多模型转发和治理 | 开源程度、部署方式 |
| 可观测性 | Langfuse / Helicone / OpenTelemetry | 调用日志、trace、成本观测 | 数据留存和私有化 |
| 基础设施 | Docker / Docker Compose / Kubernetes | 部署知识库和模型服务 | 运维成本 |
| 存储 | Postgres / MinIO | 元数据、对象存储 | 备份、迁移、权限 |
| 身份权限 | Keycloak / Casdoor / Authentik | 统一身份认证 | 集成复杂度 |

## 6. 适合个人 / 小团队 / 企业的落地方式

| 场景 | 推荐起点 |
|---|---|
| 个人验证 | 外部 API + Docker Compose + 本地备份 |
| 家庭知识库 | WeKnora / Dify 单机部署 + 数据定期导出 |
| 小团队 | 模型网关 + 权限隔离 + 调用日志 + 知识库备份 |
| 企业 | 统一身份、权限、审计、成本治理、备份迁移、私有化评估 |

---

## 7. 与其他模块的关系

- 为 RAG、Agent、知识库提供长期运行环境；
- 为知识工程提供数据可控和备份机制；
- 为评测提供 trace 和日志；
- 为企业场景提供权限、审计和合规边界。
