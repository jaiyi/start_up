# 06 · WeKnora / LightRAG / Reme 对比

## 1. 这个模块解决什么问题

这个模块用于对比知识库、RAG、知识图谱和 Agent 知识底座相关工具，判断它们是否适合承载长期知识复利。

重点不是“哪个功能最多”，而是：

```text
哪个系统能让知识资产可控、可导出、可评测、可治理，并能逐步连接 Agent 和真实业务流程？
```

---

## 2. 它在知识复利系统中的位置

```text
知识资产
  ↓
知识库 / RAG / 图谱系统
  ↓
问答、检索、关系浏览、Agent 调用
  ↓
反馈、治理、迁移
```

这些工具是知识复利系统的产品化载体。

## 4. 对比维度

| 维度 | 要看什么 |
|---|---|
| 定位 | 是知识库、RAG 框架、图谱系统，还是 AI 应用平台？ |
| 数据控制 | 原始文档、chunk、向量、图谱、问答记录是否可导出？ |
| 图谱能力 | 是否支持实体关系抽取、图谱浏览、GraphRAG？ |
| RAG 能力 | 检索、rerank、引用、文档解析是否成熟？ |
| Agent 能力 | 是否能被 Agent 调用，是否支持 workflow？ |
| 权限 | 是否支持多知识库、团队隔离、角色权限？ |
| 评测反馈 | 是否支持反馈、评测、日志追踪？ |
| 部署成本 | 单机是否能跑，小团队能否维护？ |
| 生态活跃度 | 是否高星、持续更新、有社区或大厂背景？ |
| 长期风险 | 是否锁定数据，是否难迁移，是否过度复杂？ |

## 5. 推荐调研的开源框架 / 工具

| 类型 | 候选项目 | 背景/特点 | 后续验证点 |
|---|---|---|---|
| 知识底座 | WeKnora | 腾讯开源，已做个人部署验证，支持知识库和图谱能力 | 数据导出、Agent 接入、图谱质量、权限 |
| 图谱 RAG | LightRAG | 轻量 GraphRAG 思路，适合研究图谱增强检索 | 工程成熟度、中文效果 |
| 个人记忆 / 知识 | Reme | 关注个人记忆和知识组织 | 项目活跃度、可扩展性 |
| 企业 RAG | RAGFlow | 文档解析和 RAG 产品化能力较强 | 私有化、权限、反馈闭环 |
| AI 应用平台 | Dify | 社区活跃，知识库 + Workflow 能力 | 数据控制、复杂场景边界 |
| 知识库平台 | FastGPT / MaxKB | 国内团队常用，部署相对直接 | 长期维护和治理能力 |
| GraphRAG | Microsoft GraphRAG | 微软背景，图谱增强检索代表 | 成本、复杂度、小团队适配 |
| RAG 框架 | LlamaIndex / LangChain | 生态丰富，适合自定义链路 | 工程复杂度 |

## 6. 适合个人 / 小团队 / 企业的落地方式

| 场景 | 推荐起点 |
|---|---|
| 个人验证 | WeKnora / Dify / RAGFlow 中选一个快速跑通 |
| 家庭知识库 | WeKnora + 结构化 Markdown + 简单图谱验证 |
| 小团队组织记忆 | RAGFlow / Dify / WeKnora + 权限 + 反馈机制 |
| 企业 | 自建 RAG 链路或平台化方案 + 数据导出 + 权限审计 + 评测闭环 |

---

## 7. 与其他模块的关系

- 承接知识工程产出的知识资产；
- 内部使用 RAG 链路；
- 可能包含知识图谱能力；
- 可作为 Agent 的知识底座；
- 需要评测和治理模块判断是否适合长期使用。

---

## 8. 后续要验证的问题

- WeKnora 的数据是否能完整导出？
- WeKnora 图谱能力和 LightRAG / GraphRAG 思路有何差异？
- RAGFlow 是否更适合作为小团队文档知识库？
- Dify 的知识库是否适合承载核心组织记忆，还是更适合作为应用层？
