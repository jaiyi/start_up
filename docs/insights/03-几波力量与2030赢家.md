# 03 · 几波力量与 2030 赢家

> 讨论稿 / 会更新 · 最近更新 2026-09-14
>
> **一句话结论**：2030 不会有单一赢家，是个**分层的 stack**——模型公司+云厂商占横向底座，
> 一批"垂直 AI-native 运营商"靠领域飞轮占垂直，设备商占单机闭环。
> 唯一确定的输家是**没有产品沉淀的通用 FDE 咨询公司**。胜负手只有一个：**谁攒住了反馈闭环。**

---

## 背景：现在下场抢这块蛋糕的几波力量

2026，模型能力已经非常强、成本持续下降，token 经济作为国家基建、政府文件密集出台（国务院《关于深入实施"人工智能+"行动的意见》国发〔2025〕11号、中央网信办+发改委《政务领域人工智能大模型部署应用指引》2025-10）。最缺的还是**大模型如何真正赋能广大制造业**，而不是 AI 圈的小范围狂欢（承接 01 篇"瓶颈不在模型、在落地"）。

盘子本身在快速做大：科智咨询估中国企业级 AI Agent 市场 2025 约 **212 亿元**，2026 约 **449 亿元**，2029 有望突破 **3,320 亿元**；沙丘智库测企业 Agent 采用率从 2024 年底 **17.3%** 升到 2026 年中 **40.3%**。钱和玩家都在涌进来。围绕这块蛋糕，至少四波力量在下场，各有各的结构性禀赋和天花板。

下面用**统一框架**逐一拆：`优势 / 能赢什么 / 天花板 / 判断`。

---

## 第一波：传统设备制造商（发那科 × 谷歌）

**案例（已核实）**：2026-05-19，FANUC America 发布"FANUC Accelerates Physical AI Through Collaboration with Google"，与谷歌合作把 AI agent 接进工业机器人控制，主打 "Physical AI / 自适应机器人"；后续报道（2026-09）提到双方联合开发 AI 焊接机器人系统。
> 一处需要诚实标注的边界：公开信源确认了"谷歌 AI agent 操作发那科机器人"这个方向，但**"拿到 CAD 图纸直接产出焊接参数和运动轨迹"这一具体能力，目前没有一手来源坐实（待核实）**。它是这条路线合理的演进方向，但别当成已发生的事实写进面试稿。作为参照，发那科自身早有 iRVision + 激光视觉焊缝跟踪（line/seam tracking），"用视觉实时纠偏焊接轨迹"的技术底子是成立的。

- **优势**：
  - 硬件本身强壁垒、寡头属性（发那科在数控系统和工业机器人是全球头部）。
  - **独占设备遥测数据**——这是别人拿不到的反馈闭环燃料。发那科的 **FIELD 系统（FANUC Intelligent Edge Link and Drive）** 就是它自建的边缘 IIoT 平台，做机器数据采集、边缘分析、预测性维护；更早还有与 GM、思科联合的 **ZDT（Zero Down Time）**，在 8,500+ 台机器人上跑云端分析、避免上百次非计划停机。**这条"设备→数据→模型"的闭环，别人从外部补不进来。**
- **能赢的**：自家设备的**单机深度闭环**（参数/轨迹类 agent、预测性维护、自适应焊接）。这一层它有独占数据 + 硬件控制权，护城河真实。
- **天花板（结构性，不是"动力不足"那么简单）**：
  - **跨厂、跨设备的编排做不了**——只懂自己的机器。一条真实产线是发那科机器人 + 别家 PLC + 别家视觉 + MES/ERP 的混编，设备商的视野天然停在自己的机身边界。
  - **软件文化弱、迭代慢**——硬件公司的组织节奏、人才结构、发布周期，跟企业级软件平台需要的快速迭代是两种物种。
  - 所以**吃不下企业级平台层**（跨系统的调度、归因、编排）。
- **判断**：**赢单机闭环，输平台层。** "进步动力不足"是表象，**结构性天花板才是本质**——它不是不想做平台，是组织基因和视野边界决定了它做不了跨厂编排。

> **展开：设备商会不会靠收购/开放平台补上软件短板？（原"待展开"第 1 条）**
> 有信号，但补的是"接口"，不是"编排能力"。
> - FIELD 已经是**开放边缘平台**姿态（兼容 FOCAS SDK、OPC UA、MTConnect），发那科也在和 NVIDIA 深化 ROBOGUIDE ↔ Isaac Sim 仿真集成（2026-05）——说明它愿意开放接口、拥抱外部 AI 栈。
> - **但"开放接口"≠"能做跨厂编排"。** 开放平台让第三方来自家生态里开发，本质是把自己做成"底座之一"，不是自己去当那个统管全线的编排层。收购一家软件公司也难改组织基因（硬件公司整合软件团队的失败案例太多）。
> - **结论**：设备商大概率走"开放平台 + 深耕单机智能"，把跨厂编排这块**主动让渡**给第二层的垂直运营商或模型公司。发那科这条线值得持续跟——它补短板的**方式**（是自建平台，还是甘当被编排的一环）会直接验证这个判断。

## 第二波：仿 Palantir 的 FDE 服务商（乱象重灾区）

国内一大批用 FDE（Forward Deployed Engineer，前置部署工程师）模式给客户驻场部署智能体的软件商。

- ⚠️ **必须纠正的流行误解**：**Palantir 的护城河是 Foundry（平台产品）+ Ontology（本体层），不是 FDE 这种人力模式。**
  - FDE 只是 Palantir 早期"打进难啃行业"的**打法**（Nabeel Qureshi《Reflections on Palantir》，2024-10，第一手回忆他 2015 年作为 FDE 驻场的经历）——FDE 是**获客和冷启动的手段**，不是终局。
  - 真正沉淀下来、拿得住 **80%+ 毛利**和 **3–10 年长约**的，是 **Foundry 平台 + Ontology（把企业里的设备/订单/客户及其关系映射成一套语义化的运营模型，不是普通数仓）**，再加 AIP 把私有部署的大模型约束在本体上降幻觉。2026 Q2 Palantir 收入 19.35 亿美元、同比 +93%——**这个数字是平台复利，不是人头堆出来的。**
  - **国内清一色抄了 FDE 的人力外包壳，没抄平台内核。**
- **结果**：本质是"贵的咨询公司"，项目不沉淀、不复利 → **必然产生大量烂尾工程**。
  - 数据佐证这个结构性差距：国内"数据智能/中国版 Palantir"公司普遍毛利率落在 **30%–55%** 区间（中科闻歌 2026 H1 毛利率约 55%、仍净亏约 5,290 万元；第四范式毛利率长期 30% 档 [具体数值以港股财报为准，待核实]），远低于 Palantir 的 80%+。差在哪？**差在没有平台化的经常性收入，全是项目制、非经常性、重定制、私有化部署。**
  - 数新智能 CEO 陈廷梁一句话点破本质：**"中国做 Palantir，最难的不是本体（Ontology），而是 2B 软件市场本身"**——付费意愿低、定制化重、难规模化复制。这才是国内 FDE 商烂尾的根因，不是技术不行。
- **但这个过程似乎不可避免**：大家都在探索期；国内企业转型预算有限；正规大企业不愿趟浑水（按现在模式利润率太低，30%–55% 毛利养不起一线大厂的成本结构）。所以这波乱象是阶段性的必经之路。
- **谁能活下来**：**只有能把每个项目产品化、让沉淀复利的那批**——那一刻他们就不再是 FDE 商，而是变成了第五类"垂直 AI-native 运营商"。中科闻歌把本地化交付周期从 2023 年 185 天压到 2026 H1 约 72 天，就是"往产品化收敛"的早期信号——**但周期压缩只是效率，真正的分水岭是毛利能不能从项目制的 50% 走向平台化的 80%。**

## 第三波：C 端大厂（豆包工作 / 腾讯 WorkBuddy / 阿里千问办公）

上个互联网时代拿到大结果的厂商，2025–2026 密集推出企业办公 Agent。

- **他们自己讲的优势**：依托微信/飞书/钉钉生态，拿到更多上下文。
- **真实的牌其实不在应用，在两处**：
  1. **token / 算力层——他们要靠这个变现，会把横向底座打成白菜价。**
     - 这不是猜测，是已经发生的价格战。火山引擎 2024-05-15 把豆包主力模型定到 **0.0008 元/千 tokens（输入）**，喊"比行业便宜 99.3%"；一周后阿里云把 Qwen-Long 输入价 **直降 97% 到 0.0005 元/千 tokens**；腾讯混元 lite 直接免费。到 2026-03，豆包日均 token 调用突破 **120 万亿**（对比 2024-05 上线时的 1,200 亿/天，两年 **1,000 倍**）。
     - 易观分析把这层的逻辑讲透了：价值正从"拥有硬件"迁移到"组织算力、生产 token"——**GPU = 发电机，裸算力 = 电，Token = 送到户的电力服务**；硬件商品化、利润变薄，而调度/组织层（"电网运营商"）拿住规模优势和稳定位置，token 工厂对裸算力有 **3–6 倍**价值放大。北京 2026-07《关于加快智能体引领发展的若干措施》甚至首次把"Token 工厂"写进政策，并推动计费从"按资源消耗"转向"按价值计费"。
     - **对制造业玩家的含义**：横向底座会被这波打成公用事业（呼应 02 篇"横向会被云厂商抹平、别镀金"）——你不该在这层下重注，但可以**享受它变便宜的红利**。
  2. **飞书/钉钉/企业微信当 system-of-record——组织数据入口。**
     - 办公 Agent 的真正竞争分三层：底层模型、中层 Harness（工程运行时框架）、**顶层上下文数据权限**。模型层难差异化、中层在收敛，**"唯独最上层的数据权限，决定了一个企业办公 Agent 的能力上限"**（蓝洞商业 2026-09）。谁的 Agent 站得离数据更近，谁赢。
     - 钉钉/飞书/企微手里攥着 Agent 最想要的东西：**员工身份、组织关系、业务数据、权限与审计规则**。任务入口会迁移到 Agent，但"组织上下文只会变得更贵"（新立场 Pro 2026-08）。
- **短板（结构性）**：C 端应用和 B 端企业应用差异极大。不是写个文档、改个表格的事；**与业务系统和底层数据的深度打通做不好。**
  - 而且大厂内部的组织墙就卡住这件事：腾讯 **企业微信在微信事业群（WXG）、而 WorkBuddy/腾讯文档在云与智慧产业事业群（CSIG）**——WorkBuddy 默认看不到企业微信的聊天/上下文，除非用户手动喂文件。所谓"生态打通"，在自家都还是两条平行线。
  - 成本结构也拧巴：AI 应用不遵循互联网"用户越多边际成本越低"的规律，**每一次调用都是一次实打实的算力消耗**（中山大学戴欣）。这就是为什么大厂都往"办公"这个**最接近变现**的场景挤——效率提升能换成可量化指标、进企业预算。清华蒋俏蕾对当前办公 Agent 的评语很精准：**"工具以上，伙伴未满"**——从工具到可信赖的伙伴，中间隔着信任和深度打通的坎。
- **判断**：**可能赢横向底座（token/算力 + system-of-record 入口），输纵向应用。** 他们真正的战略意图是把横向抹平、把组织入口攥牢，而不是去某个工业细分里死磕业务闭环——那既不是他们的能力圈，也不是他们的成本结构能承受的。（呼应 02 篇：横向会被这类玩家抹平。）

## 第四波：大模型公司（Claude 金融/法律 · Kimi · 智谱）

模型公司同时握着"最强模型"和"肯下场学到的领域反馈"，是四波里**威胁最大**的一波。

- **案例（已核实）**：
  - **Anthropic / Claude**：2025-07-15 推出 "Claude for Financial Services"（金融分析解决方案，打通 Databricks/Snowflake 等内部数据 + MCP 连接器）；2025-10-27 扩展，出 **Claude for Excel** 侧边栏插件和金融 Agent Skills（DCF 建模、发起覆盖报告等）。法律侧：2026-05 与 **Thomson Reuters** 扩大合作，用 MCP 打通 **CoCounsel Legal** 的"fiduciary-grade"工作流。**而且 Anthropic 自己也在招 Forward Deployed Engineer 做企业驻场交付**（含与 Deloitte 联合挂出的政府线 FDE 岗）——**注意：连模型公司都在用 FDE 打法，进一步印证 FDE 是"桥"不是"护城河"。**
  - **Kimi（月之暗面）**：走的是**轻 FDE**路线——约 **70% 收入来自 API 调用**，靠外部 FDE 伙伴做"最后一公里"交付，而非自建重型驻场团队；企业侧 ARR 报道从约 1 亿→2 亿→3 亿美元（2026 年 3/4/6 月，具体节点待核实）；产品上有 Kimi Hosted Agent 托管智能体平台。
  - **智谱（Zhipu/GLM）**：走的是**国家队 + 央国企 + 地方国资**路线——截至 2025-03 已中标 32 个政府大模型项目，2025 全年中标 57 个、披露金额 2.54 亿元（能源/政务/通信/教科为主）；靠低价中标站稳 B 端（岚图项目报价 348 万，远低于腾讯云 1,334 万、讯飞 759 万）；2024 年净亏损约为收入 10 倍，同样陷"高交付成本、低毛利、巨亏"困境。BigModel 开放平台已聚 70 万企业/开发者。
- **优势**：**FDE 对他们是桥，不是终点**——先前置部署学域知识，再产品化泛化回模型和 Agent Skills 层。他们同时握着模型能力和下场学到的领域反馈，**能弯道超车**：模型够强 + 肯下场趟一个垂直，就能把这个垂直的飞轮转起来。
- **天花板 / 风险**：
  - **战线太长，未必肯在某个工业细分死磕到底。** Anthropic 优先啃金融/法律这种**高客单价、数字化程度高、文本密集**的行业——工业（尤其是重设备、脏活多、账算不清的制造业）不是它的首选战场。这给垂直玩家留了时间窗。
  - 国内两家（智谱靠政府订单、Kimi 靠 API）都还没证明自己能在某个**工业垂直**里把反馈闭环转起来——它们的钱和注意力在别处。
- **判断**：**最强的潜在对手，但注意力有限。** 他们会横扫几个"性感"的高价值垂直（金融、法律、代码），但**广大制造业的长尾细分，短期内轮不到他们死磕**——这正是第二层垂直运营商的机会窗口，也是最大变数（见下"存疑"）。

## 综合判断：2030 是分层 stack，不是单一赢家

| 层 | 谁占 | 为什么 | 关键证据 |
|---|---|---|---|
| **横向底座**（模型/算力/编排） | 模型公司 + 云厂商 | 有动力打白菜价，且模型会吞掉部分编排 | 豆包 0.0008 元/千 tokens、Qwen 降 97%；"Token 工厂"进政策 |
| **垂直应用**（领域飞轮） | **垂直 AI-native 运营商**（从今天的 FDE 商或工业团队里长出来）| 领域反馈闭环不可迁移，模型公司注意力有限 | Palantir 80% 毛利来自 Foundry 平台复利，非 FDE 人力 |
| **单机闭环** | 设备商 | 独占设备遥测 + 硬件控制权 | 发那科 FIELD/ZDT 独占遥测；跨厂编排做不了 |

**唯一确定的输家**：没有产品沉淀的通用 FDE 咨询公司（国内 30–55% 毛利、项目制、烂尾——数据已经在打脸这个模式）。

**胜负手只有一个**：**谁攒住了反馈闭环**（谁的领域数据飞轮转得快）——不是谁技术强、谁模型大。

> ⚠️ **必须自己记住的反方观点：数据飞轮真的是护城河吗？**
> a16z 的 Martin Casado / Peter Lauten 在《The Empty Promise of Data Moats》（2019-05）里泼过冷水：企业级创业里**数据网络效应的实证证据很弱**，单纯的数据规模防御力有限，把数据当"魔法护城河"会误导创始人忽略真正该做的——垂直化、GTM 主导、售后账户控制、品牌。红杉 David Cahn《AI's $600B Question》（2024-06）从另一面提醒：AI 的资本开支和真实收入之间有个巨大缺口，防御性和回报都要打问号。
> **所以别把"攒数据"当免死金牌。** 飞轮成立的前提是 **①数据是私有且不可外部复制的（生产反馈、人工修正）；②飞轮直接改善产品、形成正反馈；③叠加了迁移成本和领域 know-how**。光"有很多数据"不构成护城河——这恰恰是本篇和 02 篇反复强调"反馈闭环 + 领域评价 + 组织嵌入"三件套的原因：单靠数据量不行，得是"转得起来的闭环"。

## 我们的象限（择业 / 是否创业的关键）

我们团队的画像——**垂直域（工业）+ 已有一版基建 + EVI 归因能力**——正好落在"最有意思的象限"：有条件长成第二层的"垂直 AI-native 运营商"。

- 对**择业**：判断一个雇主值不值得去，就看它在这张分层图里站哪——是在会被抹平的横向层挣扎，还是在攒不可迁移的垂直飞轮。（一把可直接用的尺：**它的收入是项目制非经常性的，还是平台化能复利的？毛利在往 55% 天花板撞，还是在往 80% 爬？**）
- 对**是否创业**：这个象限是少数模型公司和云厂商都吃不掉的位置，值得认真评估——**但要清醒**：模型公司注意力有限给了窗口，可窗口不会永远开着（见下"存疑"最大变数）。
- 对**面试**：这套分层格局 + "谁攒住反馈闭环" + "Palantir 的护城河是平台不是 FDE" + "C 端大厂真牌在 token 层不在应用"——是最能体现行业判断力的谈资，而且每一条都有真实证据链撑着，不是空谈。
- **EVI 是我们卡这个象限的关键筹码**：垂直运营商能不能从项目制过渡到产品复利，取决于能不能把"AI 创造的价值"算清并锁定为可计价的商业结果（呼应 04 篇：谁把客户的账算清，谁就掌握归因权和定价权）。

## 待展开 / 存疑（逐条展开论证）

### 1. 设备商会不会靠收购/开放平台补上软件短板？
已在"第一波"末尾展开。**结论**：设备商大概率走"开放接口 + 深耕单机"，主动让渡跨厂编排。发那科的 FIELD 开放平台、与 NVIDIA 的仿真集成是"开接口"，不是"做编排"；补短板的方式（自建平台 vs. 甘当被编排一环）是关键观察点。

### 2. 垂直 AI-native 运营商的融资/商业模式长什么样？靠项目制起步怎么过渡到产品复利？
这是我们自己要走的路，必须想清楚（详见 04 篇）。核心路径：
- **起步不可避免是项目制/驻场**（跟 FDE 商同一个起跑线）——这不丢人，Palantir、Anthropic 都这么起步。
- **分水岭在于：每个项目的沉淀是不是"框架无关的领域资产"**（呼应 02 篇：知识图谱、轨迹日志、评测集、标注样本这四类可迁移资产）。FDE 商烂尾，是因为交付物长在临时脚手架上、换个客户就重写；能活下来的，是把沉淀变成可复用的产品内核。
- **商业模式上从"按人力工时"逐步爬向"按效果分成"**（04 篇的 effect-based 演进曲线）——毛利从项目制的 50% 往平台化的 80% 爬，就是"变成第二层"的量化标志。
- **融资叙事**：不讲"我们有多少数据"（a16z 会拆穿），讲"我们的反馈闭环在 X 个客户上转起来了、领域评价标准别人抄不走、归因能力锁定了定价权"。

### 3. 模型公司如果开源垂直 agent 能力，会不会直接端掉第二层？（最大的不确定性）
**这是整篇最大的变数，必须正视。**
- **威胁场景**：模型公司把某个工业垂直的 agent 能力做进模型/开源 Agent Skills，第二层的"领域 know-how 溢价"被瞬间抹平。Bitter Lesson 在纵向层的翻版（呼应 02 篇：模型进步会吞掉横向层——问题是它会不会也吞掉部分纵向）。
- **为什么第二层仍有防线**：模型公司能开源的是**通用的、可从公开数据学到的领域知识**；它开源不了的是 **①你独占的私有生产反馈数据（工厂现场的轨迹+人工修正）；②与具体设备的物理闭环/标定；③嵌进客户组织流程和账本的归因能力**。这三样正是 02 篇说"模型吞不掉的三样"，也正是 EVI 的内核。
- **但防线有时效**：模型公司注意力有限（金融/法律优先、工业长尾靠后）给了窗口，可一旦某个工业垂直被证明值钱、且反馈数据能被绕过（比如仿真数据足够好、或客户愿意把数据交给模型公司），窗口就会关。
- **应对**：**把不可外部获取的私有闭环攥得越紧越好**——数据留在客户侧+我们侧的防腐层里、归因能力和组织嵌入越深越好。**打的不是"模型能力差"，打的是"物理世界和组织账本的最后一公里，模型公司够不着也不愿够"。**

### 4. 国内 vs 海外这套格局的差异
四波力量的**排序和形态在国内外不同**，不能照搬 Palantir/Anthropic 的剧本：
- **数据合规 / 国产化栈**：国内政务、央国企要求私有化部署、国产算力栈——这**天然利好"驻场+私有部署"的第二层玩家**（模型公司的 SaaS 打法在这些场景受限），但也**压低毛利**（私有化交付重、难复利），是把双刃剑。
- **预算结构**：海外企业软件付费意愿强、接受长约订阅（Palantir 3–10 年长约撑起 80% 毛利）；国内 2B 付费意愿低、偏一次性项目制（数新智能陈廷梁点破的"最难的是 2B 软件市场本身"）。**这意味着国内"从项目制过渡到产品复利"比海外更难，effect-based/gainsharing 更需要先帮客户把账算清**（呼应 04 篇：EVI 是楔子）。
- **玩家形态**：国内模型公司分化明显——**智谱靠政府/央国企订单、Kimi 靠 API+轻 FDE**，都还没在工业垂直里转出飞轮；C 端大厂的组织墙（腾讯 WXG vs CSIG）让"生态打通"打折扣。**海外是 Palantir/Anthropic 直接下场高价值垂直；国内是一地探索、各走各路**——对我们这种"垂直+基建+归因"的团队，国内的窗口反而更宽，因为强对手都还没聚焦到工业长尾。
