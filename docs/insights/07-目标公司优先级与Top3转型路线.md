# 07 · 目标公司优先级与 Top3 岗位转型路线

> 讨论稿 / 会更新 · 最近更新 2026-09-14
>
> **一句话结论**：这次排序需要拆成两层：**严格甲方 / 准甲方业务腹地路线**与**综合现实求职路线**。用友 BIP 不是甲方，它的价值是“产品化过渡”和补产品定义力；第四范式也不是甲方，它的价值是“商业化训练”；工大卫星更像真实高端制造甲方，但公司小，数据成熟度、组织授权和预算都高度不确定，不能无条件排 Top3。综合看，当前更稳妥的推进组合是：**中石油数智研究院作为工业准甲方 / 稳定线，用友作为产品化过渡线，第四范式作为商业化进攻线；工大卫星作为验证通过可上调的高潜力甲方机会。**

---

## 0. 这篇在回答什么

`06-职业选择与智能制造转型路线.md` 已经给出一个核心判断：

> 职业选择不是选公司，而是选复利资产。若目标是智能制造 / 数字化负责人，长期更值得沉淀的是“甲方业务腹地 + AI / 数据能力”的复合能力，而不是单点工具能力。

但把这个判断落到具体公司时，不能简单地把“看起来做制造 / 工业 AI 的公司”都归为一类。至少要区分三种路线：

1. **甲方 / 准甲方业务腹地路线**：更接近真实工厂、真实工业数据、内部经营指标和组织转型。
2. **产品化过渡路线**：不在甲方内部，但能把已有甲方经验转成标准化工业软件 / AI 产品能力。
3. **乙方商业化路线**：AI 更纯、客户更多、商业化训练更强，但可能远离完整真实业务腹地。

这篇因此不是简单重排 `docs/companies/`，而是回答：

1. 哪些机会属于真正的甲方 / 准甲方腹地？
2. 哪些机会虽然不是甲方，但对当前阶段仍有现实价值？
3. 工大卫星这种“小而真”的甲方机会，如何判断是高潜力还是大坑？
4. 当前应该形成怎样的主攻、备选和验证清单？

## 1. 排序口径：先分路线，再排优先级

### 1.1 原始六维度仍然有效

| 维度 | 问题 | 权重 |
|---|---|---:|
| 场景腹地 | 是否能接触真实制造 / 工业现场、质量、工艺、设备、供应链或运营指标？ | 高 |
| 数据资产 | 是否能接触真实数据问题，而不是只做 PPT / 报表 / 系统上线？ | 高 |
| AI 落地 | 是否能参与 AI 从场景定义、数据接入、模型 / Agent、反馈到复盘的闭环？ | 高 |
| 经营归因 | 是否能把 AI 效果翻译成良率、OEE、停机、报废、返工、客诉、成本、交付等经营语言？ | 高 |
| 产品 / 方法论 | 是否能补齐产品定义、标准化方案、方法论输出，而不是只做交付碎活？ | 高 |
| 生活约束 | 通勤、出差、加班、稳定性、薪资是否与当前人生阶段兼容？ | 高 |

### 1.2 但必须新增两个判断：甲方属性与数据成熟度

前面的排序把“综合机会好”和“甲方腹地好”混在了一起，这会造成误判。需要新增两个问题：

#### 问题一：它到底是不是甲方腹地？

| 类型 | 代表公司 | 本质 | 能沉淀什么 | 主要缺口 |
|---|---|---|---|---|
| 严格甲方 / 制造本体 | 小米智能工厂、三一、工大卫星、商飞 | 自己拥有生产 / 制造 / 质量责任 | 真实现场、内部流程、组织推动、经营指标 | 可能工时高、薪资低、数据不成熟或体制重 |
| 准甲方 / 集团内部数智平台 | 中石油数智院、国能数智、国网智研院 | 服务集团内部真实工业场景 | 工业数据、长期项目、内部转型方法论 | 可能偏研究、平台、汇报，离一线有距离 |
| 产品化供给侧 | 用友 BIP | 工业软件 / 企业服务产品公司 | 产品定义、标准化、工业软件体系 | 不掌握真实产线和内部经营账 |
| AI 商业化供给侧 | 第四范式、天泽智云、寄云科技 | 对外卖 AI / 工业数据智能方案 | 商业化、客户价值表达、跨客户经验 | 可能售前化、交付化、出差多 |
| 运营商 / 央企乙方 | 中国电信 TeleAI | 云网 + AI + 工业互联网方案 | 稳定、产业化、央企资源 | 工业不是主航道，容易方案包装化 |

#### 问题二：它的数据成熟度是否足够支撑 AI？

“甲方”不是天然好。甲方如果数据很差、组织不授权、预算不明确，反而会让人陷入更早期、更混乱、更难推动的坑。

尤其像工大卫星这类小型高端制造公司，虽然场景真实，但数据基础可能处在非常早期：

- PLM / MES / QMS / ERP 体系未必完整；
- 测试数据可能散落在设备本地、Excel、PDF 报告或专家个人电脑里；
- 产品编号、BOM、总装、测试、问题归零、供应商批次未必打通；
- AI 岗位可能只是“老板觉得该搞 AI”；
- 没有明确团队、预算和业务 owner；
- 进去后可能先做数据清洗、系统补洞、流程推动，而不是 AI 架构。

所以更准确的判断不是：

```text
甲方 > 乙方
```

而是：

```text
有真实场景 + 有数据基础 / 可治理空间 + 有组织授权 + 有经营指标
  >
只有甲方身份但没有数据和授权
```

## 2. 修正后的路线分类与优先级

### 2.1 严格甲方 / 准甲方业务腹地排序

如果严格执行 `06` 的“甲方业务腹地 + AI / 数据能力”逻辑，排序应更接近：

| 优先级 | 公司 / 岗位 | 类型 | 判断 |
|---:|---|---|---|
| 1 | **中石油数智研究院** | 准甲方 / 集团内部数智平台 | 工业数据、AI 投入、组织托底、薪资弹性相对平衡，是当前最稳的工业数智化路线 |
| 2 | **工大卫星** | 小型高端制造甲方 | 场景真、通勤好、影响力大，但必须验证数据成熟度、预算和授权；验证通过可升 Top2，未验证前只能强备选 |
| 3 | **商飞北研中心** | 央企高端制造 / 科研甲方 | 技术方向匹配、稳定、女性友好，但薪资和科研院所体制是硬伤 |
| 4 | **小米智能工厂** | 大厂智能制造甲方 | 数据基建和场景极好，但工时考核对当前阶段风险过高 |
| 5 | **国能数智** | 集团内部 IT / AI 平台 | 技术对口，但通勤、薪资、岗位个贡化不确定 |
| 6 | **三一 / 树根互联** | 制造龙头 / 工业互联网 | 场景丰富，但三一本体强度和文化风险太高；树根需单独验证 |
| 7 | **国网智研院 / 国家能源低碳院** | 央企研究院 | 稳定但薪资降幅和岗位错配明显 |

这张表里没有用友和第四范式，因为它们本质上不是甲方腹地。

### 2.2 产品化 / 商业化路线排序

如果目标是把现有甲方经验转化为产品定义、解决方案和商业化能力，则排序是另一套：

| 优先级 | 公司 / 岗位 | 类型 | 判断 |
|---:|---|---|---|
| 1 | **用友 BIP 智能制造** | 工业软件产品化路线 | 家庭友好、通勤极佳、补产品定义力，适合把甲方经验标准化，但不是甲方 |
| 2 | **第四范式** | AI 商业化路线 | AI 是利润中心，商业化训练强，薪资可能匹配，但出差和售前化风险高 |
| 3 | **天泽智云 / 寄云科技** | 工业 AI 小公司路线 | PHM / 工业数据智能高度匹配，个人影响力大，但稳定性和出差风险高 |

如果把职业复利、家庭友好、薪资风险、岗位可得性和路线纯度放在一起，当前更稳妥的综合排序是：

| 排名 | 公司 / 岗位 | 推荐动作 | 一句话判断 |
|---:|---|---|---|
| 1 | **中石油数智研究院** | 主攻 | 最稳的工业准甲方路线：有真实工业数据、AI 投入和组织托底 |
| 2 | **用友 BIP 智能制造** | 主攻 | 不是甲方，但现实匹配度强；适合补产品定义和工业软件产品化能力 |
| 3 | **第四范式** | 主攻但严筛 | 商业化训练最强，但要严控出差、售前化和交付化 |

| 5 | **中国电信 TeleAI / AI 科技公司** | 稳定备选 | 国企中比国网/低碳院更市场化，工业 AI 不是主航道但可接受 |

| 9 | **兆易创新** | 技术转型备选 | 公司和通勤好，但路线偏端侧 AI，不是智能制造腹地主线 |
| 10 | **国能数智 / 国网 / 低碳院** | 保底或信息收集 | 稳定性强，但综合复利和薪资性价比偏弱 |

## 3. 当前建议的三线推进组合

不建议只按单一价值观押注。当前更合理的是三线并行，但要明确每条线的性质。

```text
稳定准甲方线：中石油数智研究院
  押工业 AI 方法论 + 真实工业数据 + 央企组织托底

产品化过渡线：用友 BIP
  补产品定义力 + 工业软件体系 + 把甲方经验标准化

商业化进攻线：第四范式
  训练对外表达、客户价值归因和 AI 商业化，但严控出差和售前化

高潜力甲方观察线：工大卫星
  验证数据成熟度、组织授权、预算和团队；通过后可上调
```

这比“用友 Top1、工大卫星 Top4”更准确，因为它承认：

- 用友是好机会，但不是甲方；
- 工大卫星是甲方，但不一定有成熟数据和组织条件；
- 中石油数智院虽然不是制造业本体，但更接近“有组织托底的工业准甲方”；
- 第四范式适合补商业化，不适合被误认为甲方腹地路线。

## 4. 主线一：中石油数智研究院工业 AI 应用 / 方法论方向

### 4.1 为什么现在上调为综合第一

中石油数智研究院不是典型制造业甲方，但它更像“工业集团内部数智化平台”：

- 服务中石油内部真实能源工业场景；
- 有昆仑大模型、数字孪生、预测性维护、工业物联网等明确 AI 投入；
- 2024 年新成立，处在扩张期；
- 相比小公司，数据、预算和组织托底更强；
- 相比传统研究院，薪资和岗位弹性更好；
- 最需要的不是纯算法，而是“AI 场景落地 + 方法论 + 价值评估”。

这与当前能力高度匹配：

> 工业 AI 的瓶颈通常不是模型本身，而是场景定义、数据质量、专家知识结构化、反馈闭环和价值归因。过去 6 年做的正是这条链路。

### 4.2 应主投的岗位

优先级：

1. AI 应用研究员，工业场景落地方向；
2. 大模型工业应用 / 智能体场景负责人；
3. 工业数据治理 / 价值评估 / AI 场景规划方向；
4. 数字孪生 / 预测性维护研究员；
5. 昆仑大模型场景应用专家。

要避开的岗位：

- 纯大模型训练工程师；
- 纯算法研究员；
- 纯后台开发；
- 昆仑数智大规模交付实施岗。

### 4.3 面试定位

要把自己讲成：

> 能把行业大模型、工业数据、诊断智能体和经营价值连接起来的工业 AI 落地方法论人才。

经验迁移关系：

| 当前经验 | 能源工业映射 |
|---|---|
| 汽车质量预警 | 炼化过程异常检测 |
| 焊接 / 工艺曲线异常 | 设备时序信号异常 |
| 供应商风险预警 | 油气设备 / 管道风险预警 |
| SPC 诊断 Agent | 油井 / 炼化 / 管道诊断 Agent |
| EVI 价值归因 | 节能、减停机、降事故、提产量 |

### 4.4 90 天准备路线

#### 第 1 阶段：能源行业补课

重点了解：

- 油气田生产流程；
- 炼化基本流程；
- 管道运输；
- 抽油机井、钻井、压裂、炼化装置；
- 设备预测性维护；
- 昆仑大模型公开案例；
- 中石油“数智石油”战略。

#### 第 2 阶段：准备迁移方案

输出材料：

```text
《从汽车制造 AI 到能源工业 AI：场景迁移与价值评估方案》
```

建议结构：

1. 工业 AI 落地的共性问题；
2. 汽车制造案例；
3. 能源工业场景映射；
4. 昆仑大模型 + Agent 的应用切入点；
5. 预测性维护 / 异常检测 / 诊断 Agent / EVI；
6. 90 天试点建议；
7. 价值评估框架。

#### 第 3 阶段：投递与验证

面试必问：

1. 这个岗位在研究院还是昆仑数智？
2. 是做方法论 / 规划，还是被借调做交付？
3. 团队目前最缺算法、工程，还是场景落地人才？
4. 社招定级如何？是否一人一策？
5. 工作地点在沙河 / 未来科学城吗？
6. 出差频率与项目节奏如何？
7. 是否有机会负责一类场景，而不是只做课题支持？

### 4.5 成功路径

```text
当前：汽车制造 AI 落地负责人
  ↓
中石油数智院：工业 AI 应用研究员 / 场景方法论专家
  ↓ 1-2 年
能源工业 AI 场景负责人 / 昆仑大模型行业应用骨干
  ↓ 3-5 年
央企工业 AI 转型专家 / 数字化转型负责人候选
```

## 5. 主线二：用友 BIP 智能制造 AI 产品经理

### 5.1 为什么仍然保留为主攻，但要重新定性

用友不属于甲方，这是必须修正的前提。

用友本质上是：

```text
工业软件 / 企业服务厂商 / 乙方产品公司
```

它不拥有自己的真实工厂、产线、质量责任、生产经营账和内部组织变革场景。因此，它不应被定义为“甲方业务腹地路线”。

但它仍然是当前很强的现实选项，因为它能提供另一种复利：

- 把甲方制造 AI 经验转成标准化产品能力；
- 补独立产品定义力；
- 学工业软件体系：ERP / MES / QMS / APS / PLM / BIP；
- 接触大量制造客户；
- 家庭友好、通勤极佳、出差少；
- 在传统企业软件 AI 化转型期，制造业一线经验有稀缺性。

所以用友的准确定位是：

> **产品化过渡路线**：不是甲方腹地，但适合把已有甲方经验标准化、产品化。

### 5.2 应主投的岗位

优先级：

1. AI 产品经理 / 高级 AI 产品经理，智能制造方向；
2. 制造云 AI 场景产品负责人；
3. 工业数据产品经理 / 工业知识库 / 工业智能体方向；
4. 智能制造解决方案专家。

要避开的岗位：

- ERP 实施项目经理；
- 纯报表 / BI 产品；
- 纯供应商实施管理；
- 大客户定制交付 PM；
- 没有 AI 或制造业务入口的横向平台岗位。

### 5.3 面试定位

不要把自己讲成算法工程师，也不要讲成传统项目经理，而要讲成：

> 来自制造业甲方一线，真正知道工业 AI 为什么落不了地，并且做过从数据采集、AI 诊断、业务闭环到价值核算的人。

核心卖点：

| 卖点 | 证据 |
|---|---|
| 制造场景理解 | 供应链质量预警、56 家供应商、46000+ 工艺点位 |
| AI 产品化能力 | SPC 诊断 Agent、本体论 / 知识图谱、异常检测、人机反馈闭环 |
| 价值归因能力 | 风险拦截、3.77 亿收益、EVI / ROI / 经营价值量化 |
| 组织推动能力 | 跨供应商、跨部门、从 0 到 1 项目落地 |

### 5.4 90 天准备路线

#### 第 1 阶段：把理想经验产品化

输出一份 10 页以内材料：

```text
《制造质量 AI 闭环产品方案》
```

建议结构：

1. 目标客户：离散制造企业质量 / 工艺 / 供应链部门；
2. 痛点：质量风险发现晚、数据口径乱、经验沉淀弱；
3. 产品形态：质量预警 + 根因诊断 + 人机反馈 + 价值归因；
4. 核心模块：数据接入、SPC、诊断 Agent、知识库、EVI；
5. 与 ERP / MES / QMS / PLM 的关系；
6. 价值指标：良率、报废、返工、客诉、停线、供应商质量损失；
7. 可标准化部分与需行业定制部分。

#### 第 2 阶段：补用友语境

重点了解：

- BIP 制造云；
- iuap；
- YonGPT / YonClaw；
- ERP / MES / QMS / APS / PLM 基础关系；
- 信创替代 SAP / Oracle；
- 大型制造企业数字化常见架构。

目标不是成为 ERP 专家，而是能讲清：

> AI 不应该只是外挂功能，而应该嵌入业务流程、数据对象和管理闭环。

#### 第 3 阶段：投递与验证

面试必问：

1. 这个岗位是做标准产品，还是大客户定制？
2. AI 产品团队在制造云里的话语权如何？
3. 是否能接触客户真实制造场景？
4. 是否有机会定义产品，而不是只写需求文档？
5. 出差频率多少？
6. 职级和薪资是否能按专家 / 总监级谈？

### 5.5 成功路径

```text
当前：制造业甲方 AI 落地负责人
  ↓
用友：智能制造 AI 产品经理 / 专家
  ↓ 1-2 年
制造云 AI 场景负责人 / 工业智能体产品负责人
  ↓ 3-5 年
智能制造产品线负责人 / 工业 AI 解决方案负责人
```

风险边界：如果用友岗位实际只是 ERP / MES 功能需求、项目实施、客户定制或售前包装，则不值得作为主线。

## 6. 主线三：第四范式制造业 AI 解决方案架构师

### 6.1 为什么保留为进攻线

第四范式也是乙方，不是甲方腹地。但它的价值在于商业化训练：

- AI 是 100% 利润中心；
- 经验可以直接变现；
- 能接触多个制造业客户；
- 能补对外价值表达和商业化能力；
- 薪资较可能持平；
- 未来如果想回甲方、去工业 AI 创业公司，或者做工业 AI 产品负责人，这段经历都有价值。

但它的问题也很明确：

- 出差；
- 售前化；
- 项目压力；
- 对宝妈不友好；
- 可能做成高级方案 / PPT / 投标，而不是产品和方法论。

所以第四范式不是甲方路线，而是：

> **商业化进攻线**：职业跃迁强，但生活风险高。

### 6.2 应主投的岗位

优先级：

1. 工业 / 制造业解决方案架构师；
2. 制造业 AI 行业专家；
3. SHIFT 制造方向方案负责人；
4. AI 产品经理，制造行业应用方向；
5. 客户成功 / 行业交付负责人。

要避开的岗位：

- 纯售前投标；
- 泛行业解决方案；
- 长期驻场交付；
- 不参与产品沉淀的项目经理。

### 6.3 面试定位

要把自己讲成：

> 真正来自制造业内部、懂客户真实问题、能帮第四范式把 AI 方案从 PoC 推到价值闭环的人。

第四范式最需要的不是“会模型”，而是：

- 知道制造企业为什么买 AI；
- 知道客户内部谁阻碍、谁推动；
- 知道数据为什么拿不到；
- 知道怎么讲 ROI；
- 知道 AI 方案上线后怎么判断有没有用；
- 知道供应链质量、设备、工艺、生产的真实语言。

### 6.4 90 天准备路线

#### 第 1 阶段：补对外方案表达

把现有案例改写成客户方案语言：

```text
《制造质量 AI 解决方案案例包》
```

每个案例按以下结构写：

1. 客户背景；
2. 业务痛点；
3. 数据基础；
4. AI 方案；
5. 落地路径；
6. 业务结果；
7. 可复制性；
8. 商业价值。

#### 第 2 阶段：补第四范式产品体系

重点了解：

- Sage AIOS；
- SHIFT；
- AIGS；
- 制造业客户案例；
- 宁德时代等标杆案例；
- AI 平台型公司如何做行业解决方案；
- 招投标 / PoC / 标杆客户 / 复制推广的商业逻辑。

#### 第 3 阶段：投递与筛选

面试必问：

1. 月均出差几天？
2. 是售前为主，还是方案设计 + 落地跟踪？
3. 是否有制造业专属团队？
4. 是否有北京 / 华北客户，还是全国跑？
5. 项目价值如何衡量？是否做上线后经营效果复盘？
6. 方案能否沉淀进产品，还是每个客户都重做？
7. 这个岗位和产品团队的关系是什么？

### 6.5 成功路径

```text
当前：制造业甲方 AI 落地负责人
  ↓
第四范式：制造业解决方案架构师 / 行业专家
  ↓ 1-2 年
工业 AI 行业方案负责人 / 制造业标杆客户负责人
  ↓ 3-5 年
工业 AI 商业化负责人 / 工业 AI 产品负责人 / 创业公司合伙人候选
```

## 7. 高潜力验证对象：工大卫星

### 7.1 为什么不能直接排 Top3

工大卫星很有吸引力：

- 永丰中关村壹号，通勤极佳；
- 商业航天 + 卫星批产 + 智能制造，处在国家战略和产业上升期；
- 卫星 AIT 质量管控与汽车制造质量 AI 底层逻辑相通；
- AI / 数据团队可能从 0 到 1，个人影响力大；
- 可能有北京户口 / 工作居住证等特殊福利。

但它最大的不确定性也很明显：

> 公司小，数据、流程、系统、组织机制很可能都不成熟。

可能出现的情况包括：

- 没有统一数据平台；
- 测试数据散落在 Excel、设备本地文件、PDF 报告里；
- PLM / MES / QMS / ERP 体系不完整；
- 数据标准、编码、批次追溯还没打通；
- 老专家经验在脑子里，未结构化；
- AI 岗位只是“老板觉得该搞 AI”；
- 没有明确预算、团队和业务 owner；
- 进去后不是做 AI 架构师，而是先做数据清洗、系统补洞、流程推动。

所以工大卫星的准确定位不是“稳定甲方首选”，而是：

> **高潜力、高不确定性的机会型甲方选项。**

### 7.2 数据不成熟什么时候是机会，什么时候是坑

#### 情况 A：数据不成熟，但公司承认问题，并给授权

这是好机会。

如果管理层明确知道：

- 批产能力上来后，靠人工和专家经验撑不住；
- 质量追溯、测试数据、工艺参数、供应商数据必须打通；
- AI 不是先做大模型聊天，而是先做数据底座、知识库、质量闭环；
- 愿意给跨部门权限、预算和团队；

那么数据不成熟反而是壁垒，因为你能做的是：

```text
从混乱数据和模糊场景里，搭出可用的数据-知识-AI-价值闭环
```

#### 情况 B：数据不成熟，但公司只想要 AI 效果

这是大坑。

如果他们的真实想法是：

- 没有数据治理预算；
- 没有业务部门配合；
- 没有数字化负责人；
- 没有产品 / 项目 owner；
- 只是想招一个“懂大模型的人”做 demo；
- 老板期待三个月出一个 AI 助手；
- 质量、工艺、测试团队不愿改流程；

那这个岗位会变成：

```text
一个人补数据基建 + 补业务流程 + 补 AI 方案 + 补老板预期
```

这很容易重演已有困境，而且资源更少、组织托底更弱。

### 7.3 工大卫星八问

如果后续接触工大卫星，必须问得很细。

1. **当前有哪些核心系统？**  
   PLM、MES、QMS、ERP、测试数据管理系统分别是什么状态？是自研、外采，还是 Excel / 文档为主？

2. **数据是否能按产品编号打通？**  
   一颗卫星从设计、BOM、总装、测试、环境试验、问题归零到交付，能不能用统一编号追溯全链路数据？

3. **测试数据在哪里？**  
   热真空、振动、EMC、总装测试、单机测试这些数据目前是结构化入库，还是保存在设备本地文件 / Excel / 报告 PDF 里？

4. **有没有明确的数字化 owner？**  
   公司内部谁对数字化建设负责？是质量、制造、研发、IT，还是老板直接抓？

5. **这个岗位有没有团队和预算？**  
   是独立贡献者，还是要组建数据 / AI 团队？今年是否有明确预算和项目目标？

6. **AI 的第一优先级是什么？**  
   是设计知识管理、测试数据异常、质量追溯、问题归零、遥感数据处理，还是办公效率？

7. **业务部门是否愿意改流程？**  
   如果为了数据闭环，需要研发、总装、测试、质量团队改变记录方式和流程，公司是否愿意推动？

8. **老板对这个岗位的一年期待是什么？**  
   是一个 AI demo，还是一套可持续运行的数据 / 质量 / 知识闭环？

### 7.4 上调 / 下调规则

#### 可以上调到 Top2 / Top3 的条件

如果确认以下条件成立：

- 有真实批产质量 / 测试 / 追溯痛点；
- 管理层愿意做数据底座；
- 有明确数字化 / AI 预算；
- 能直接参与体系设计；
- 不只是做 demo；
- 薪资可接受；
- 有团队或未来组队空间；

那么工大卫星可以升入 Top3，甚至超过第四范式。

#### 应下调的条件

如果发现：

- 数据基本没有结构化；
- 没有团队；
- 没预算；
- 老板只想做大模型 demo；
- 业务部门不愿配合；
- 薪资还低；

那它应该降到第二梯队甚至第三梯队。

## 8. 不同优先级下的排序

### 8.1 如果严格坚持甲方 / 准甲方腹地

```text
中石油数智院 > 工大卫星（验证通过后）> 商飞北研 > 小米智能工厂 > 国能数智 > 三一 / 树根 > 国网 / 低碳院
```

注意：用友和第四范式不在这条路线里。

### 8.2 如果家庭友好是第一优先级

```text
用友 > 中石油数智院 > 中国电信 / 商飞北研 > 工大卫星（验证后）> 第四范式
```

第四范式、小米、三一应谨慎。

### 8.3 如果职业跃迁速度是第一优先级

```text
第四范式 > 用友 > 天泽智云 / 寄云科技 > 工大卫星（验证后）> 中石油数智院
```

这条路牺牲生活稳定性更明显。

### 8.4 如果长期稳定是第一优先级

```text
中石油数智院 > 中国电信 > 商飞北研 > 国能数智 > 国网 / 国家能源低碳院
```

但需要接受体制、薪资和成长节奏限制。

### 8.5 如果要兼顾现实可行性和长期复利

```text
中石油数智院 + 用友 + 第四范式 并行推进，工大卫星重点验证
```

这是当前最稳妥的组合。

## 9. 面试时统一使用的筛选问题

无论去哪家公司，都应问这几类问题。

### 9.1 判断是否能沉淀复利资产

1. 这个岗位能不能接触真实业务现场？
2. 能不能接触生产、质量、工艺、设备、供应链中的至少两类核心业务？
3. 能不能参与需求定义，而不是只接需求？
4. 能不能看到项目上线后的业务结果？
5. 能不能参与数据治理、指标口径、价值归因？
6. 能不能沉淀产品、方法论或标准方案？

### 9.2 判断是否会掉坑

1. 是否主要做 ERP / OA / 报表 / 运维？
2. 是否只是供应商管理和会议纪要？
3. 是否长期驻场交付？
4. 是否只做售前 PPT 和投标？
5. AI 项目是否只是展示工程？
6. 业务 owner 是否真实存在？
7. 是否没人关心上线后的效果？

### 9.3 判断数据成熟度

1. 核心业务数据在哪里？
2. 数据是否结构化入库？
3. 是否有统一主数据 / 编码体系？
4. 是否能追溯到产品、批次、工序、设备、人员、供应商？
5. 是否有人对数据质量负责？
6. 是否有数据治理预算？
7. AI 项目是否先做数据评估？

### 9.4 判断生活约束

1. 月均出差几天？
2. 日常工作时间和加班机制是什么？
3. 是否有工时考核？
4. 坐班地点是否固定？
5. 薪资是否能匹配底线？
6. 是否支持弹性办公？
7. 直接领导风格如何？

## 10. 最终结论

修正后的关键判断是：

```text
用友不是甲方，而是产品化过渡路线；
第四范式不是甲方，而是商业化进攻路线；
工大卫星像甲方，但数据成熟度和组织授权未验证前不能无条件排 Top3；
中石油数智院虽然不是制造业本体，但更像有组织托底的工业准甲方数智化平台。
```

因此当前最稳妥的推进组合是：

```text
综合主攻：中石油数智研究院
产品化主攻：用友 BIP 智能制造
商业化进攻：第四范式
高潜力验证：工大卫星
稳定备选：中国电信 / 商飞北研
高成长备选：天泽智云 / 寄云科技
```

最重要的定位不是：

- 算法工程师；
- 传统 IT 项目经理；
- ERP 实施顾问；
- 售前 PPT 专家；
- 大模型工具使用者。

而是：

> **懂制造现场 + 懂数据系统 + 懂 AI 能力边界 + 懂经营价值归因 + 懂组织推动的工业 AI 落地负责人。**

公司只是载体。真正要选择的是下一阶段最值得沉淀的复利资产，同时要避免两个误区：

1. **把乙方产品公司误认为甲方腹地。**  
   用友、第四范式有价值，但它们沉淀的是产品化 / 商业化能力，不是完整甲方内部经营账。

2. **把甲方身份误认为天然复利。**  
   工大卫星、小米、三一、商飞虽然更接近真实场景，但只有在数据基础、组织授权、预算和业务 owner 成立时，才真的有复利。
