# 12-02 · 芯片良率水平、难拦截失效与数据挖掘优先级

> 讨论稿 / 会更新 · 最近更新 2026-09-30
>
> **一句话结论**：良率不是一个单点数字，而是 Wafer、CP、FT、可靠性和客户现场质量的连续链条。成熟芯片量产后 CP/FT 良率通常可以很高，但真正难拦截的是 **spec 内边缘品、长期可靠性尾部、应用场景耦合、偶发失效和低概率随机缺陷**；其中最适合用数据挖掘优先攻克的是多参数 out-of-family、wafer map pattern、stress delta、retest-pass unit、存储 margin 尾部和 RMA 反向标注。

## 1. 良率不能只看一个数字

芯片质量里说“良率”，至少要分 5 层。

| 层级 | 含义 | 典型关注点 |
|---|---|---|
| Wafer yield | 晶圆制造后可用 die 比例 | 制程缺陷、阵列缺陷、空间 pattern、参数漂移 |
| CP yield | 晶圆级测试通过率 | 功能、电性、memory BIST、Vmin、Fmax、leakage、wafer map |
| FT yield | 封装后成品测试通过率 | IO、接口、功耗、温度、电源、封装引入问题 |
| Reliability yield | 可靠性应力后通过率 | HTOL、HAST、TC、ESD、retention、P/E、disturb |
| Field quality | 客户现场质量 | ppm、RMA、应用边界、长期退化、系统级耦合 |

质量工程最容易误判的地方是：

> CP / FT 良率看起来很好，不等于客户现场质量一定没有尾部风险。

因为 CP / FT 更多回答“现在是否通过测试”，而客户现场质量回答：

> 在真实电源、温度、负载、软件、湿度、噪声、使用年限和客户系统组合下，未来是否仍然稳定。

## 2. 各产品线的大致良率特征

### 2.1 NOR Flash

成熟 NOR Flash 通常使用相对成熟的非易失存储工艺。若产品、容量、工艺平台和测试程序都已经稳定，CP / FT 良率一般可以做到较高水平。

行业经验级判断：

```text
成熟 NOR Flash：CP / FT 良率常见可到 90% - 98%+
大容量、新工艺、新产品爬坡或特殊可靠性等级：波动更大
```

但 NOR 的风险不只在初始良率。

关键矛盾：

> 初始读写能过，不代表长期 retention、endurance、read disturb 和高速接口边界一定安全。

较容易提前拦截：

- 初始 read fail；
- program / erase verify fail；
- 固定 sector / block fail；
- 明显 retention bake fail；
- 明显 QSPI timing fail。

较难提前拦截：

- 长期 retention tail；
- P/E 后 erase time 或 program time 退化过快；
- read disturb / program disturb 的尾部风险；
- 客户高速 QSPI 场景下的边界失效；
- embedded Flash 在 MCU 场景里的 boot / code fetch 边界。

难点：

- 长期数据保持靠加速模型外推，无法每颗等真实寿命；
- tail bit 很少，抽样可靠性测试很难覆盖所有尾部；
- 客户真实写入次数、温度、保存时间和接口配置差异大；
- 传统 pass / fail 不一定捕捉 read margin 的逐步变窄。

---

### 2.2 NAND Flash

NAND Flash 与 NOR 不同。NAND 天然允许坏块和 bit error，产品质量不是追求 raw cell 零错误，而是看坏块管理、ECC、read retry 和 controller 策略是否有足够 margin。

行业经验级判断：

```text
成熟 NAND / SPI NAND 产品：产品级 CP / FT 良率可较高，约 85% - 98%+
高密度、大阵列、多层 cell 或新平台：raw BER、ECC margin 和可靠性波动更大
```

关键矛盾：

> NAND 的核心问题不是有没有 bit error，而是 bit error 是否会在生命周期内逼近 ECC 极限。

较容易提前拦截：

- 初始坏块过多；
- program / erase fail；
- raw BER 明显异常；
- ECC correction count 明显接近上限；
- plane / die 局部 fail。

较难提前拦截：

- 长期 ECC margin 耗尽；
- retention 后 raw BER 增长过快；
- P/E cycling 后 BER growth rate 异常；
- read disturb / program disturb；
- workload 相关热点磨损。

难点：

- 出厂时 ECC 可以兜住，不代表寿命后期仍可兜住；
- 客户 controller、文件系统、写放大、读写热点差异大；
- disturb 是累积效应，ATE 难以复刻真实 workload；
- 出货质量要看 raw BER 分布尾部，而不是只看 final pass。

---

### 2.3 DRAM

DRAM 的失效高度依赖 cell leakage、refresh、timing、温度和访问模式。成熟产品可以达到较高良率，但先进节点、高容量或爬坡阶段波动会更明显。

行业经验级判断：

```text
成熟 DRAM 产品：量产稳定后良率常见可到 85% - 95%+
先进节点、高容量、新产品爬坡：良率和可靠性尾部压力更大
```

关键矛盾：

> DRAM cell 数量巨大，单个 weak cell 的低概率尾部也可能变成产品级风险。

较容易提前拦截：

- 固定 bit / row / column fail；
- 明显 retention fail；
- timing shmoo 明显不足；
- bank fail 集中；
- repair 后仍然 fail 的阵列缺陷。

较难提前拦截：

- weak cell 长尾；
- 高温 retention 边缘；
- refresh interval 边界；
- row hammer / disturb；
- controller 策略相关失效。

难点：

- weak cell 分布稀疏，常规 refresh 下可能不暴露；
- long retention test 成本高；
- row hammer 依赖访问模式，普通测试不一定触发；
- repair / redundancy 让初始良率提高，但不自动消除全部长期尾部。

---

### 2.4 GD32 MCU / 通用 MCU

MCU 通常是成熟逻辑工艺 + embedded Flash + SRAM + 模拟外设。小 die、成熟工艺、稳定测试程序下，量产良率通常较好。

行业经验级判断：

```text
成熟 MCU 产品：CP / FT 良率常见约 90% - 98%+
大容量 eFlash、复杂外设、高温 / 车规等级、新产品爬坡：有效良率更受挑战
```

关键矛盾：

> MCU 的很多失效不是“芯片完全坏”，而是在电源、时钟、软件状态、外设组合和客户板级环境下暴露边界。

较容易提前拦截：

- 明显功能 fail；
- SRAM BIST fail；
- eFlash program / erase fail；
- IO leakage；
- ADC / DAC 参数 out of spec；
- Fmax / Vmin 明显异常。

较难提前拦截：

- 偶发启动失败；
- slow ramp / brown-out / reset 边界问题；
- 低功耗电流异常；
- 外设组合异常；
- embedded Flash 长期 retention / endurance；
- 客户固件触发的状态机边界。

难点：

- MCU 状态空间巨大，ATE 无法覆盖所有固件路径；
- 电源 ramp、boot pin、晶振、reset、外部负载和客户 PCB 差异大；
- 低功耗问题常常是芯片 leakage、IO 状态、外部反灌和软件配置共同作用；
- 外设组合问题经常只有客户真实应用才能暴露。

---

### 2.5 指纹 / 触控传感器

传感器产品要同时看裸 die 良率和模组良率。很多质量问题不是 die 本身单独决定，而是封装、FPC、盖板、贴合、湿度、人体和算法共同决定。

行业经验级判断：

```text
成熟裸 die：良率常见可到 90% - 98%+
模组级良率：可能明显低于裸 die，受材料、装配、校准和应用环境影响更大
```

关键矛盾：

> 传感器质量不是单纯电性 pass，而是 raw signal、SNR、baseline、噪声、环境和算法阈值共同决定体验。

较容易提前拦截：

- dead pixel；
- electrode open / short；
- baseline 明显异常；
- SNR 明显低；
- ESD 后 leakage 明显上升；
- row / column noise 明显异常。

较难提前拦截：

- 湿度 / 汗液 / 污染导致的误触或识别率下降；
- 充电器噪声导致误触；
- 长期灵敏度下降；
- 盖板、贴合、FPC 应力导致的边缘问题；
- 算法阈值与硬件分布耦合问题。

难点：

- 客户使用环境高度复杂；
- 人体、接地、湿度、充电器、盖板材料差异大；
- 模组数据、raw image、算法日志和客诉标签很容易割裂；
- 单纯 wafer CP 很难覆盖真实交互体验。

---

### 2.6 模拟 / 电源芯片

模拟 / 电源芯片常用成熟工艺，die size 不大时制造良率通常较高。但模拟芯片的难点在于参数、温漂、环路稳定和客户外围器件匹配。

行业经验级判断：

```text
成熟模拟 / 电源产品：FT 良率常见约 90% - 99%+
高压、大电流、功率密度高、车规等级或新封装产品：可靠性和参数分布压力更大
```

关键矛盾：

> 模拟 / 电源芯片经常不是功能坏，而是在极限负载、温度、外围器件和板级布局下参数漂移或不稳定。

较容易提前拦截：

- 输出电压 out of spec；
- current limit 明显异常；
- Iq 明显偏高；
- line / load regulation fail；
- 保护功能 fail；
- trim 后仍然超差。

较难提前拦截：

- 极限负载 / 外围器件组合下振荡；
- 长期温漂；
- HTOL 后小幅漂移；
- 封装热阻与客户散热条件耦合；
- 负载瞬态边界；
- EMI / layout 相关问题。

难点：

- FT 无法覆盖所有电容、电感、ESR、PCB layout 和负载组合；
- 环路稳定是系统级问题，不是单颗芯片参数就能完全决定；
- trim code、bandgap、bias、opamp、功率管和封装热特性相互耦合；
- 很多问题需要客户板级复现。

## 3. 最难提前拦截的 8 类失效

### 3.1 Spec 内边缘品 / Out-of-family 产品

表现：

```text
单项测试都 pass
但多个参数同时偏向边界
```

例子：

```text
Vmin 偏高
+ Fmax 偏低
+ leakage tail 偏厚
+ sleep current 偏高
+ wafer edge location
```

难点：

- 传统测试按单项 limit 判定；
- 单项参数正常，组合风险异常；
- 需要历史族群建模；
- 需要把 WAT、CP、FT、reliability 和 RMA 串起来。

这是最适合数据挖掘切入的问题之一。

---

### 3.2 长期可靠性退化

典型包括：

- Flash retention；
- Flash endurance；
- DRAM retention；
- TDDB；
- BTI；
- HCI；
- EM；
- 封装热疲劳。

难点：

- 出厂时是好的；
- 短测也能过；
- 真实寿命可能是几年；
- 加速模型与真实使用之间存在误差；
- 可靠性测试通常只能抽样。

数据挖掘可以做的是：

> 不直接预测完整寿命，而是识别“应力前后退化速度明显大于正常族群”的 lot / wafer / die。

---

### 3.3 应用相关失效

典型场景：

- 客户电源 ramp 很慢；
- 电源纹波大；
- SPI / QSPI 线长、SI 差；
- MCU 外设反灌；
- 电源芯片外围电容 ESR 不匹配；
- 触控芯片在充电器噪声下误触。

难点：

- 芯片厂测试环境不等于客户真实系统；
- ATE / FT 无法完整模拟客户板级条件；
- 失效依赖芯片、PCB、软件、环境和用户行为组合；
- 数据标签往往来自 RMA，严重滞后。

数据挖掘适合做关联和分群，但不能完全替代系统级实验。

---

### 3.4 偶发性 / 间歇性失效

表现：

- 1000 次上电失败 1 次；
- 高温运行数小时后死机；
- 冷热循环后偶发恢复；
- 按压板子时好时坏；
- 客户现场偶发，实验室难复现。

难点：

- 复现成本高；
- ATE 时间有限；
- 样品到 FA 时可能已经恢复；
- retest 可能掩盖风险；
- 需要事件触发日志和长时间监控。

数据挖掘适合关注：

- first fail final pass；
- retest count；
- tester / site correlation；
- temperature corner sensitivity；
- power cycle fail rate；
- RMA 场景聚类。

---

### 3.5 ESD / EOS / Latch-up

表现：

- 突然死亡；
- IO leakage；
- 电源对地低阻；
- 单 pin 异常；
- 热点；
- 金属烧蚀。

难点：

- 出厂测试通常正常；
- 客户现场过应力瞬间发生；
- 物理痕迹可能被损伤过程破坏；
- ESD 和 EOS 证据有时相似；
- 系统级浪涌路径复杂。

数据挖掘能辅助：

- RMA failure signature 聚类；
- pin-level leakage pattern；
- 客户 / 应用 / 板级保护方案关联；
- lot / package / IO cell revision 风险对比。

但根因确认仍高度依赖 FA 和系统级复现。

---

### 3.6 图像弱异常 / 形貌边缘异常

典型包括：

- CD-SEM 边缘粗糙稍大；
- contact hole 形貌轻微异常；
- wafer map 有微弱 radial gradient；
- X-ray void 没超标但区域集中；
- SAM 有轻微分层迹象；
- sensor raw image 有轻微 row / column noise。

难点：

- 人工 review 主观性强；
- 图像异常不一定立刻对应 CP fail；
- 标注少；
- 需要和参数、空间位置、下游测试结果叠加。

这是中长期很适合数据挖掘和多模态模型的方向。

---

### 3.7 测试覆盖不足导致的逃逸

例子：

- MCU 某外设组合异常；
- DMA + sleep + interrupt 组合死锁；
- ADC 在特定源阻抗下漂移；
- 电源芯片某 ESR 下振荡；
- 传感器在湿手 + 充电器噪声下误触。

难点：

- 组合空间巨大；
- ATE 时间昂贵；
- 应用条件难在 FT 完整模拟；
- 软件状态空间大；
- 不同客户使用方式差异大。

数据挖掘可以帮助从 RMA 和客户日志里反推测试覆盖缺口。

---

### 3.8 低概率随机缺陷

典型来源：

- random particle；
- via / contact latent defect；
- 局部微裂纹；
- rare weak bit；
- soft error；
- 极少数封装微缺陷。

难点：

- 基率极低；
- 抽样测试覆盖不到；
- 大多数 lot 数据看起来正常；
- 只有出货量上去后才显现；
- 容易表现为 ppm 级客诉。

数据挖掘适合做 rare event monitoring 和 Bayesian risk update，但不能指望零漏检。

---

## 4. 数据挖掘优先级评估方法

不是所有问题都适合优先上模型。优先级要看 6 个维度。

| 维度 | 问题 |
|---|---|
| 业务影响 | 这个问题一旦漏出，是否会造成大规模 RMA、客户停线、品牌损伤？ |
| 数据可得性 | WAT / CP / FT / reliability / RMA 数据是否可规模化拿到？ |
| 信号强度 | 异常是否能在数据里形成稳定 pattern，而不是纯随机噪声？ |
| 可行动性 | 模型发现风险后，工程上能否 hold、加测、降级、guardband 或反馈供应链？ |
| 标签成熟度 | 是否有可靠 fail label、RMA label、retest label、FA label？ |
| 建模难度 | 是否需要难以获取的物理机理、长周期寿命或复杂系统实验？ |

可以用一个简单的优先级公式：

```text
PriorityScore
  = 0.25 * BusinessImpact
  + 0.20 * DataReadiness
  + 0.20 * SignalStrength
  + 0.20 * Actionability
  + 0.15 * LabelMaturity
  - 0.15 * ModelingRisk
```

评分不必一开始追求精确，关键是避免两个误区：

- 只因为问题重要，就马上上复杂模型；
- 只因为数据多，就忽略工程动作和业务影响。

更合理的判断是：

> 优先做“数据能拿到、信号能看见、发现后能行动、漏检代价高”的问题。

## 5. 最适合数据挖掘优先攻克的问题

### 5.1 P0：多参数 Out-of-family / Maverick 检测

优先级：最高。

适用产品：全部产品线。

可用数据：

- WAT；
- CP；
- FT；
- wafer map；
- tester / site；
- reliability delta；
- RMA 追溯。

核心特征：

```text
robust z-score
Mahalanobis distance
PCA residual
Isolation Forest score
multi-parameter tail count
distance to historical normal family
```

为什么优先：

- 数据通常最容易规模化获取；
- 直接针对 spec 内边缘品；
- 可解释性相对好；
- 工程动作明确：hold lot、加严 guardband、追加测试、分 bin、降级出货；
- 适合先做 MVP。

典型例子：

```text
MCU：Vmin 偏高 + Fmax 偏低 + sleep current 偏高 + RO 偏慢
NOR：read margin p01 变差 + erase time p99 变长 + retention delta 增大
Analog：trim code 靠边 + tempco 偏大 + Iq tail 偏厚
Sensor：baseline sigma 偏大 + noise floor 上升 + SNR p01 降低
```

---

### 5.2 P0：Wafer map / Bin map 空间 pattern 识别

优先级：最高。

适用产品：全部产品线，尤其适合存储、MCU、传感器。

可用数据：

- die 坐标；
- CP bin；
- 参数 map；
- wafer id；
- reticle 坐标；
- lot / fab / tool genealogy。

核心特征：

```text
edge ring score
radial slope
cluster score
reticle repeat score
scratch line score
half-wafer score
Moran's I
connected component count
local fail density
```

为什么优先：

- 空间 pattern 对制程和设备根因指向强；
- 比单看总良率更早发现 maverick wafer；
- 可解释性强，工程师容易接受；
- 与 fab / chamber / reticle 反馈动作直接相关。

典型动作：

- hold wafer / lot；
- 追加邻近 die 测试；
- 反馈代工厂查 tool / chamber；
- 对 edge / cluster 区域降级或剔除。

---

### 5.3 P0：Retest-pass unit 风险识别

优先级：最高。

适用产品：全部产品线，尤其适合 MCU、模拟、电源、传感器和高速接口产品。

可用数据：

- first pass bin；
- retest bin；
- retest count；
- tester id；
- site id；
- temperature；
- contact event；
- final disposition。

核心特征：

```text
first_fail_final_pass_flag
retest_count
same_bin_recovery_rate
site_specific_retest_rate
temperature_corner_recovery_pattern
wafer_location_retest_density
```

为什么优先：

- first fail final pass 往往是边缘品信号；
- 数据成本低；
- 工程动作明确；
- 对偶发性和间歇性失效有很强指示价值。

典型动作：

- retest-pass unit 单独打标；
- 加严 guardband；
- 对高风险 bin 增加 stress；
- 禁止部分高可靠客户使用；
- 追查 tester / probe / socket / site 问题。

---

### 5.4 P0 / P1：Stress delta 退化监控

优先级：高。

适用产品：存储、MCU embedded Flash、DRAM、模拟 / 电源、传感器。

可用数据：

- stress 前参数；
- stress 后参数；
- HTOL；
- HAST；
- TC；
- P/E；
- bake；
- ESD 前后 leakage。

核心特征：

```text
AbsoluteDelta
RelativeDelta
NormalizedDelta
DegradationRate
DeltaZ
post_stress_tail_count
before_after_rank_shift
```

为什么优先：

- 长期可靠性难直接预测，但退化速度可以监控；
- 对 retention、endurance、leakage、温漂、封装应力都有效；
- 能把“当前 pass 但退化快”的风险样品筛出来。

限制：

- 可靠性样本量通常小；
- 测试周期长；
- 标签滞后；
- 需要和产品机理结合，不能纯黑盒。

---

### 5.5 P0 / P1：存储类 Margin 尾部建模

优先级：高。

适用产品：NOR Flash、NAND Flash、DRAM、MCU embedded Flash。

可用数据：

- read margin；
- program / erase time；
- erase count；
- verify fail count；
- raw BER；
- ECC correction count；
- read retry shift；
- retention bake 前后；
- P/E cycling 前后；
- weak bit count。

核心特征：

```text
p01 / p99 margin
BER growth rate
ECC tail ratio
read retry shift distribution
erase_time_p99
program_time_p99
retention_delta_BER
weak_bit_tail_count
```

为什么优先：

- 存储产品的现场质量高度依赖尾部 margin；
- 数据天然结构化，适合统计建模；
- 和工程动作对应清晰：guardband、坏块管理、ECC 策略、降级、加测。

典型产品映射：

| 产品 | 优先特征 |
|---|---|
| NOR | read margin、erase / program time tail、retention bake delta、read disturb delta |
| NAND | raw BER、ECC count、read retry、P/E 后 BER growth、bad block growth |
| DRAM | weak bit count、retention p01、refresh margin、row hammer victim flip |
| MCU eFlash | program / erase time、retention CRC、code fetch Vmin、boot margin |

---

### 5.6 P1：RMA / 客诉反向标注与根因聚类

优先级：高，但需要数据治理配合。

适用产品：全部产品线。

可用数据：

- RMA failure mode；
- 客户应用场景；
- lot / wafer / die 追溯；
- CP / FT 原始参数；
- reliability 记录；
- FA 结论；
- firmware / board / module 信息。

核心特征：

```text
RMA mode cluster
customer application cluster
lot-level RMA lift
wafer-level RMA lift
feature combination lift
FA-confirmed label
field symptom embedding
```

为什么优先：

- 真正校准模型的是现场失败；
- 可以反向发现测试覆盖缺口；
- 能把“模型报警”从统计异常提升为质量风险。

限制：

- 标签滞后；
- 样本少；
- 失效描述不标准；
- 客户侧条件不完整；
- FA 成本高。

所以它适合作为 P1，而不是第一个 MVP 的唯一抓手。

---

## 6. 中期值得做，但不适合作为第一优先级的问题

### 6.1 P1：图像 + 参数多模态异常识别

适用数据：

- defect inspection image；
- CD-SEM；
- wafer map；
- X-ray；
- SAM；
- sensor raw image；
- CP / FT 参数；
- reliability 结果。

价值：

- 能识别弱形貌异常；
- 能把视觉缺陷和电性结果关联；
- 对传感器、封装、光刻、阵列类问题有价值。

为什么不是最先做：

- 图像数据治理难；
- 标注少；
- 不同设备图像分布差异大；
- 纯图像异常不一定等于质量风险；
- 需要工程师反馈闭环。

更合理路径：

```text
先做 wafer map / 参数 map
再做 defect-to-die overlay
最后做 image embedding + 多模态风险模型
```

---

### 6.2 P1 / P2：应用场景失效预测

适用问题：

- MCU 偶发启动；
- QSPI 高速边界；
- 电源芯片外围组合振荡；
- 传感器湿度 / 充电噪声误触。

价值：

- 贴近客户真实问题；
- 对产品竞争力和客户体验影响大。

为什么难：

- 客户数据不完整；
- 系统变量太多；
- ATE 数据与现场场景之间缺桥；
- 标签严重滞后；
- 很多问题需要实验平台复现。

适合方法：

- 客户场景聚类；
- application profile mining；
- system-level shmoo；
- RMA symptom embedding；
- lab reproduction result tracking。

---

### 6.3 P2：ESD / EOS 责任归因模型

价值很高，但不适合作为早期纯数据挖掘项目。

原因：

- 出厂数据往往正常；
- 损伤发生在客户现场；
- 需要 FA 证据；
- 需要板级保护设计信息；
- ESD / EOS 痕迹有时相似。

更合理的目标不是“自动判责”，而是：

```text
RMA signature 聚类
+ pin leakage pattern
+ 客户应用场景
+ FA 证据
+ 板级保护方案
=> 给出可能性排序
```

---

### 6.4 P2：完整寿命预测

很多团队容易一上来就想做“预测芯片寿命”。这通常不是最好的第一目标。

原因：

- 真实寿命长；
- 加速模型假设复杂；
- 可靠性样本量小；
- 现场标签滞后；
- 使用场景差异大。

更好的阶段性目标是：

- 预测退化速度异常；
- 识别 stress delta outlier；
- 建立 lot / wafer 风险排序；
- 把风险样品送入更多可靠性验证。

---

## 7. 按产品线的数据挖掘优先级

### 7.1 NOR Flash

P0：

- read margin tail；
- erase / program time p99；
- retention bake delta；
- P/E 后参数退化；
- wafer map pattern；
- retest-pass unit。

P1：

- read disturb / program disturb 风险；
- 高速 QSPI margin 与客户场景关联；
- embedded Flash boot / code fetch 边界。

P2：

- 长周期真实保存寿命精确预测。

优先原因：

> NOR 的关键不是初始能不能读写，而是 read margin 是否在长期保持、擦写和客户高速接口条件下仍有足够余量。

---

### 7.2 NAND Flash

P0：

- raw BER distribution；
- ECC correction count tail；
- read retry shift；
- bad block growth；
- P/E cycling BER growth；
- retention 后 BER delta。

P1：

- workload 相关 disturb；
- controller 策略关联；
- block / page / plane 级空间 pattern。

P2：

- 跨客户 workload 的通用寿命预测。

优先原因：

> NAND 的产品质量本质是 ECC margin 管理，数据挖掘最应该盯住 tail BER 和 margin 消耗速度。

---

### 7.3 DRAM

P0：

- weak bit count；
- retention time p01；
- high-temp retention fail；
- timing pass area；
- row / column / bank fail pattern；
- wafer map pattern。

P1：

- row hammer victim flip；
- refresh interval sensitivity；
- repair 后剩余风险；
- controller 策略相关风险。

P2：

- 真实客户 workload 下的长期 fail 概率预测。

优先原因：

> DRAM 的风险集中在 weak cell 长尾和访问模式相关 disturb，最适合先做 retention / weak bit / timing / 空间 pattern 的组合预警。

---

### 7.4 GD32 MCU

P0：

- WAT + CP + FT 多参数 out-of-family；
- Vmin / Fmax / RO / leakage 组合；
- eFlash program / erase time tail；
- SRAM BIST / Vmin；
- sleep current p99；
- retest-pass unit。

P1：

- POR / BOR / slow ramp 风险；
- oscillator startup tail；
- PLL lock time tail；
- low-power wakeup 场景；
- 外设组合异常的 RMA 反向挖掘。

P2：

- 任意客户固件状态空间的通用预测。

优先原因：

> MCU 数据挖掘第一步不该追求“理解所有软件问题”，而要先抓硬件边缘品、eFlash 尾部、低功耗尾部和 retest-pass 风险。

---

### 7.5 指纹 / 触控传感器

P0：

- baseline mean / sigma；
- noise floor；
- SNR p01；
- dead pixel / row / column noise；
- humidity drift；
- charger noise sensitivity；
- 模组校准参数异常。

P1：

- raw image embedding；
- 盖板 / FPC / 贴合参数关联；
- 客户误触 / 识别失败日志聚类；
- image + parameter 多模态风险模型。

P2：

- 复杂人体行为和真实环境下的体验预测。

优先原因：

> 传感器最值得挖的是 raw signal 和环境 stress 后的漂移，而不是只看最终 pass / fail。

---

### 7.6 模拟 / 电源芯片

P0：

- trim code 分布；
- bandgap / reference 偏移；
- tempco；
- Iq tail；
- current limit 分布；
- line / load regulation；
- HTOL 后参数 delta；
- retest-pass unit。

P1：

- load transient overshoot / settling；
- phase margin proxy；
- dropout / thermal behavior；
- 客户外围器件组合关联。

P2：

- 任意 PCB layout 和外围器件组合下的稳定性预测。

优先原因：

> 模拟 / 电源产品最适合先挖参数分布、trim 边界、温漂和应力 delta，再逐步扩展到系统级稳定性。

---

## 8. 数据挖掘项目优先级总表

| 优先级 | 方向 | 适合程度 | 主要原因 | 主要限制 |
|---|---|---:|---|---|
| P0 | 多参数 out-of-family | 极高 | 数据结构化、信号强、动作明确 | 需要统一历史基线 |
| P0 | Wafer map / bin map pattern | 极高 | 空间异常指向制程根因 | 需要坐标和 genealogy 对齐 |
| P0 | Retest-pass unit 风险 | 极高 | 成本低、对偶发边缘品敏感 | 要区分接触问题和真实芯片风险 |
| P0 / P1 | 存储 margin 尾部 | 高 | 直接关联 retention、ECC、endurance | 需要产品机理和 stress 数据 |
| P0 / P1 | Stress delta 退化 | 高 | 能识别当前 pass 但退化快的样品 | 样本少、周期长 |
| P1 | RMA 反向标注 | 高 | 最贴近现场真实风险 | 标签滞后、数据脏 |
| P1 | 图像 + 参数多模态 | 中高 | 可发现弱形貌和空间异常 | 标注难、治理难 |
| P1 / P2 | 应用场景失效预测 | 中 | 贴近客户价值 | 系统变量多、复现难 |
| P2 | ESD / EOS 归因 | 中 | RMA 价值高 | 依赖 FA 和板级证据 |
| P2 | 完整寿命预测 | 中 | 长期价值高 | 标签周期长、外推难 |

一句话排序：

```text
先做结构化数据里的异常族群和空间 pattern，
再做应力退化和 RMA 反向闭环，
最后做图像多模态、应用场景和寿命预测。
```

## 9. 推荐 MVP 路线

### Phase 1：先抓最有性价比的 P0

目标：3 个月内做出可用的质量风险看板。

范围：

- WAT / CP / FT 参数统一；
- die / wafer / lot / product key 对齐；
- 多参数 out-of-family score；
- wafer map pattern score；
- retest-pass risk score；
- 存储 margin tail score。

输出：

```text
DieRiskScore
WaferRiskScore
LotRiskScore
RiskReason
RecommendedAction
```

典型动作：

- R1：观察；
- R2：追加测试；
- R3：hold lot；
- R4：停出 / 反馈供应链。

---

### Phase 2：引入 stress delta 和可靠性闭环

目标：把“当前 pass”进一步升级为“未来风险排序”。

范围：

- HTOL delta；
- HAST delta；
- TC delta；
- retention bake delta；
- P/E cycling delta；
- ESD 前后 leakage delta。

输出：

- degradation score；
- stress sensitivity score；
- lot reliability risk ranking；
- guardband adjustment suggestion。

---

### Phase 3：接入 RMA、图像和客户场景

目标：用现场失败校准前端预警。

范围：

- RMA failure mode 标准化；
- FA 结论结构化；
- 客户场景标签；
- image embedding；
- defect-to-die overlay；
- RMA lift analysis。

输出：

- escaped failure pattern；
- test coverage gap；
- RMA-driven feature importance；
- new screen recommendation。

---

## 10. 质量工程上的最终判断

良率高，不代表质量风险低；良率低，也不一定说明产品不可控。真正要看：

```text
良率损失来自哪里？
是否集中在某些 wafer / lot / tool / chamber / reticle / tester / site？
pass 的产品里有没有 out-of-family？
应力后是否退化快？
RMA 是否能追溯到出货前的弱信号？
```

对于兆易创新这类产品组合，数据挖掘最有价值的切入点不是泛泛地预测“会不会坏”，而是把质量风险拆成可行动的问题：

- 哪些 lot 虽然 pass，但不像正常族群；
- 哪些 wafer 有空间 pattern；
- 哪些 die 是 retest-pass 边缘品；
- 哪些存储阵列 margin 正在变薄；
- 哪些样品 stress 后退化过快；
- 哪些 RMA 能在出货前数据里找到共同弱信号。

一句话收束：

> 芯片良率管理的下一步，不是把 pass / fail 表格做得更漂亮，而是把 spec 内边缘品、空间异常、退化速度和现场失败反向串起来，形成能 hold、加测、降级、反馈供应链的质量风险决策系统。
