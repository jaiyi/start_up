# Ideas · 应用点子池

> 内部讨论稿，持续迭代。用途：沉淀我们在 AI、智能制造、企业转型、个人效率和行业产品化中的应用点子。
>
> 这里先放**尚未成型的应用想法**；一旦某个点子进入深入论证，再拆成独立文档。

---

## 1. 这个目录放什么

`docs/ideas/` 用来存放三类内容：

| 类型 | 含义 | 例子 |
|---|---|---|
| **应用点子** | 可以做成产品、工具、agent、服务或内部平台的想法 | Agent 广场、企业 AI 控制面、面试研究助手 |
| **场景假设** | 还没验证，但可能有需求密度和商业价值的场景 | 质量异常作战群、排产 Copilot、供应链风险预警 |
| **产品化线索** | 从公司研究、行业洞察、个人痛点里长出来的可产品化方向 | 从 `05-01` 的 AI 控制面拆出企业 agent marketplace |

不放：

- 已经比较成熟的行业判断：放 `../insights/`；
- 单家公司事实研究：放 `../companies/`；
- 已经成体系的产品分析：放 `../product-analysis/`；
- 简历、面试、证书等个人材料：仍放原目录。

## 2. 点子记录模板

每个点子先按这个最小模板记录，避免只剩一句灵感：

```markdown
## 点子名

**一句话**：这个点子解决什么问题？

**目标用户**：谁会高频使用？谁愿意付费 / 背指标？

**痛点**：现在为什么痛？不用它会怎样？

**场景入口**：用户会从哪里进入？网页、飞书、钉钉、企微、IDE、浏览器插件、企业系统？

**核心能力**：
- 能力 1
- 能力 2
- 能力 3

**数据 / 知识需求**：需要哪些数据、文档、系统接口或 ontology？

**反馈闭环**：用户如何采纳、驳回、修正？结果如何回流？

**价值指标**：效率、成本、收入、风险、质量、转化率、EVI 等怎么衡量？

**产品形态**：agent、平台、插件、工作流、咨询交付、SaaS、内部工具？

**风险 / 难点**：权限、数据、合规、冷启动、集成、销售、替代方案。

**下一步验证**：最小验证动作是什么？访谈、原型、数据样本、竞品研究、Demo？
```

## 3. 初始分类

### 3.1 企业 AI 控制面 / Agent 平台

从 `../insights/05-01-大企业AI转型的杠铃结构落地路径.md` 延伸出来的方向：

- Agent Developer Portal：给业务开发者 / 开发型 agent 的 Context Pack 与开发规范；
- Agent 广场 / Marketplace：产品级 agent 的发现、试用、调用、雇佣和内部结算；
- Model Gateway：统一模型 / token 接入、成本、路由、脱敏和审计；
- Knowledge Gateway：企业知识访问层，不只是向量库；
- Ontology / Semantic Layer：从黑洞场景长出的轻量业务语义层；
- Channel Adapter：接入钉钉、企业微信、飞书、邮件、会议和工单系统。

### 3.2 智能制造黑洞场景

围绕供应链、排产、生产良率三类场景继续拆：

- 质量异常作战群 Agent；
- 生产良率根因诊断 Agent；
- 排产约束解释 / 排产冲突 Copilot；
- 关键物料缺料风险预警；
- 供应商质量风险飞轮；
- 工艺参数变更审核 Agent。

### 3.3 个人职业 / 面试 / 研究助手

围绕当前择业、公司研究和面试准备：

- 公司研究自动化助手；
- 面试弹药生成器；
- 职位 JD 与个人资产匹配器；
- 行业洞察卡片库；
- 简历故事线重写 Agent。

### 3.4 中小企业托管 AI 能力

从 `../insights/05-02-中小企业AI转型：托管杠铃与数据主权.md` 延伸：

- 中小制造企业 AI 托管运营包；
- 数据主权合同检查器；
- schema / 退出权审查工具；
- 轻量质量 / 排产 / 供应链托管 agent；
- 行业协会数据主权模板。

### 3.5 家庭消费 AI / 生活 Agent

围绕家庭健康、饮食、采购、厨房执行、长期偏好记忆和家庭财务管理：

- 家庭营养师 Agent：把健康饮食建议落到菜单、采购、做饭和反馈闭环；
- 厨房免手操作 Agent：语音优先、视觉辅助的做饭现场交互；
- 家庭采购与成本 Agent：从 shopping list 升级到选品、渠道拆单、下单和饮食记账；
- 家庭财务管理 Agent：把家庭收入、支出、资产、负债、预算、风险和长期目标统一成家庭 CFO。

## 4. 点子成熟度

| 阶段 | 含义 | 下一步 |
|---|---|---|
| **Seed** | 只有一句灵感或痛点 | 补齐模板 |
| **Sketch** | 已有用户、场景、能力草图 | 找 3 个真实案例验证 |
| **Validated** | 痛点和使用入口被初步验证 | 做原型或 Demo |
| **Prototype** | 有可演示版本 | 找真实用户试用 |
| **Product Thesis** | 已能讲清市场、壁垒、商业模式 | 拆成独立产品文档 |

## 6. 使用规则

1. 新点子先追加到“当前候选点子”。
2. 如果 3 次以上反复讨论同一个点子，就拆成独立文档。
3. 独立文档命名建议：`NN-点子名.md`。
4. 每个点子都必须逐步补齐：目标用户、痛点、入口、数据需求、反馈闭环、价值指标。
5. 优先沉淀能连接 `insights/` 主线判断的点子，尤其是：反馈闭环、数据主权、EVI、AI 控制面、智能制造黑洞场景。
