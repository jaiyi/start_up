# 反馈更新规则

> 用于把每餐反馈转成可积累的家庭饮食记忆。

---

## 1. 反馈入口

用户可以通过微信自然语言反馈：

```text
今天宝宝很爱吃这个丸子，但是老人觉得有点淡。
这道菜阿姨做起来有点麻烦。
这个鱼复热后有点腥。
爸爸觉得这个早餐蛋白质够，但太干。
```

Agent 需要抽取：

- 菜品；
- 餐次；
- 谁吃了；
- 谁喜欢 / 不喜欢；
- 宝宝接受度；
- 老人接受度；
- 成人接受度；
- 执行难度；
- 复热表现；
- 口味问题；
- 颗粒度问题；
- 是否愿意复吃；
- 下次改法。

---

## 2. 反馈影响范围

每次反馈后，Agent 应考虑更新：

- `meals/meal-feedback-log.md`；
- 对应 `recipes/*.md` 的历史反馈；
- `family/member-preferences.md` 的长期偏好；
- `inventory/current-inventory.md` 的主要消耗；
- 菜谱的 `recommendation_weight`；
- 菜谱的宝宝版 / 成人老人共用版注意事项。

---

## 3. 权重调整规则

### 3.1 上调权重

以下情况可以上调：

- 宝宝吃得好；
- 老人接受度高；
- 爸爸妈妈觉得适合早餐或周末；
- 阿姨执行顺利；
- 食材容易买；
- 和库存匹配好；
- 复热后表现好；
- 高蛋白、少油目标达成。

### 3.2 下调权重

以下情况应下调：

- 宝宝不接受；
- 颗粒度不合适；
- 老人觉得太咸、太油、太甜；
- 姥爷控糖不友好；
- 阿姨执行困难；
- 复热后口感差；
- 食材难买；
- 做法太复杂；
- 清洁成本太高。

### 3.3 不直接淘汰的情况

以下情况优先修改做法，不直接淘汰：

- 食材适合但火候失败；
- 宝宝口感不适但味道接受；
- 成人觉得淡但宝宝适合；
- 老人适合但年轻人觉得不够香；
- 阿姨第一次执行不熟练。

---

## 4. 宝宝反馈处理

宝宝反馈重点记录：

- 吃了多少；
- 是否吐出；
- 是否咀嚼困难；
- 是否喜欢；
- 是否出现过敏或嘴周红；
- 颗粒度是否合适；
- 是否便于喂食或自主进食。

宝宝反馈更新规则：

- 出现过敏反应必须标记为安全提醒，不能只作为口味反馈；
- 香蕉嘴周红已记录，默认谨慎 / 避免；
- 新食材首次尝试要单独记录；
- 颗粒度不适合时，优先调整切法、软烂程度和形态。

---

## 5. 老人反馈处理

老人反馈重点记录：

- 是否太咸；
- 是否太油；
- 是否太甜；
- 是否复热后好吃；
- 是否适合姥爷控糖 / 高血压；
- 是否适合奶奶高血糖风险；
- 是否有牙口或消化问题。

---

## 6. 阿姨执行反馈

阿姨执行反馈重点记录：

- 小红书链接是否清楚；
- 步骤是否容易执行；
- 是否需要更明确的宝宝版 / 成人老人共用版分离说明；
- 是否需要提前备菜；
- 是否耗时过长；
- 是否清洁成本高；
- 是否适合工作日午餐。

---

## 7. 反馈记录模板

```markdown
## YYYY-MM-DD 餐次：菜名

原始反馈：

> 用户原话

结构化记录：

| 维度 | 结果 |
|---|---|
| 宝宝接受度 | 高 / 中 / 低 / 未吃 |
| 成人接受度 | 高 / 中 / 低 / 未吃 |
| 老人接受度 | 高 / 中 / 低 / 未吃 |
| 执行难度 | 低 / 中 / 高 |
| 复热表现 | 好 / 一般 / 差 / 不适用 |
| 问题 | 具体问题 |
| 下次调整 | 具体调整 |
| 推荐权重变化 | 上调 / 不变 / 下调 |
```
