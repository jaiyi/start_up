# 家庭营养师 Agent：把营养建议落到餐桌上

> 内部讨论稿，持续迭代。当前阶段：Sketch。
>
> 核心判断：家庭不缺营养建议，缺的是把营养建议落到每天三餐的执行系统。

---

## 0. 产品定义

**家庭营养师 Agent**：一个能把“健康饮食建议”落地到每天三餐的家庭饮食执行系统。它理解家庭成员的营养目标、口味偏好、忌口、时间预算和冰箱库存，自动规划菜单，完成食材选品、shopping list、渠道下单与饮食记账，并通过摄像头和语音在厨房一步步指导做饭、记录反馈、持续优化。

核心 slogan：

> **让营养建议真正落到餐桌上。**

扩展表达：

> 它不只是告诉你吃什么，还帮你买对、做对、吃对，并持续优化你家的饮食结构和食材成本。

更商业化的表达：

> 把家庭营养师从“一次性咨询服务”升级成“持续在线的家庭饮食操作系统”。

---

## 1. 核心判断：家庭不缺营养建议，缺饮食执行系统

家庭饮食管理的难点，不在于“不知道什么健康”，而在于：

```text
知道健康原则
但不知道今天吃什么
知道要营养均衡
但不知道怎么买、买多少、怎么搭配
请了营养师
但方案无法进入每天的采购和做饭现场
家里有人做饭
但没人管理目标、标准、反馈和复盘
```

所以这个产品不是解决“知识供给”，而是解决**家庭健康饮食的执行落地**。

它要完成的链条是：

```text
营养建议
→ 菜单计划
→ 食材采购
→ 厨房执行
→ 用餐反馈
→ 长期优化
```

## 2. 请得起家庭营养师的家庭，真正买的是什么

| 家庭类型 | 支付能力 / 家庭状态 | 为什么会请营养师 | 他们真正买的不是 | 他们真正买的是 |
|---|---|---|---|---|
| 高收入核心家庭 | 年收入较高，有稳定健康消费预算 | 想系统管理全家饮食、体重、慢病、孩子成长、老人健康 | 菜谱、营养知识、热量表 | 专业判断 + 长期陪伴 + 家庭健康确定性 |
| 有孩子的中高收入家庭 | 90 后 / 95 后父母，育儿焦虑强 | 担心孩子挑食、营养不均衡、长高、免疫力、学习精力 | 儿童餐推荐 | 降低养育焦虑，让孩子每顿吃得更可控 |
| 有老人 / 慢病成员的家庭 | 家庭里有控糖、控脂、高血压、术后恢复等需求 | 饮食直接影响健康风险，但家人执行困难 | 通用健康建议 | 把医疗 / 营养要求转成家庭可执行菜单 |
| 有阿姨 / 私厨 / 月嫂的家庭 | 已经有人负责做饭，但缺统一标准 | 营养目标、家庭偏好、执行者之间信息断裂 | 找一个会做饭的人 | 让执行者按家庭健康目标稳定交付 |
| 健身 / 减脂 / 身材管理家庭 | 有明确身体目标，愿意为结果付费 | 想控制热量、蛋白质、碳水、外食和饮食节奏 | 单次饮食计划 | 持续监督、反馈和调整，确保结果发生 |
| 精英工作人群家庭 | 忙、时间贵、决策成本高 | 不想每天想吃什么、买什么、怎么搭配 | 省钱 | 省心、省决策、提高生活质量 |

结论：

> 请得起家庭营养师的家庭，买的不是“营养知识”，而是家庭健康管理的确定性：有人理解家庭成员，有人制定计划，有人持续监督，有人把目标落到每天三餐。

## 3. 为什么只请一个营养师仍然不够

| 环节 | 传统营养师能做什么 | 真正落地时的问题 | 家庭营养师 Agent 可以补什么 |
|---|---|---|---|
| 评估 | 根据身高体重、疾病、目标做饮食建议 | 评估是周期性的，不知道每天实际吃了什么 | 持续记录家庭饮食、库存、偏好和反馈 |
| 制定方案 | 给一周菜单、营养原则、忌口建议 | 菜单和真实库存、时间、厨艺、口味经常脱节 | 根据冰箱库存、做饭能力和时间动态调整 |
| 采购 | 可能给采购建议 | 谁买、买多少、怎么买、买回来怎么用，没人管 | 自动生成 shopping list，并和菜单 / 库存联动 |
| 做饭 | 通常不在现场 | 阿姨 / 家人不会做、做错、油盐控制不了、步骤执行不到位 | 通过摄像头和语音在厨房实时指导 |
| 口味适配 | 能给原则，但很难细致记住每个人偏好 | 孩子不吃、老人嫌淡、伴侣不喜欢，方案就失败 | 记住每个家庭成员的口味和接受度 |
| 执行监督 | 靠用户自觉打卡 | 大多数家庭无法长期记录和坚持 | 自动化记录、提醒、复盘，降低执行负担 |
| 反馈优化 | 周期性复盘 | 反馈滞后，无法根据每顿饭快速调整 | 每顿饭形成反馈，持续优化下一餐 |
| 家庭协同 | 主要面对付费决策者 | 决策者、采购者、做饭者、吃饭者不是同一个人 | 把家庭饮食链条上的不同角色连接起来 |

结论：

> 传统营养师解决的是“应该怎么吃”，但家庭真正困难的是“每天怎么做到”。家庭营养师 Agent 的价值，是把营养建议嵌入采购、库存、烹饪、监督和反馈流程，让方案不止停留在纸面上。

## 4. 目标用户与切入顺序

这个产品表面上是“给家庭做饭 / 营养搭配”，但真正付费的人群不应该一开始泛化到所有家庭。第一批用户应该满足几个条件：

1. 对饮食健康有明确焦虑或目标；
2. 愿意为家庭健康、省心、专业感付费；
3. 家庭饮食链条已经有一定复杂度；
4. 存在“建议无法落地”的痛点；
5. 有机会形成高频使用和长期留存。

### 4.1 第一优先级：有阿姨 / 私厨 / 月嫂 / 育儿嫂的中高收入家庭

| 维度 | 内容 |
|---|---|
| 家庭状态 | 有人负责做饭，但缺饮食管理标准 |
| 核心问题 | 决策者、采购者、做饭者、吃饭者不是同一个人 |
| 典型矛盾 | 父母想要健康，营养师给了建议，阿姨不知道怎么稳定执行 |
| 付费能力 | 高 |
| 产品价值 | 让家庭饮食服务可计划、可执行、可监督、可复盘 |
| 核心卖点 | 让阿姨 / 私厨按你家的健康目标稳定交付 |

这类家庭最符合“建议不落地”的痛点：不是没人做饭，而是没人管理“怎么按目标做饭”。

### 4.2 第二优先级：有孩子的中高收入年轻家庭

| 维度 | 内容 |
|---|---|
| 家庭状态 | 90 后 / 95 后父母，有育儿焦虑 |
| 核心问题 | 孩子挑食、营养不均衡、父母每天不知道怎么搭配 |
| 典型矛盾 | 信息很多，但执行混乱 |
| 付费能力 | 中高 |
| 产品价值 | 把儿童营养目标落到每天三餐 |
| 核心卖点 | 让孩子每一顿吃得更科学，也让父母少一点焦虑 |

这类用户的情绪入口强，容易传播，但未必一开始就愿意付很高的钱，除非产品做得非常省心和专业。

### 4.3 第三优先级：营养师 / 家政 / 月子中心 / 高端私厨机构

| 维度 | 内容 |
|---|---|
| 客户类型 | 营养师工作室、月子中心、高端家政、私厨服务 |
| 核心问题 | 有专业方案，但交付不可规模化，执行质量不可控 |
| 付费能力 | 取决于服务机构客单价 |
| 产品价值 | AI 化家庭饮食交付系统 |
| 核心卖点 | 让营养服务从“给建议”升级成“可执行、可追踪、可复盘” |

这类可能是很好的商业化入口，因为它不是从零教育用户，而是嵌入已有服务链条。

## 5. 产品链条

完整链条可以定义为：

```text
家庭成员画像
→ 健康目标 / 忌口规则
→ 时间预算 / 工作日周末模式
→ 冰箱库存 / 语音录入 / 视觉识别
→ 菜单规划
→ 食材选品
→ shopping list
→ 渠道拆单 / 下单外送
→ 免手操作 Kitchen Mode
→ 摄像头 + 语音烹饪指导
→ 用餐语音反馈
→ 饮食记账 / 营养复盘
→ 下一轮优化
```

这个链条是产品的核心壁垒。普通产品往往只覆盖其中一两环：

| 产品类型 | 覆盖环节 | 没解决什么 | 家庭营养师 Agent 的差异 |
|---|---|---|---|
| 菜谱 App | 菜单 / 做法 | 不理解家庭目标、库存、时间和反馈 | 从“菜”出发升级为从“家庭目标”出发 |
| 短视频做饭 | 灵感 / 单道菜教学 | 不可交互，不可个性化，不进厨房现场 | 从“看别人做”变成“陪你现场做” |
| 普通 AI 聊天助手 | 菜单生成 / 营养建议 | 不知道库存、不会长期复盘、难进入执行现场 | 从“建议生成”变成“执行闭环” |
| 营养师 | 评估 / 建议 | 难以每天介入采购和烹饪 | 从“周期咨询”变成“持续在线执行系统” |
| 智能冰箱 | 局部库存 | 不管理家庭营养目标和做饭过程 | 从“设备智能”变成“家庭饮食 Agent” |
| 生鲜平台 | 采购履约 | 不知道家庭目标和长期反馈 | 从“交易入口”变成“采购决策” |
| 记账 App | 成本记录 | 不理解营养、库存和菜单 | 从“花了多少钱”变成“饮食成本是否有效” |

## 6. 核心功能模块

### 6.1 家庭成员画像

记录每个家庭成员的：

- 年龄；
- 身高体重；
- 健康目标；
- 忌口；
- 过敏；
- 慢病限制；
- 口味偏好；
- 饮食习惯；
- 用餐时间；
- 对菜品的接受度。

重点不是“资料填写”，而是形成长期记忆：

```text
孩子不爱吃西兰花
→ 但可以接受西兰花蒸蛋

老人不能吃太硬
→ 牛肉优先炖煮或切薄片

爸爸减脂
→ 晚餐自动减少主食、增加蛋白
```

### 6.2 营养目标与规则

把抽象目标转成可执行饮食规则。

| 目标 | 转换成的执行规则 |
|---|---|
| 孩子成长 | 蛋白质、钙、铁、维生素、蔬菜摄入 |
| 减脂 | 控制热量，提高蛋白，减少高油高糖 |
| 控糖 | 控制精制碳水，主食定量，低 GI 搭配 |
| 老人饮食 | 软烂、低盐、易消化、优质蛋白 |
| 产后恢复 | 补铁、补蛋白、补钙，避免过度油腻 |
| 全家健康 | 控油盐、增加食材多样性、减少外卖 |

边界上要明确：产品做营养建议和执行管理，不做医疗诊断。涉及疾病场景时，应以医生 / 营养师给出的限制条件为依据。

### 6.3 时间感知菜单规划

菜单规划必须考虑：

- 工作日还是周末；
- 今天几点吃饭；
- 还有多久可以做饭；
- 做饭人是谁；
- 做饭人能力如何；
- 是否需要带饭；
- 是否需要给孩子 / 老人单独处理；
- 是否可以提前备菜；
- 清洁成本能不能接受。

核心原则：

> 不是生成理论上最健康的菜单，而是在今天这个时间条件下，最可能被做出来、吃下去、并符合营养目标的菜单。

工作日和周末逻辑不同：

| 维度 | 工作日 | 周末 |
|---|---|---|
| 核心目标 | 稳定执行，别崩盘 | 改善生活质量 |
| 时间约束 | 强 | 弱 |
| 用户状态 | 累、急、决策疲劳 | 有时间、有情绪价值 |
| 菜品策略 | 快手、少步骤、少清洁 | 丰富、仪式感、可探索 |
| 营养策略 | 保基础盘 | 补短板、做优化 |
| 采购策略 | 少量、高确定性 | 可做大采购和备餐 |
| 家庭参与 | 执行效率优先 | 可加入亲子互动 |
| Agent 角色 | 调度员 / 教练 | 规划师 / 陪伴式教练 |

一句话：

> 工作日解决“别崩盘”，周末解决“变更好”。

### 6.4 库存管理

库存管理不是简单记录冰箱里有什么，而是让库存参与决策。它要支持：

- 语音录入；
- 拍照识别；
- 小票 / 订单导入；
- 常备食材模板；
- 临期提醒；
- 优先消耗建议。

厨房场景中，录入最好不是手动，因为用户手里通常有水、油、面粉、生肉或厨具。因此库存录入应当优先支持语音：

```text
鸡蛋还剩 6 个。
牛奶快没了。
这袋牛肉今天拆了，还剩一半。
蓝莓明天要吃掉。
西兰花用完了。
```

Agent 要把自然语言转成结构化库存数据：

| 用户表达 | 系统理解 |
|---|---|
| 鸡蛋还剩 6 个 | 鸡蛋库存 = 6 个 |
| 牛奶快没了 | 牛奶库存低，加入补货提醒 |
| 牛肉拆了，还剩一半 | 牛肉库存约 50%，状态变为已开封 |
| 蓝莓明天要吃掉 | 蓝莓临期优先消耗 |
| 西兰花用完了 | 西兰花库存归零 |

### 6.5 采购与成本 Agent

它不只是生成 shopping list，而是完成采购决策：

```text
菜单
→ 缺口判断
→ 食材选品
→ 渠道拆单
→ 用户确认
→ 下单配送
→ 入库
→ 消耗记录
→ 成本复盘
```

能力包括：

| 能力 | 说明 |
|---|---|
| 菜单驱动采购 | 根据本周菜单生成采购清单 |
| 智能选品 | 判断具体买什么品类、部位、规格、品牌 |
| 渠道拆单 | 盒马、山姆、网购、本地生鲜分别买什么 |
| 下单外送 | 用户确认后跳转或 API 下单 |
| 饮食记账 | 记录食材支出、外卖支出、浪费和预算 |
| 采购复盘 | 分析哪些买多了、哪些性价比高、哪些不适合家庭 |

核心判断：

> shopping list 的真正价值不是列出“缺什么”，而是在家庭目标、库存、预算、渠道和时间约束下，帮用户完成食材采购决策。

以肉类选品为例：

| 目标 | 推荐逻辑 | 避坑点 |
|---|---|---|
| 儿童成长 | 高蛋白、易咀嚼、少筋膜 | 避免太硬、太油、重调味 |
| 减脂 | 低脂高蛋白 | 避免肥牛卷、五花肉、加工肉 |
| 老人饮食 | 软烂、易消化 | 避免筋多、硬、难咀嚼 |
| 控糖 / 控脂 | 原切优先，少加工 | 避免腌制肉、酱汁肉、香肠培根 |
| 快手晚餐 | 薄切、预处理但少调味 | 避免重口味半成品 |
| 周末备餐 | 大包装、可分装冷冻 | 注意家庭消耗能力和冷冻空间 |

推荐逻辑必须透明，不能为了佣金牺牲信任。

### 6.6 免手操作 Kitchen Mode

厨房不是适合手动录入的场景。用户做饭时手上可能有水、油、面粉或生肉，眼睛也要看火候、刀具和锅具。因此，家庭营养师 Agent 的核心交互应该是：

> 语音优先，视觉辅助，触控兜底。

Kitchen Mode 的核心能力：

| 能力 | 说明 |
|---|---|
| 语音库存录入 | 说一句即可更新库存 |
| 语音菜单调整 | 临时改变人数、时间、食材、忌口 |
| 语音做饭导航 | 下一步、重复、暂停、计时、提醒 |
| 语音反馈记录 | 饭后口味、剩菜、执行难度记录 |
| 语音安全确认 | 过敏、慢病、付款等关键动作需要确认 |
| 大字卡片界面 | 用户只需瞥一眼，不用仔细阅读 |
| 多噪声适配 | 油烟机、水声、锅声环境下仍能用 |
| 多角色识别 | 妈妈、阿姨、老人说话时能区分上下文 |

屏幕主要承担确认、状态展示和复盘作用，而不是高频输入。

### 6.7 厨房实时指导

能力包括：

- 语音陪伴；
- 分步指导；
- 摄像头识别；
- 食材状态判断；
- 切法提醒；
- 火候提醒；
- 油盐控制；
- 老人 / 儿童特殊处理；
- 临时替代；
- 失败救场。

它的体验应该是：

```text
你现在可以先把牛肉切薄片，大概硬币厚度。
我看到这几块有点大，给孩子吃建议再切小一点。
锅可以再热 30 秒，现在下油还早。
这道菜给奶奶吃的话，最后不要加糖，盐也减半。
```

它本质上是：

> AI 在厨房现场陪你完成任务。

### 6.8 用餐反馈与周报复盘

记录每顿饭的结果：

- 谁吃了；
- 吃了多少；
- 喜不喜欢；
- 有没有剩；
- 哪道菜失败；
- 哪道菜太复杂；
- 哪个食材浪费；
- 是否符合营养目标。

周报可以同时看三件事：

```text
营养
+ 执行
+ 成本
```

示例：

```text
本周家庭饮食复盘：

营养：
- 孩子早餐蛋白质达标 5/7 天
- 全家蔬菜摄入偏少 2 天
- 奶奶控糖餐执行较好

执行：
- 工作日晚餐平均用时 32 分钟
- 阿姨执行成功率较高
- 周三因缺少西兰花临时改菜

成本：
- 本周食材支出：986 元
- 外卖支出：168 元，较上周下降 42%
- 山姆大包装牛肉已使用 60%
- 蓝莓剩余较多，建议明早加入酸奶
```

## 7. 数据源与数据壁垒

家庭营养师 Agent 并不依赖单一数据源，而是由三类数据共同驱动：

1. **外部权威数据**：膳食指南、食材营养成分、食品安全规则、专业菜谱；
2. **家庭自有数据**：成员画像、健康目标、口味偏好、忌口、时间预算、库存、采购记录；
3. **实时场景数据**：语音输入、冰箱 / 食材图片、厨房视频、小票 / 订单截图、用餐反馈。

其中，外部权威数据决定建议是否专业，家庭自有数据决定建议是否个性化，实时场景数据决定建议是否能落地。

### 7.1 数据源成熟度

| 数据类型 | 有没有现成数据源 | 早期可用性 | 难点 |
|---|---:|---:|---|
| 基础营养知识 | 有 | 高 | 标准化、中文化、适配家庭场景 |
| 食材营养成分 | 有 | 高 | 数据授权、单位换算、烹饪损耗 |
| 膳食指南 | 有 | 高 | 需要转成可执行规则 |
| 菜谱数据 | 有很多 | 中 | 质量参差、版权、营养结构不完整 |
| 烹饪步骤数据 | 有 | 中 | 很多步骤不适合 Agent 分步指导 |
| 商品数据 | 有，但平台封闭 | 中低 | 盒马 / 山姆 / 电商接口和授权 |
| 价格数据 | 有，但不稳定 | 中低 | 实时性、地域差异、渠道差异 |
| 库存数据 | 没有公共源 | 需要用户产生 | 需要语音 / 拍照 / 订单导入 |
| 家庭偏好数据 | 没有公共源 | 必须自建 | 是产品长期壁垒 |
| 厨房视觉数据 | 有通用视觉能力，但缺垂直数据 | 中低 | 识别厨房状态难 |
| 医疗 / 慢病规则 | 有权威指南 | 中 | 合规、责任边界、专业审核 |
| 选品经验数据 | 有碎片化知识 | 中 | 需要结构化和专业化 |

### 7.2 数据分层

```text
外部基础数据
├── 营养指南
├── 食材成分
├── 菜谱知识
├── 商品信息
└── 价格 / 渠道信息

家庭自有数据
├── 家庭成员画像
├── 健康目标
├── 忌口过敏
├── 口味偏好
├── 厨房设备
├── 时间规律
├── 库存状态
├── 采购记录
├── 做饭记录
└── 用餐反馈

专业服务数据
├── 营养师方案
├── 医生 / 营养师限制条件
├── 家政执行标准
├── 月子中心菜单体系
└── 机构服务 SOP

实时场景数据
├── 语音输入
├── 冰箱 / 食材图片
├── 厨房视频
├── 订单截图
└── 小票 OCR
```

产品真正的长期壁垒，不是拥有通用营养知识，而是持续积累每个家庭的饮食上下文，并把它转化为更准确的菜单、采购、烹饪和复盘决策。

### 7.3 最现实的早期数据路径

第一阶段不应试图一次性搞全量数据源，而应优先组合：

1. **公共 / 半公共营养数据**：中国居民膳食指南、常见食材营养成分、常见人群饮食原则、食品安全常识；
2. **自建结构化菜谱库**：先做 100–300 道高质量家庭菜，重点覆盖工作日快手菜、儿童友好菜、老人友好菜、减脂友好菜、控油低盐菜、备餐菜、一锅出；
3. **家庭建档数据**：通过访谈 / 表单 / 语音采集家庭成员、目标、忌口、口味、做饭人、采购渠道、时间预算、厨房设备；
4. **语音反馈数据**：记录“孩子不爱吃这个”“这道菜太麻烦”“今天买菜花了 180”等真实反馈；
5. **小票 / 订单截图数据**：用于采购入库和饮食记账。

## 8. 技术可行性

总体判断：方向可行，但不能一开始追求全自动。

早期不要把它设计成“全自动厨房机器人”，而要设计成：

> 语音优先的家庭饮食协作 Agent。

### 8.1 技术成熟度

| 能力模块 | 当前技术成熟度 | 是否适合早期做 | 判断 |
|---|---:|---:|---|
| 菜单规划 | 高 | 适合 | 大模型 + 规则约束已经可以做到不错 |
| 营养建议 | 中高 | 适合，但需边界 | 可做健康饮食建议，不应做医疗诊断 |
| 语音交互 | 高 | 适合 | 语音输入 / TTS / 对话已经成熟，但要适配厨房噪声 |
| 长期记忆 | 中高 | 适合 | 家庭成员、口味、忌口、历史反馈可以结构化保存 |
| shopping list | 高 | 适合 | 从菜单生成清单很成熟 |
| 食材选品 | 中高 | 适合 | 需要商品知识库和规则体系 |
| 渠道拆单 | 中 | 可做半自动 | 早期可先支持用户常用渠道偏好，不必直接 API 下单 |
| 下单外送 | 中低 | 后置 | 受平台接口、商业合作、履约限制影响 |
| 饮食记账 | 高 | 适合 | 可从语音 / 小票 / 订单导入开始 |
| 冰箱库存识别 | 中 | 可做辅助 | 视觉可辅助识别，但不能完全依赖 |
| 厨房摄像头指导 | 中 | 可做受控场景 | 能做部分状态识别，但不能过度承诺火候判断 |
| 自动判断熟没熟 | 中低 | 谨慎 | 食品安全相关，不能轻率承诺 |
| 家庭多角色协作 | 高 | 适合 | 主要是产品设计和权限设计 |
| 医疗级慢病饮食 | 中低 | 谨慎 | 需要专业背书和合规边界 |

结论：

> AI 对话、语音、菜单规划、长期记忆、采购清单、反馈复盘已经足够支撑早期产品；真正难的是厨房视觉、食品安全、医疗边界和生鲜履约。

### 8.2 早期产品形态

早期不应该直接做：

- 专用厨房机器人；
- 智能冰箱；
- 专用摄像头硬件；
- 复杂 IoT 厨房系统。

更合理的早期形态是：

```text
手机 / 平板 App
+ 厨房支架
+ 语音交互
+ 摄像头辅助
+ 可选蓝牙音箱 / 耳机
```

也就是：

> 先用已有设备进入厨房，不先制造厨房设备。

### 8.3 技术路线判断

家庭营养师 Agent 的早期可行性不依赖完美的厨房视觉或全自动下单，而依赖这条闭环能否跑通：

```text
语音优先交互
+ 家庭长期记忆
+ 时间感知菜单规划
+ 采购决策
+ 做饭陪伴
+ 反馈复盘
```

## 9. 试产 / 试点要求

试点要验证的不是：

> AI 能不能生成菜单。

真正要验证的是：

> AI 能不能持续进入一个家庭的饮食链条，并让他们觉得：比以前更省心、更健康、更可控，而且愿意继续付费。

### 9.1 试点家庭条件

| 条件 | 原因 |
|---|---|
| 每周至少 4 天在家吃饭 | 否则饮食链条频率不够 |
| 家里至少 2–3 个家庭成员 | 才有多目标、多偏好冲突 |
| 有明确健康目标 | 比如孩子营养、减脂、控糖、老人低盐 |
| 有固定采购渠道 | 盒马、山姆、叮咚、菜市场等 |
| 愿意语音反馈 | 产品需要积累家庭记忆 |
| 厨房可放手机 / 平板支架 | 验证摄像头和免手操作 |
| 愿意连续使用 2–4 周 | 饮食产品不能只测一天 |
| 接受人工兜底 | 早期需要 human-in-the-loop 保证体验 |

### 9.2 四周试点设计

| 周期 | 目标 | 验证重点 |
|---|---|---|
| 第 0 周：家庭建档 | 建立基础上下文 | 成员、目标、忌口、偏好、时间、渠道、设备、预算 |
| 第 1 周：菜单 + shopping list | 验证前半链条 | 菜单是否符合家庭情况，采购清单是否减少决策 |
| 第 2 周：语音库存 + 厨房陪做 | 验证厨房场景 | 语音是否高频使用，做饭步骤是否真的好用 |
| 第 3 周：反馈 + 复盘 | 验证长期记忆 | 口味、时间、库存、执行反馈是否进入下一轮优化 |
| 第 4 周：付费意愿 | 验证商业价值 | 是否愿意续费、愿意推荐、愿意让阿姨 / 营养师一起用 |

### 9.3 试点场景

| 场景 | 目标 | 验证点 |
|---|---|---|
| 工作日晚餐 | 30–45 分钟内，让一家人吃上一顿符合目标的饭 | 时间感知菜单、库存使用、快手做饭指导、反馈 |
| 儿童营养早餐 / 晚餐 | 让父母觉得孩子吃得更科学、更稳定 | 儿童营养目标、口味适配、挑食处理、周报 |
| 有阿姨执行的家庭晚餐 | 让阿姨按家庭目标稳定做饭，让决策者能监督和复盘 | 多角色协作、任务化菜单、语音步骤、执行报告 |

### 9.4 试产成败指标

| 指标类型 | 指标 |
|---|---|
| 使用行为 | 每周菜单生成次数、shopping list 使用率、语音录入次数、厨房陪做次数、反馈记录次数、周报查看率、连续使用天数 |
| 执行效果 | 菜单实际完成率、采购准确率、食材浪费率、做饭平均耗时、临时改菜次数、外卖次数变化、工作日晚餐成功率 |
| 家庭体验 | 决策压力下降、育儿 / 健康焦虑下降、做饭执行者满意度、家庭成员接受度、口味命中率、专业可信度 |
| 商业指标 | 续费意愿、可接受月费、服务升级意愿、采购转化率、推荐意愿、机构合作意愿 |

### 9.5 试点方式：human-in-the-loop

早期一定要允许人工兜底：

- 营养顾问审核菜单；
- 运营人员检查 shopping list；
- 人工标注库存；
- 人工整理周报；
- 人工复核儿童 / 慢病敏感建议；
- 人工收集访谈反馈。

这不是作弊，而是正确的试产方式。早期要验证的是：

> 如果这个体验真的存在，用户是否需要？

不是一开始就验证：

> 所有环节能否 100% 自动化？

## 10. 产品边界与风险

| 做 | 不做 |
|---|---|
| 做家庭饮食计划 | 不做医疗诊断 |
| 做营养建议落地 | 不替代医生 |
| 做库存和采购辅助 | 不一开始自建生鲜供应链 |
| 做厨房实时指导 | 不一开始做重型厨房机器人 |
| 做饮食成本复盘 | 不做泛财务记账 |
| 做语音优先厨房交互 | 不依赖用户在厨房频繁手动录入 |
| 做营养师 / 家政服务增强 | 不一开始承诺完全自动化 |

关键风险：

1. **厨房视觉不稳定**：早期只能辅助判断，不能承担食品安全裁决；
2. **营养建议可信度**：需要权威数据、专业审核和医疗边界；
3. **长期记忆准确性**：过敏、忌口、慢病、偏好等关键记忆必须可确认、可修改；
4. **语音误识别**：关键动作要复述确认，支持撤销；
5. **商品推荐信任问题**：推荐理由必须透明，商业合作不能污染推荐逻辑；
6. **隐私风险**：家庭健康、孩子、消费、厨房视频都是敏感数据，应最小化采集、加密存储、可删除、权限隔离。

## 11. MVP 方向：靠后，但可以先记录判断

虽然完整产品很大，但早期 MVP 不应该做成“大而全”。更合理的是先验证一个最小闭环：

```text
家庭建档
→ 每周菜单
→ shopping list
→ 工作日晚餐语音陪做
→ 饭后语音反馈
→ 每周复盘
```

早期可以不做：

- 全自动识别冰箱；
- 自动下单；
- 精准热量计算；
- 所有菜品视觉识别；
- 专用硬件；
- 医疗级营养方案。

MVP 的核心问题不是“功能够不够酷”，而是：

> 用户是否愿意把家庭饮食目标交给 Agent 管，并持续提供反馈？

---

## 12. 暂定结论

家庭营养师 Agent 的机会不在于“AI 生成菜谱”，而在于把家庭饮食中原本割裂的环节串起来：

```text
目标
→ 时间
→ 库存
→ 菜单
→ 选品
→ 采购
→ 做饭
→ 反馈
→ 复盘
```

它的长期壁垒来自三件事：

1. **家庭上下文**：长期理解每个家庭成员的目标、口味、忌口、时间和预算；
2. **执行闭环**：不只建议，还进入采购和厨房现场；
3. **反馈数据**：每一顿饭的结果都会反过来优化下一顿。

一句话：

> **家庭营养师 Agent 要做的不是“更聪明的菜谱”，而是“更可靠的家庭饮食执行系统”。**
