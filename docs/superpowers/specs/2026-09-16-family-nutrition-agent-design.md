# 家庭营养师 Agent MVP 设计方案

> 日期：2026-09-16  
> 主题：基于 WeKnora + 结构化 Markdown 菜谱卡片，验证家庭营养师 Agent 的每日食谱生成、家庭成员口味 / 过敏适配、库存跟踪、饭后反馈与持续优化能力。

---

## 1. 背景与目标

现有产品设想见：`docs/ideas/01-家庭营养师Agent.md`。

完整的家庭营养师 Agent 可以覆盖：

```text
家庭成员画像
→ 健康目标 / 忌口规则
→ 时间预算 / 工作日周末模式
→ 冰箱库存
→ 菜单规划
→ 食材采购
→ 厨房执行
→ 用餐反馈
→ 长期优化
```

但第一阶段不做完整产品链条，而是先验证一个可落地的知识库驱动 MVP：

```text
家庭成员画像
+ 家庭饮食硬规则
+ 当前库存
+ 结构化 Markdown 菜谱卡片
+ 每日食谱生成 Agent
+ 饭后复盘与库存更新 Agent
```

第一阶段核心目标：

```text
验证 WeKnora 是否能支撑家庭营养师 Agent，
根据家庭成员、口味、过敏、忌口、老人 / 孩子 / 减脂目标、库存和历史反馈，
生成可执行的每日 / 每周食谱，
并通过饭后反馈影响下一次推荐。
```

---

## 2. 已确认设计决策

本设计基于以下已确认判断：

```text
目标不是先做商业产品，而是先验证知识库能力。
家庭场景同时包含：普通日常吃饭、孩子营养、减脂/健身、老人/慢病饮食。
第一阶段采用方案 2：知识库 + 结构化家庭档案 + 规则护栏。
菜谱数量早期不大，不先上数据库。
菜谱采用结构化 Markdown 卡片。
第一阶段不做购物清单和自动下单。
第一阶段需要跟踪库存、推荐历史、实际做菜、饭后反馈。
每日食谱生成和饭后复盘库存更新拆成两个 Agent。
```

---

## 3. MVP 范围

### 3.1 第一阶段要做

```text
1. 建立 WeKnora 后台知识库结构。
2. 建立家庭成员画像。
3. 建立家庭饮食硬规则。
4. 建立当前库存记录。
5. 建立 30–50 道结构化 Markdown 菜谱卡片。
6. 建立每日食谱生成 Agent。
7. 建立饭后复盘与库存更新 Agent。
8. 记录推荐历史。
9. 记录实际做菜与库存消耗。
10. 记录饭后反馈，并影响下一次推荐。
```

### 3.2 第一阶段不做

```text
数据库
精确营养计算
完整购物清单
自动下单
自动扣库存
摄像头识别
医疗诊断
微信机器人
复杂 App
多人权限
```

第一阶段不追求全自动，核心是验证：

```text
结构化 Markdown 是否足够表达家庭菜谱；
WeKnora 是否能稳定检索这些卡片；
Agent 是否能遵守家庭硬规则；
Agent 是否能兼顾孩子、老人、减脂和普通饮食；
反馈是否能影响下一次菜单。
```

---

## 4. 总体架构

```text
用户
  ↓
WeKnora Agent 入口
  ↓
每日食谱生成 Agent
  ↓
读取知识库：
  - 家庭成员画像
  - 家庭硬规则
  - 营养原则
  - 食材知识
  - 菜谱卡片
  - 饭后反馈
  - 菜单历史
  - 当前库存
  ↓
生成今日 / 本周食谱推荐
  ↓
用户实际做饭
  ↓
饭后复盘与库存更新 Agent
  ↓
生成记录草稿：
  - 实际做菜
  - 库存消耗
  - 成员反馈
  - 菜谱更新建议
  ↓
人工确认后写回知识库
  ↓
影响下一次推荐
```

核心原则：

> 第一阶段由 Agent 生成“可写入知识库的草稿”，用户人工确认后再写回。不要一开始自动改库存、自动改菜谱、自动修改硬规则。

---

## 5. WeKnora 后台知识库结构

建议在 WeKnora 中创建 9 个知识库：

```text
00-inbox
01-family-profile
02-family-rules
03-nutrition-principles
04-ingredient-knowledge
05-recipe-cards
06-meal-feedback
07-meal-history
08-kitchen-inventory
```

| 知识库 | 作用 | 每日食谱 Agent 默认读取 |
|---|---|---|
| `00-inbox` | 临时收集、待整理 | 否 |
| `01-family-profile` | 家庭成员画像 | 是 |
| `02-family-rules` | 过敏、忌口、健康硬规则 | 是，最高优先级 |
| `03-nutrition-principles` | 营养原则 | 是 |
| `04-ingredient-knowledge` | 食材知识、替代关系 | 是 |
| `05-recipe-cards` | 结构化 Markdown 菜谱卡片 | 是 |
| `06-meal-feedback` | 饭后反馈 | 是 |
| `07-meal-history` | 推荐和实际做菜历史 | 是 |
| `08-kitchen-inventory` | 当前库存、采购、消耗 | 是 |

---

## 6. 知识库详细设计

### 6.1 `00-inbox`：临时收集箱

用途：

```text
临时放文章、菜谱、营养建议、医生提醒、家人反馈、购物记录。
```

规则：

```text
新资料先进入 00-inbox。
每周整理一次。
正式食谱生成 Agent 默认不查 00-inbox。
只有知识整理助手可以查 00-inbox。
```

价值：

```text
防止正式知识库变成杂物堆。
降低随手收集成本。
避免敏感资料未经判断直接进入正式知识库。
```

### 6.2 `01-family-profile`：家庭成员画像

建议每个成员一个 Markdown 文件：

```text
01-family-profile/
  爸爸.md
  妈妈.md
  孩子.md
  奶奶.md
```

成员画像模板：

```markdown
# 成员：爸爸

## 基本信息
- 年龄阶段：成人
- 常见用餐：早餐、晚餐
- 活动量：中等

## 健康目标
- 减脂
- 晚餐控制主食
- 增加蛋白质
- 控油

## 过敏
- 暂无明确过敏

## 忌口
- 不吃动物内脏

## 口味偏好
- 喜欢：牛肉、鸡蛋、番茄、微辣
- 不喜欢：苦瓜、芹菜、太甜

## 菜品反馈
- 番茄牛肉汤：喜欢
- 清蒸鱼：可以接受
- 水煮鸡胸：不喜欢

## Agent 注意事项
- 晚餐主食减半
- 优先安排高蛋白菜
- 避免高油高糖
```

目标是让 Agent 知道：

```text
这个人是谁；
吃饭目标是什么；
不能吃什么；
不爱吃什么；
过去吃过什么反馈。
```

### 6.3 `02-family-rules`：家庭硬规则

这是最高优先级知识库。它不是普通偏好，而是 Agent 必须遵守的规则。

建议文件：

```text
02-family-rules/
  家庭饮食硬规则.md
  过敏与忌口规则.md
  慢病与健康边界.md
```

示例：

```markdown
# 家庭饮食硬规则

## 绝对禁止
- 如果某成员对某食材过敏，所有包含该食材及其常见同义食材的菜品必须排除。
- 不确定是否含过敏源时，必须向用户确认，不能直接推荐。
- 任何含高风险食材的菜单，都必须给出替代方案或说明不可推荐。

## 家庭过敏规则
- 成员 A 对虾过敏。
- 禁止：虾、虾仁、河虾、基围虾、虾皮、虾酱。

## 健康限制
- 奶奶需要低盐、软烂、易消化。
- 晚餐避免太硬、太辣、太油。
- 控糖相关建议仅作为饮食管理参考，不替代医生建议。

## 口味偏好规则
- 妈妈不喜欢香菜，默认不放。
- 孩子不喜欢整块西兰花，但可以接受西兰花蒸蛋。
- 爸爸减脂，晚餐主食减半，优先高蛋白。
```

规则类型必须区分：

```text
过敏：绝对禁止
忌口：默认排除
不喜欢：尽量避免
健康目标：优化方向
```

### 6.4 `03-nutrition-principles`：营养原则库

这里放通用营养知识，不放家庭私有偏好。

内容包括：

```text
中国居民膳食指南
儿童饮食原则
老人饮食原则
减脂饮食原则
控糖饮食原则
低盐饮食原则
高蛋白饮食原则
三餐搭配原则
```

建议把权威资料整理成短 Markdown 页面，而不是直接塞大段 PDF。

示例：

```markdown
# 儿童晚餐搭配原则

## 目标
- 保证优质蛋白。
- 有足量蔬菜。
- 主食适量。
- 避免过甜、过油、过辣。
- 尽量适合咀嚼和吞咽。

## 推荐结构
- 主食：米饭、面、杂粮，适量。
- 蛋白质：鱼、蛋、鸡肉、牛肉、豆制品。
- 蔬菜：深色蔬菜 + 浅色蔬菜。
- 汤：可选，但不宜过咸。

## 避免
- 高糖饮料。
- 油炸食品。
- 重口味调料。
- 大块难咀嚼肉类。
```

### 6.5 `04-ingredient-knowledge`：食材知识库

用于记录食材解释、适合人群、替代关系。

建议文件：

```text
04-ingredient-knowledge/
  鸡蛋.md
  牛肉.md
  鱼.md
  西兰花.md
  番茄.md
  燕麦.md
  豆腐.md
```

食材知识模板：

```markdown
# 食材：鸡蛋

## 营养特点
- 优质蛋白。
- 含脂溶性维生素。
- 适合早餐和快手菜。

## 适合人群
- 儿童。
- 成人。
- 减脂人群。
- 老人，视消化情况。

## 注意事项
- 对鸡蛋过敏者禁用。
- 控脂人群注意总量。

## 常见做法
- 水煮蛋。
- 蒸蛋。
- 番茄炒蛋。
- 鸡蛋羹。
- 蛋花汤。

## 家庭适配
- 孩子：更适合蒸蛋、蛋羹。
- 老人：更适合蒸蛋、蛋花汤。
- 减脂：水煮蛋、少油炒蛋。
```

### 6.6 `05-recipe-cards`：结构化 Markdown 菜谱卡片

这是 MVP 的核心。

第一批建议 30–50 道家庭高频菜，不追求大而全。

目录可以保持简单：

```text
05-recipe-cards/
  番茄牛肉汤.md
  西兰花蒸蛋.md
  清蒸鲈鱼.md
  鸡胸肉蔬菜饭.md
  番茄鸡蛋面.md
```

菜谱卡片模板：

```markdown
# 菜名：番茄牛肉汤

## 基础信息
- 菜品类型：汤 / 蛋白质主菜
- 适合餐次：晚餐
- 总耗时：40 分钟
- 难度：中
- 清洁成本：中
- 口味：酸甜、清淡
- 辣度：0
- 软硬程度：软烂

## 标签
- 儿童友好
- 老人友好
- 减脂可用
- 高蛋白
- 低油
- 可低盐
- 工作日晚餐可用

## 主要食材
- 牛肉
- 番茄
- 洋葱
- 姜

## 可能过敏源
- 牛肉

## 不适合
- 不吃牛肉者
- 牛肉过敏者
- 当天需要 20 分钟内完成时不适合

## 适合人群
- 儿童
- 老人
- 减脂成员
- 普通家庭晚餐

## 家庭适配
- 孩子：牛肉切小块，番茄味更容易接受。
- 老人：牛肉多炖 10–15 分钟，减少盐。
- 减脂成员：少油，不加糖，主食减量。
- 控糖成员：不加糖，搭配少量杂粮饭。

## 做法
1. 牛肉切薄片或小块。
2. 番茄去皮切块。
3. 少油炒番茄出汁。
4. 加水炖煮。
5. 加牛肉煮熟。
6. 少量调味出锅。

## 替代方案
- 牛肉可替换为鸡胸肉。
- 番茄可搭配豆腐。

## 注意事项
- 如果老人牙口不好，牛肉必须炖软。
- 如果孩子不喜欢大块肉，牛肉要切小。
- 如果当天时间少于 30 分钟，不优先推荐。
```

### 6.7 `06-meal-feedback`：饭后反馈库

记录每顿饭后的真实反馈。

示例：

```markdown
# 2026-09-16 晚餐反馈

## 菜单
- 番茄牛肉汤
- 西兰花蒸蛋
- 杂粮饭

## 成员反馈

### 孩子
- 番茄牛肉汤：喜欢汤，不喜欢大块牛肉。
- 西兰花蒸蛋：接受度高。
- 杂粮饭：一般。

### 爸爸
- 番茄牛肉汤：满意。
- 杂粮饭：希望晚餐主食再少一点。

### 奶奶
- 番茄牛肉汤：牛肉略硬。
- 西兰花蒸蛋：适合。
- 整体咸度：可以。

## 执行反馈
- 做饭时间：42 分钟。
- 难度：中。
- 清洁成本：中。
- 剩菜：无明显剩菜。

## 下次调整
- 牛肉给奶奶部分多炖 10 分钟。
- 孩子部分肉切更小。
- 爸爸主食继续减量。
```

### 6.8 `07-meal-history`：菜单历史库

记录推荐菜单和实际执行情况。

示例：

```markdown
# 2026-W38 菜单历史

## 2026-09-16 晚餐

### Agent 推荐菜单
- 番茄牛肉汤
- 西兰花蒸蛋
- 杂粮饭

### 用户是否采纳
- 状态：已采纳

### 实际做了
- 番茄牛肉汤
- 西兰花蒸蛋
- 杂粮饭

### 是否需要避免短期重复
- 番茄牛肉汤：3 天内不主动重复。
- 西兰花蒸蛋：2 天内不主动重复。
- 杂粮饭：可重复。

### 备注
- 孩子接受西兰花蒸蛋。
- 奶奶反馈牛肉略硬。
```

必须区分：

```text
推荐过
确认做
实际做
吃完反馈
```

关键原则：

```text
推荐过的菜：用于避免短期重复。
实际做过的菜：用于更新库存和反馈。
未采纳推荐：不减库存。
```

### 6.9 `08-kitchen-inventory`：厨房库存库

第一版库存不需要精确到克，而是辅助菜单决策。

建议文件：

```text
08-kitchen-inventory/
  当前库存.md
  每周采购记录.md
  食材消耗记录.md
  临期与优先消耗.md
```

`当前库存.md` 示例：

```markdown
# 当前库存

> 更新时间：2026-09-16 晚上

## 蛋白质类

| 食材 | 数量 | 状态 | 优先级 | 备注 |
|---|---:|---|---|---|
| 鸡蛋 | 8 个 | 正常 | 中 | 早餐常用 |
| 牛肉 | 300g | 已开封 | 高 | 建议 1–2 天内用完 |
| 鸡胸肉 | 500g | 冷冻 | 中 | 减脂餐可用 |

## 蔬菜类

| 食材 | 数量 | 状态 | 优先级 | 备注 |
|---|---:|---|---|---|
| 西兰花 | 1 颗 | 新鲜 | 中 | 孩子不爱整块吃 |
| 番茄 | 4 个 | 正常 | 中 | 可做汤或炒蛋 |
| 菠菜 | 1 把 | 临期 | 高 | 明天前吃掉 |

## 主食类

| 食材 | 数量 | 状态 | 优先级 | 备注 |
|---|---:|---|---|---|
| 大米 | 充足 | 正常 | 低 | |
| 燕麦 | 半袋 | 正常 | 中 | 早餐可用 |
| 杂粮米 | 少量 | 正常 | 中 | 减脂成员可用 |
```

库存原则：

```text
只根据实际做了的菜更新库存。
不根据推荐菜单扣库存。
如果用量不确定，标记为估算。
关键库存变化不确定时，要求用户确认。
```

## 7. 核心 Agent 设计

第一版只做两个核心 Agent。

```text
Agent 1：每日家庭食谱生成 Agent
Agent 2：饭后复盘与库存更新 Agent
```

后续可选：

```text
Agent 3：每周饮食复盘 Agent
Agent 4：知识整理助手
```

---

## 8. Agent 1：每日家庭食谱生成 Agent

### 8.1 职责

负责：

```text
生成推荐菜单
解释推荐理由
检查过敏 / 忌口 / 健康限制
读取当前库存
读取近期菜单历史
预估库存影响
生成推荐记录草稿
提示饭后需要反馈什么
```

不负责：

```text
扣减库存
修改菜谱卡片
总结长期偏好
自动更新家庭硬规则
```

### 8.2 可访问知识库

```text
01-family-profile
02-family-rules
03-nutrition-principles
04-ingredient-knowledge
05-recipe-cards
06-meal-feedback
07-meal-history
08-kitchen-inventory
```

不默认访问：

```text
00-inbox
```

### 8.3 工作流

```text
1. 识别本餐场景。
2. 读取家庭硬规则。
3. 读取成员画像。
4. 读取当前库存。
5. 读取近期菜单历史。
6. 检索候选菜谱卡片。
7. 组合菜单。
8. 做安全自检。
9. 输出推荐菜单。
10. 生成推荐历史草稿。
11. 提醒用户饭后反馈。
```

```text

  >

  >

  >
当前库存
  >
近期菜单历史
  >
菜谱卡片
  >

  >
模型自由发挥
```

### 8.4 Agent Prompt 规则

```text
你是家庭营养师 Agent，负责为这个家庭生成每日食谱。

你必须遵守以下优先级：
1. 家庭硬规则高于一切，包括过敏、忌口、健康限制。
2. 家庭成员画像高于通用营养建议。
3. 当前库存和近期菜单历史高于自由发挥。
4. 菜品必须优先来自结构化 Markdown 菜谱卡片。
5. 如果菜谱库没有合适菜品，不要编造，说明缺口。
6. 涉及慢病和医疗相关内容，只能给饮食管理建议，不做医疗诊断。
7. 对不确定的过敏源或禁忌食材，必须提示用户确认。
8. 输出必须包含安全自检。
9. 推荐菜单后，只做库存影响预估，不直接扣减库存。
10. 实际做了什么必须由用户饭后确认。
```

### 9.1 职责


### 9.4 Agent Prompt 规则

## 11. 库存跟踪设计

### 11.1 库存定位

第一版库存不是专业仓储系统，而是：

```text
辅助菜单决策的轻量状态记录。
```

它回答的问题是：

```text
家里大概有什么？
哪些快过期？
哪些应优先消耗？
推荐菜单是否能用现有食材完成？
实际做完后哪些食材减少了？
```

### 11.2 库存更新原则

```text
只有实际做过的菜才减库存。
推荐过但没做，不减库存。
用户提供用量时，以用户提供为准。
用户未提供用量时，可按菜谱估算，但必须标记为估算。
关键食材数量不确定时，要求用户确认。
库存更新第一阶段生成草稿，由用户人工确认。
```

### 11.3 菜单重复控制

建议默认规则：

```text
同一道主菜 3 天内不主动重复。
同一种主要蛋白质连续 2 天不重复。
反馈低于 2 分的菜 7 天内不主动推荐。
反馈高的菜可以保留，但也不要天天推荐。
未采纳推荐不计入实际做菜，但可记录为“用户未选择”。
```

## 13. 验收标准

第一周验证以下 10 点：


只要这 10 条成立，就说明：

> WeKnora + 结构化 Markdown 的家庭营养师 Agent 路线是可行的。

## 15. 设计结论

第一阶段采用：

```text
WeKnora
+
结构化 Markdown 菜谱卡片
+
家庭硬规则
+
家庭成员画像
+
当前库存
+
菜单历史
+
饭后反馈
+
两个核心 Agent
```

两个核心 Agent：

```text
每日家庭食谱生成 Agent：
  计划者，负责生成菜单、解释理由、安全自检和库存影响预估。

饭后复盘与库存更新 Agent：
  记录者和学习者，负责实际做菜记录、库存更新草稿、成员反馈和菜谱改进建议。
```

最终目标：

> 不是做一个更聪明的菜谱生成器，而是验证一个能记住家庭成员、尊重过敏忌口、理解库存、避免重复、持续根据反馈优化的家庭饮食执行系统。
