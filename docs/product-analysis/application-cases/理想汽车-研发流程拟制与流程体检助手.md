# 理想汽车：研发流程智能拟制、查询与流程体检助手

> 收录日期 2026-09-30 · 来源：内部技术社区文章（作者：董国凤，研发运营 · 业务质量运营 × 研发效能 × 流程管理平台 AI，2026-09-11）
>
> **一句话**：把研发域"流程咨询 → 流程拟制 → 流程评审 → 流程会签 → 流程发布"整条链路装进 AI 底座，两大 AI 引擎（流程文件拟制 + 智能查询）嵌入原有流程库；更值得记录的是让 AI 反向诊断存量流程资产（职责边界模糊、责任主体漂移、环节断点、冗余审批），从"流程执行工具"变成"流程管理的硅基参与者"。

## 1. 案例来源与背景

- 来源：公司内部技术社区文章（研发运营板块），作者董国凤，Level 3；
- 发布时间：2026-09-11，阅读量约 70；

- 立项到上线约 1 个月，8 月起全链路投用。

## 2. 解决什么问题

### 2.1 痛点

**痛点一：职责边界靠经验直觉，会漂移。**

真实案例：跨领域流程共识时的问题是"P 阶段还没完成 AAR / ESO 认可时，样件封样确认该由谁负责？"——几个人凭直觉答 TPM，通用 AI 工具也顺着答 TPM；但知识库检索给出的正确答案是质量安全（PQE）负责，因为职责划分逻辑里质量安全才是该场景的责任主体。

> 启示：流程职责边界，靠经验直觉会漂移，靠"知识检索 + 规则"才严谨。

**痛点二：流程管理没有自己的入口，协同靠东拼西凑。**

| 环节 | 改造前 | 改造后 |
|---|---|---|
| 评审 / 会签 | 拿"自由审批"硬凑，字段对不上、留痕分散 | 流程库原生支持，全程留痕 |
| 发布评审通知 | 人肉在多个群里 @人、催办、贴文件 | 节点到了通知自动触达 |
| 管理入口 | 散在自由审批 + 各类群聊 | 归一到流程库一个入口，全链路可追溯 |

### 2.2 关键决策

不新建一套系统，而是把 AI 引擎直接嵌回原有流程库——审批、评审、会签、发布收回同一个原生入口。

## 3. 任务流拆解

### 3.1 日常链路（AI 嵌入流程库）

```text
流程咨询
  自然语言提问 → 企业级知识检索 → 即问即得（秒级，替代翻十几个文件花 30 分钟）
  ↓
流程文件拟制
  大模型 + 流程智能引擎（业务规则 + 历史经验 + 标准模板）
  → 智能生成 + 内容优化 + 规范校验（约 10 分钟出合规初稿，替代几小时 + 老法师口传）
  ↓
流程线上 AI 审核
  AI 合规预审：职责边界不清、引用缺失、格式不合规在提交专家评审前拦下
  ↓
流程评审 / 会签
  按预设路径自动流转，节点到了通知同步触达，全程留痕
  ↓
流程发布
  标准化发布，通知跟随节点自动触达
```

### 3.2 反向诊断链路（本案例最独特的部分）

以"平台调整职能分工机制"为对象做系统性体检，四步法：

```text
第一步：画像
  AI 通读存量流程知识库，结构化每个环节的负责角色、职责边界、输入输出、卡点
  → 沉淀"谁在什么环节、该负什么责"的职能分工底账
  ↓
第二步：体检（不是背书）
  基于业务规则库 + 历史案例，反向扫描四类高风险点：
  职责边界模糊 / 责任主体漂移 / 环节孤岛与断点 / 重复审批冗余
  每条落到具体流程文件与具体环节
  ↓
第三步：分级开方
  按影响面、风险等级、改造成本分三档：必须改（红线）/ 建议改（优化）/ 可留观（观察）
  → 输出可执行的迭代优先级
  ↓
第四步：联合评审闭环
  PDT 负责方、关联方、质量业务代表，流程内外联合评审
  逐条确认、会签 → 收敛成可发布的流程迭代版本
```

## 4. 用到的能力

- 自然语言理解 + 企业级知识检索（智能查询引擎）；
- 大模型 + 流程智能引擎（业务规则、历史经验、标准模板融合，文件拟制 + 规范校验）；
- AI 合规预审（评审前拦截硬伤）；
- 原生评审 / 会签 / 发布流转 + 留痕；
- 权限：知识库底座权限跟随用户 ID 在流程库中的查看、发布权限；
- 知识范围：当前仅产研类流程。

## 5. 效果与证据

作者给出的关键数据：

| 指标 | 数据 |
|---|---|
| 开发投入 | 1 人月 + Token 1k |
| 年提效工时 | 10,616 H |
| 提效折算价值 | 356.7 万元 |
| 投资回报率 | 62.6 倍 |
| 回收周期 | 上线首月即转正（8 月），每周 200+ 会话量 |
| 覆盖环节 | 5 个（咨询 / 拟制 / 评审 / 会签 / 发布） |

体感变化：

- 流程文件拟制：几小时 + 口口相传 → 10 分钟合规初稿；
- 流程咨询：翻十几个文件 30 分钟 → 秒级即问即得。

反向诊断成果：AI 输出"该不该改、先改哪个、怎么改"的清单，替代了过去要开多场评审会、翻数月历史文档的人肉梳理。

## 6. 可信度判断

**判断：内部一手实践、真实落地，但 ROI 数字是宣传口径，需要打折看。**

可信的部分：

- 封样责任主体（PQE vs TPM）案例有具体业务场景、判断逻辑和对比表格，是真实问题的颗粒度；
- "自由审批硬凑评审、群里人肉催办"的痛点描述非常真实；
- 反向诊断四步法（画像 → 体检 → 分级 → 联合评审）有方法论、有录屏验证、有具体对象（职能分工机制）；
- 明确说当前知识库只覆盖产研类流程、权限跟随流程库——边界诚实。

需要打折的部分：

- 62.6 倍 ROI、10,616 H、356.7 万元这些数字没有给出计算口径：10,616 小时除以年是多少人的使用量？提效时数是实测还是按"每次查询节省 30 分钟 × 会话量"外推？折算单价是多少？
- "1 人月 + Token 1k" 的投入口径大概率只算了显性开发投入，未算知识库治理、流程规则梳理、内测推广的隐性成本；
- 每周 200+ 会话量是活跃度指标，不直接等于 10,616 H/年的提效。

结论：**平台真实、方法真实、ROI 数字当故事听。**

## 7. 对我们当前项目的启发

### 7.1 "AI 反向诊断流程资产"是一个新场景形态

大多数 AI 应用是"帮人执行任务"，这个案例是让 AI 审视**制度资产本身**：

```text
不是"帮你走流程"，而是"告诉你哪些流程不该存在、边界不清、该合并淘汰"
```

这正好对应我们 insights 里反复出现的判断：AI 的价值不在回答问题，而在**审视和重构业务对象本身**。类似形态还可以出现在：

- 审视 SOP 库：哪些 SOP 冲突、过期、重复；
- 审视指标口径：哪些指标定义漂移、口径打架（对应 `09` 的语义治理）;
- 审视供应商规则：哪些质量协议条款缺数据权利（对应 `12-03`）；
- 审视测试覆盖：哪些 RMA 模式没有对应的 screen（对应 `12-02`）。

### 7.2 "四步法"本质是一个可复用的诊断任务闭环

画像 → 体检 → 分级开方 → 联合评审闭环，和 `04-05` 的任务控制面完全同构：

| LI-PAS / 通用闭环 | 本案例 |
|---|---|
| 上下文补全 | 通读存量流程库，画像职能分工底账 |
| 证据提取 + 案例比对 | 规则库 + 历史案例扫描四类风险点 |
| 结论分级 | 红线 / 优化 / 留观三档 + 优先级 |
| 人工校准闭环 | 流程内外联合评审、逐条会签 |

**结论分级 + 人工联合评审收口**这个组合，和 LI-PAS 的"四档结论 + 人工归并校准"是同一个模式——这已经是第二个验证该模式的案例。

### 7.3 嵌入原系统而非新建系统

"不新建一套系统，把 AI 引擎嵌回原有流程库"——直接印证 `04-05` 的"厚场景，薄系统"和"权威数据留在原系统"原则。审批、评审、会签收回原生入口，避免了再造一套烟囱。

### 7.4 ROI 数字的教育意义

这个案例的数字是"AI 项目如何向管理层汇报"的典型样本：

- 显性投入极小（1 人月）+ 外推提效极大（62.6 倍），是 AI 项目汇报最常见也最脆弱的算法；
- 对应 `04-01` 经营 AI 账本的观点：没有成本对象和口径的提效数字，本质是宣传口径；
- 我们自己做 EVI / 价值归因时，要避免同样的外推陷阱，先说清计算口径。

### 7.5 最值得抄的设计

1. **反向诊断四步法**（画像 → 体检 → 分级 → 联合评审）可直接移植到 SOP 库、指标口径、供应商规则等任何制度资产上；
2. **AI 合规预审前置**：在提交专家评审前先拦"职责边界不清、引用缺失、格式不合规"这类硬伤，省专家时间；
3. **权限跟随原系统 ID**：知识库权限不做第二套，直接继承流程库查看 / 发布权限；
4. **从一条最头疼的流程开始**的推广话术："找出职责不清、审批重复、卡点最多的那一条当试验田"——比宏大计划有效。

## 8. 后续想实测 / 追问的问题

- 10,616 H 提效的计算口径（会话量 × 单次节省时长？实测还是外推？）；
- 反向诊断出的清单里，"必须改"红线条目最终闭环了几条？改造后效果如何验证？
- 职能分工底账（结构化的角色 / 职责 / 输入输出 / 卡点）是否持续更新，还是一次性快照？
- AI 诊断的误报率如何？联合评审里 AI 结论被驳回的比例？
- 流程知识库的质量治理：过期流程文件如何淘汰，谁负责标注"已被迭代版本取代"；
- 通用 AI 工具答错 TPM 的那个对比，是冷启动时的真实记录还是事后构造的演示；
- 后续是否会把联合评审的逐条确认 / 驳回记录，用于优化诊断规则或做 SFT。
