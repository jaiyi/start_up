# 应用案例

本目录用于持续积累看到的 AI 应用介绍：真实落地案例、产品使用案例、客户场景、公开分享的应用实践。

与 `../` 下其他目录的区别：

- 其他目录按"产品类型 / 能力形态"分析产品本身；
- 本目录关注**具体应用场景里 AI 是怎么被用的**：谁在用、解决什么问题、任务流怎么组织、效果如何、哪些是真实落地、哪些只是宣传。

## 收录范围

- 企业内真实 AI 应用案例（设备维修、质量闭环、供应质量、采购、客服等）；
- 厂商公开的客户案例 / 白皮书 / 发布会演示；
- 个人或团队的高质量 AI 使用实践分享；
- 值得借鉴的 Agent / 工作流 / 知识库实际用法；
- 反面案例（demo 花哨但落地失败）同样有价值。

## 每篇案例建议记录

1. 案例来源（链接 / 截图 / 公开资料）；
2. 一句话：谁在什么场景用 AI 解决什么问题；
3. 任务流拆解：输入 → AI 参与 → 人工确认 → 执行 → 反馈；
4. 用到的能力：模型、RAG、Agent、工具调用、MCP、SFT 等；
5. 效果与证据：有没有量化指标，是实测还是宣传口径；
6. 可信度判断：真实落地 / 疑似 demo / 无法验证；
7. 对自己项目的启发；
8. 后续想实测或追问的问题。

## 文档命名建议

案例文档名统一用中文，少用字母代称，要能直接看出系统是干什么的：

```text
<公司或领域>-<系统功能总结性描述>.md
```

例如：

```text
理想汽车-车载性能稳定性问题分析助手.md
美的-质检视觉AI案例.md
```

不要用内部代号或英文缩写作文件名（如 LI-PAS、MIP 之类），代号写在文档正文里即可。

同一来源多个案例可建子目录：

```text
application-cases/理想汽车/
application-cases/OpenAI客户案例/
```

## 累积判断维度

随着案例增多，后续可以做横向归纳，例如：

- 哪些场景是真实高频刚需（每天用）；
- 哪些场景只在发布会里出现；
- 人机分工的常见形态（AI 建议 + 人确认）；
- 数据 / 知识 / 工具 / 权限四个基建里，案例实际缺哪块；
- 案例背后的任务闭环 schema 是否可以抽象复用。
