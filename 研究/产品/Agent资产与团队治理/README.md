# Agent 资产与团队治理产品分析

本目录用于分析 Agent Skill、团队 Harness 资产、Agent 组织、任务分配、预算审批、发布分发与持续治理产品。

这里关注的是 Agent 如何作为团队成员和可管理资产进入组织，而不是单个 Agent 如何在一次任务中运行。

## 关注重点

- Skill、规则、MCP、模型配置和 Agent 模板的注册、版本、审核与分发；
- Agent 组织结构、目标、任务、心跳、预算、审批和责任边界；
- 团队级上下文、代码图、知识资产和工作约定如何注入 Agent；
- 运行结果、失败摩擦和用户反馈如何反哺资产迭代；
- 多 Agent 协作、权限、RBAC、审计、成本控制和发布安全；
- 开源项目的自托管能力，以及与现有企业系统的集成方式。

## 评估维度

1. 资产模型：Skill、规则、工具、模型和 Agent 是否有清晰契约；
2. 生命周期：创建、版本、审核、发布、回滚、废弃是否完整；
3. 组织治理：团队、角色、权限、责任人和审批链是否明确；
4. 执行约束：预算、并发、心跳、任务领取和失败处理是否可控；
5. 反馈闭环：是否记录 friction、采纳率、失败原因和改进建议；
6. 互操作性：是否支持 MCP、A2A、Git、API、Webhook 或企业身份系统；
7. 安全性：是否有最小权限、审计、敏感信息保护和发布前验证。

## 对本仓库的关系

本目录沉淀外部产品事实和横向比较。关于自己的 Agent 团队、Skill 注册、任务控制和发布架构，应进入 `项目/`；经过项目验证后可复用的方法，再进入 `知识/`。
