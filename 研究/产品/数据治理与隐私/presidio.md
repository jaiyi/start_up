# Presidio：敏感信息识别与去标识化工具链

> 调研范围：公开文档与项目主页；未安装、未运行识别器，也未用真实数据验证召回率。Presidio 是**数据治理链路中的 PII 处理组件**，不是带资产目录、血缘和企业权限的一站式数据治理平台。

## 1. 一句话定位

Presidio 提供文本、图像以及结构化/半结构化数据中的敏感信息识别与匿名化能力。其官方文档说明项目已转为 **Data Privacy Stack 社区维护**；历史上的 Microsoft 文档入口跳转到社区文档。这里按用户提供的仓库地址和当前社区文档研究，不将旧归属误写为当前产品负责人。

## 2. 官方资料可确认的能力

| 模块 | 职责 | 不应误解为 |
|---|---|---|
| `presidio-analyzer` | 在文本中发现 PII/敏感实体；支持预定义与自定义识别器、NER、正则、规则、校验及上下文 | 对所有行业、语言和格式的自动完备识别 |
| `presidio-anonymizer` | 对已识别的实体应用去标识化算子 | 自动确保匿名结果不可重识别 |
| `presidio-image-redactor` | 结合 OCR 与识别能力处理图像中的文本 PII | 通用图像隐私审查或任意视觉敏感内容识别 |
| `presidio-structured` | 处理结构化及半结构化数据 | 数据库权限/血缘/数据质量平台 |

官方列出 Python/PySpark、Docker、Kubernetes 等运行方式，以及自定义识别器、外部检测模型集成和 HTTP 服务示例；这些是**文档列出的选项**，不是本地已验证的部署清单。是否适合中文业务术语、扫描件、表格单元格、混合语言和行业实体，须按具体数据与识别器单独验证。

## 3. 放进 Agent / 知识工程链路时的位置

```text
获授权的数据源 → 解析/OCR → Presidio 识别 + 自定义规则
                    → 人工复核高风险命中/漏检 → 脱敏副本 → 知识库或评测集
原始资料 → 单独的访问控制/保留策略/删除流程；不直接混入公开示例或日志
```

可在知识入库、用于模型训练前的数据筛查、检索返回给 Agent 前的输出检查等环节评估其作用；**不能**用检测结果替代源系统授权、分级分类、日志最小化或最终人工审核。对特定实体要把识别位置、实体类别、置信度和匿名化结果作为可核查的处理记录；处理记录本身也可能敏感，需最小化保存。

对团队知识工程和 SPC 场景，可以先用完全合成的“订单编号、姓名、电话、设备标识”样例建立测试集：分别测误报、漏报、中文变体、跨行文本、OCR 噪声和脱敏后可读性。**未获授权的真实业务原文不能因此进入测试或外部服务。**

## 4. 重要边界与选型判断

- 官方明确警告：自动检测**不能保证找到所有敏感信息**，需要附加系统和保护措施；因此“通过 Presidio”不等于“符合合规要求”。
- 文本实体检测与匿名化是两步：识别范围、识别器版本和算子配置变化会改变输出；上线前应测漏检和过度脱敏，并做好版本化回归。
- 对内部代号、设备编号、行业字段等，应由团队定义实体词典/规则，并明确哪些是敏感信息；现成的国际 PII 类型未必覆盖业务约束。
- 如需要文档权限、审批、组织身份、血缘、资产目录或审计控制面，要组合现有数据治理系统；Presidio 不能独自承担这些职责。
- 用户提供的仓库 `main` 分支 `LICENSE` 页面标注 MIT；正式采用仍须固定版本并核对模型、OCR、外部依赖等各自许可证。本文未验证具体版本、性能或云端部署安全配置。

## 5. 后续可验证的最小实验

1. 只用合成文本及合成图片构建命中、漏检和误报用例，固定实体类型与识别器配置。
2. 对比原始识别和加入自定义规则后的精确率/召回率；单独检查中文姓名、手机号、工号、机器码和 OCR 噪声。
3. 对比替换、遮盖等算子带来的下游检索可用性，确保脱敏副本与原文分离且无敏感日志。
4. 审查部署边界、依赖许可、模型下载及网络调用，再决定是否接入知识入库或运行时输出检查。
