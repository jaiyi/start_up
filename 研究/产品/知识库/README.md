# Knowledge Base 产品分析

本目录用于分析知识库、RAG、Wiki、企业知识管理和 Agent Knowledge Backend 产品。

## 关注重点

- 文档上传、解析、切片、索引、召回和重排机制；
- Wiki、派生页面与源文档的一致性；
- Agent 是否能更新源文档，还是只能生成带引用的派生内容；
- 权限、引用溯源、版本管理、知识质量和反馈治理；
- 与 MCP、数据库、业务系统和 Agent Runtime 的连接方式；
- 是否适合承载动态状态，或只能作为稳定知识层。

## 一句话判断

```text
Knowledge Base 管理稳定知识和可追溯上下文，不替代业务数据库、动态任务状态或审计系统。
```

## 与 Agent Workspace 的边界

- `Agent工作台/` 关注 Agent 执行后的文档、表格、HTML、报告和协作产物；
- 本目录关注可持续维护的源知识、切片、索引、引用和问答后端；
- 一个知识库产品可以作为 Agent Workspace 的知识后端，但这不改变它的主分类；
- WorkBuddy、飞书等工作台可以沉淀文档和产物，但不因此自动成为知识库产品。

## 与动态状态的边界

```text
业务数据库 / 任务系统 / 业务 API
→ Agent Runtime 受控读取和写回
→ Knowledge Base 沉淀稳定规则、SOP、案例、复盘和引用
```

库存、订单、工单、权限、审批、反馈等动态事实应进入事务系统或数据库；知识库可以保存经审核的总结、规则和案例，但不能成为动态业务状态的唯一 source of truth。

## 评估维度

1. 数据接入与解析：格式、OCR、表格、代码、网页和增量更新；
2. 检索质量：切片、混合检索、重排、过滤和引用；
3. 知识治理：版本、审核、归档、冲突和过期检测；
4. 权限隔离：租户、空间、文档和字段级权限；
5. Agent 接入：API、MCP、工具调用、上下文格式和写回边界；
6. 部署与成本：私有化、存储、向量数据库和模型依赖；
7. 可验证性：答案引用、原文定位、评测集和反馈闭环。
