# 数澜科技 AI 数据基座产品调研

## 0. 调研边界说明

本文基于已阅读的公开访谈《AI时代，数据中台焕发新生？|爱分析访谈》以及我们对 AI 原生数据平台的分析框架整理。

由于当前会话没有直接联网检索官网能力，本文不把具体产品版本、套餐、客户案例细节作为确定事实；对官网最新功能、产品矩阵和交付边界，后续仍需要官方资料复核。

---

## 1. 一句话定位

数澜科技可以被视为中国数据中台厂商向 **AI 数据基座 / 本体语义层 / 数据智能体** 演进的代表样本。

它试图完成的转变是：

```text
数据中台
→ AI 数据基座
→ 本体语义层
→ 行业模型
→ 企业级数据智能体
```

核心判断是：

```text
AI 不是替代数据，而是倒逼企业重新建设数据能力。
```

---

## 2. 产品背景

数澜早期定位在数据中台。过去几年，数据中台经历过高热、质疑和收缩：

- 很多企业把数据中台理解成大数据平台或报表平台；
- 很多项目重数据汇聚、轻业务闭环；
- 平台建完后不知道业务如何使用；
- 一次性交付多，资产持续运营少；
- “拆中台”成为行业反思。

但大模型进入企业后，企业重新面对基础问题：

```text
数据在哪里？
数据质量如何？
数据能否支撑 AI 做出可靠、可执行的判断？
```

因此，数澜的观点是：

```text
过去以数据交换为核心的数据中台，正在向以模型交换为核心的 AI 数据基座演进。
```

---

## 3. 核心能力拆解

### 3.1 数据基座

数澜所说的数据基座不是单纯数据库、数仓或湖仓。

更接近一种能力体系：

- 数据接入；
- 数据清洗；
- 数据治理；
- 数据资产化；
- 数据交换；
- 数据服务；
- 原生数据资产目录；
- 高质量数据集生产；
- 标准、流程、对象和语义管理。

其中最重要的目标是：

```text
持续输出高质量数据集。
```

这和 AI 原生数据平台的供给层高度相关。

### 3.2 本体与语义层

数澜把本体和语义层视为企业 AI 的“专属世界观”。

通用大模型有通用知识，但缺少每家企业内部的：

- 业务术语；
- 对象关系；
- 指标口径；
- 规则约束；
- 系统差异；
- 行业 Know-how；
- 企业私域知识。

语义层更像：

```text
统一翻译器 + 业务地图。
```

本体更像：

```text
描述业务对象本质、关系和逻辑动作的概念体系。
```

它的价值是减少：

- 语义歧义；
- 指标口径冲突；
- 跨系统认知偏差；
- AI 幻觉；
- Agent 错误调用工具。

### 3.3 从数据交换到模型交换

过去数据中台强调：

```text
把数据接进来、管起来、给 BI 和应用使用。
```

AI 时代更重要的是：

```text
数据 + 行业知识 + 企业知识库 + 通用大模型能力
→ 训练 / 适配客户自己的模型
→ 叠加智能体 Skill
→ 服务风控、营销、经营管理、供应链、财税等业务场景。
```

因此，“模型交换”不是交换模型文件，而是交换一套可复用的业务智能能力包：

- 高质量数据集；
- 行业知识；
- 企业知识库；
- 本体语义层；
- 模型能力；
- Agent Skill；
- 场景评测；
- 反馈闭环。

### 3.4 数据智能体

数澜的 AI 数据基座最终会走向企业级数据智能体。

这里的智能体不应只是 ChatBI，而应该能：

- 理解业务问题；
- 找到可信数据；
- 调用数据服务；
- 结合企业知识库；
- 受本体和语义层约束；
- 生成分析、建议或动作；
- 将反馈回流到数据资产和业务规则中。

---

## 4. 与 AI 原生数据平台的关系

数澜路线和 AI 原生数据平台的对应关系：

| AI 原生数据平台维度 | 数澜相关能力判断 |
|---|---|
| 计算 | 需要进一步验证是否具备统一异构算力、训推一体、向量计算等底层能力 |
| 供给 | 数据基座、高质量数据集、结构化与非结构化数据资产 |
| 治理 | 数据治理、标准、流程、对象、语义、本体 |
| 消费 | 数据智能体、行业模型、业务场景落地 |
| 语义 | 本体与语义层是重点方向 |
| 安全 | 面向私有化和高合规行业，但具体安全机制需复核 |

整体看，数澜不是从云湖仓或通用大模型平台切入，而是从中国数据中台和私有化企业数据治理经验切入。

---

## 5. 优势

1. **路径顺滑**：从数据中台到 AI 数据基座，逻辑上延续原有能力。
2. **抓住核心矛盾**：企业 AI 幻觉和效果差，很多根因确实在数据质量和语义不清。
3. **本体语义层表述明确**：比单纯 ChatBI 更接近 AI 原生数据平台的核心。
4. **适合私有化和高合规行业**：这类行业更需要数据治理、权限和本地部署。
5. **强调资产持续运营**：从项目交付走向数据资产运营，是平台型厂商的重要升级方向。

---

## 6. 短板 / 未验证点

需要继续验证：

- 是否有成熟的向量库、GraphRAG、Agent Runtime 和 MCP / API 工具体系；
- 本体建模是否依赖重交付，能否规模化复制；
- 数据智能体是否已经进入核心业务流程，还是主要停留在问数 / 问答；
- 是否能治理模型、Prompt、Skill、Agent 行为和执行轨迹；
- 是否有标准化的评测、反馈闭环和价值归因能力；
- 底层湖仓、计算、推理、向量检索能力是自研、集成还是依赖第三方。

---

## 7. 适用场景

更适合：

- 央国企；
- 军工、金融、制造、能源、政务等高合规行业；
- 已经有数据中台或数据治理基础，但 AI 落地效果不佳的企业；
- 需要私有化部署、行业知识沉淀、本体语义层和智能体应用的企业。

不一定适合：

- 只需要轻量 RAG 知识库的小团队；
- 数据治理基础薄弱但又只想快速做一个 ChatBI 的项目；
- 预算和组织协同能力不足以支撑本体 / 数据资产长期运营的客户。

## 8. 对我们当前项目的启发

### 8.1 对家庭营养师 Agent

家庭营养师项目虽小，但可以借鉴“AI 数据基座”的思想：

```text
Postgres 动态状态 + Markdown 稳定知识 + WeKnora 检索 + MCP 工具 + 用户反馈闭环
```

就是一个微型 AI 数据基座。

关键不是数据规模，而是：

- source of truth 清晰；
- 菜谱、库存、偏好、反馈有语义；
- Agent 不能绕过 MCP 任意改数据；
- 用户反馈能沉淀为长期规则；
- 推荐结果能解释来源。

### 8.2 对连山产品

连山如果面向工业 AI，可以重点吸收数澜路线：

- 工业数据基座；
- 质量 / 工艺 / 设备本体；
- 行业知识库；
- 数据智能体；
- 私有化和高合规交付；
- 从 demo 交付转向数据资产持续运营。
