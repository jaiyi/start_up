# 03 · 经验资产化：从经验到 Skill、剧本与图谱

> 本文比较理想汽车案例中“把个人经验变成组织能力”的不同路径。它描述的是研究抽象，不代表各案例已有统一资产平台或成熟治理流程。

## 2. 统一资产生命周期

```text
个人经验 / 任务轨迹
  ↓
原始证据与上下文留存
  ↓
候选知识、Skill、规则或剧本
  ↓
人工验证 / 复现 / 对照测试
  ↓
owner 审核与适用范围确认
  ↓
版本发布和权限分发
  ↓
任务调用与结果反馈
  ↓
复核、更新、降级、撤回或废弃
```

关键原则：

- 轨迹可以自动记录，资产不能自动无审核发布；
- 相似结果不等于相同根因，成功一次不等于通用方法；
- 失败案例、适用条件和不适用条件必须与成功路径一起保存；
- 知识、Skill、剧本和图谱是不同资产，不应只换名字重复维护；
- 候选资产和已发布资产必须分区，并且能够追溯来源。

## 3. 四种资产的边界

| 资产 | 主要回答 | 适合内容 | 不应承担 |
|---|---|---|---|
| 知识条目 | 事实、概念、案例和证据是什么 | 来源、定义、适用范围、证据和失效条件 | 隐式执行动作 |
| Skill | 如何完成一类任务 | 输入、步骤、工具、判断点、输出和失败路径 | 没有权限约束的任意系统操作 |
| 剧本 | 如何按固定流程重复运行 | 触发、编排、参数、调度、验收和异常处理 | 代替业务审批和责任签字 |
| 图谱 | 对象如何关联 | 实体、关系、版本、依赖和影响链 | 没有来源的“常识推断” |

例如：

```text
维修案例 = 知识条目
维修诊断步骤 = Skill
每周设备健康巡检 = 剧本
设备—故障—工单—零件—人员关系 = 图谱
```

## 4. 发布门槛

### 4.1 低风险知识

允许先进入候选区：

- 来源清楚的定义、日志字段和公开文档；
- 已完成脱敏的历史案例；
- 可复现的查询和报告模板。

仍需记录来源、版本、适用范围和复核日期。

### 4.2 可执行 Skill / 剧本

至少需要：

- 明确输入 schema 和输出 schema；
- 工具权限和危险动作清单；
- 成功标准、失败模式和降级状态；
- 最小测试集和代表性反例；
- owner、版本、变更记录和回滚方式；
- 对生产、真实硬件、敏感数据和外部发送的人工门槛。

### 4.3 组织级规则

自然语言规则、质量规则、安全规则和设变规则不应直接在对话中生效。建议流程：

```text
自然语言提案
  → 结构化规则候选
  → 冲突/覆盖/边界测试
  → 历史数据回放
  → 业务 owner 审核
  → 灰度发布
  → 监控误报、漏报和人工覆盖
  → 正式发布或撤回
```

## 5. 防止错误经验固化

必须同时保留：

- 当时观察到的原始证据；
- AI 的推断和置信度；
- 人工修正内容；
- 最终确认结论；
- 结论适用的版本、对象和环境；
- 后续复现结果；
- 被否定、过期或撤回的路径。

以下情况不得直接升级为组织资产：

- 只有一次成功运行；
- 只有模型生成，没有原始证据；
- 只在单一版本、单一设备或单一人员上验证；
- 失败路径没有解释；
- 规则可能影响安全、生产、真实硬件或工程变更；
- owner、版本和撤回机制缺失。

## 6. 对当前项目的映射

### SPC / 制造

```text
异常分析轨迹
  → 候选失效模式和分析 Skill
  → 工程师复核
  → 规则/剧本版本化
  → 在隔离数据上回放
  → 才能用于生产辅助
```

### 家庭营养师

```text
对话建议
  → 候选菜单/食材计划
  → 用户确认
  → 实际餐食事件与库存事件
  → 反馈复盘
  → 才能更新推荐规则
```

计划不能直接变成事实，AI 的建议也不能直接变成业务状态。

## 7. 当前结论

1. “经验 → Skill/剧本/图谱”是多个案例的共同主线，但各案例治理成熟度不同。
2. 最重要的分界是“自动捕获轨迹”和“人工审核后发布资产”。
3. 组织级资产必须有 owner、版本、证据、适用范围、失败模式和撤回机制。
4. 高风险领域应采用候选、灰度和人工确认，不应追求一次对话直接固化规则。
