# 02 · 专业工具接入：从脚本执行到 Agent 直连

> 本文比较理想汽车案例中的专业工具接入模式。它不是生产安全规范，也不证明任何案例已经具备企业级权限、隔离、审计和恢复能力。

## 2. 控制粒度谱系

```text
只读查询
  → 生成脚本，人工执行
  → 低风险批处理自动执行
  → Agent 细粒度交互
  → 敏感写入
  → 不可逆操作 / 生产操作
```

控制粒度越细，交互效率越高，但模型错误、工具误用、权限越界和状态漂移的风险也越高。不能以“用了 MCP”“有 API”直接推出“可以安全自动执行”。

## 3. 统一工具调用协议

无论是 CATIA、TRACE32、CAE 还是研发系统，每个高影响工具调用都应尽量遵循：

```text
1. 解析输入和授权范围
2. 校验目标、版本、环境和前置状态
3. 生成命令或候选动作
4. 执行前人工确认（敏感操作）
5. 执行命令
6. 读取真实状态和结果
7. 与预期值、约束和容差比对
8. 生成审计记录
9. 异常时降级、停止、补偿或回滚
```

“工具返回成功”不等于“业务动作成功”；“命令已发送”不等于“目标状态已改变”；“结果为空”也不等于“没有问题”。

## 4. 权限分级建议

| 级别 | 典型动作 | 默认策略 | 必要证据 |
|---|---|---|---|
| L0 只读 | 查询状态、读日志、读模型、读指标 | 可自动，但仍需身份和范围 | 输入、来源、返回值 |
| L1 生成候选 | 生成脚本、SQL、ECR 草稿、维修方案 | 自动生成，人审后使用 | 候选内容、版本、差异、审批 |
| L2 低风险执行 | 测试环境查询、隔离仿真、可重复计算 | 在授权环境自动执行 | 环境、参数、结果、重试 |
| L3 可改变状态 | 提交任务、改测试数据、设断点、改变临时模型状态 | 显式确认和可恢复 | 前后状态、操作者、回滚点 |
| L4 敏感写入 | 写寄存器、写内存、改业务记录、批量建 ECR | 默认阻断，逐次授权 | 双重确认、审计、失败处置 |
| L5 不可逆/生产 | 烧录、擦除、生产部署、作业许可、ECN 发布 | 不由 Agent 单独执行 | 现场/审批责任人、隔离、回滚/应急方案 |

具体案例的实际等级仍需通过代码、配置和授权材料核验；本表是研究和设计建议。

## 5. 两种主要架构的取舍

### 5.1 生成脚本 + 人执行

优点：

- 脚本可以静态审查；
- 人在专业软件界面看到真实状态；
- 执行边界清晰；
- 适合单次、探索性但可预先编排的任务。

缺点：

- 人工执行成本高；
- 宏运行环境、版本和输入准备容易出错；
- 结果回读仍需要标准化。

CATIA 装配路径校核是当前案例中的保守标杆。

### 5.2 Agent 直连工具

优点：

- 适合假设—验证循环；
- 可以实时读取状态并调整策略；
- 适合批量、重复和交互式任务。

缺点：

- 工具原语越多，危险动作越容易被误调用；
- 权限和审计必须落在工具层，不能依赖提示词；
- 状态漂移、超时、部分成功和恢复困难；
- 真实硬件和生产系统的失败成本高。

DebugForge 是直连能力的有价值样本，但文章目前没有充分证明其生产级安全机制。

## 6. 最小安全基线

在任何工具接入真实工程环境前，至少需要：

- 明确工具清单和危险动作清单；
- 只读默认和最小权限；
- 目标环境、项目、版本和身份校验；
- 敏感动作的显式人工确认；
- 命令—状态—读回—预期比对；
- 输入、输出、操作者、版本和审批审计；
- 超时、部分成功、重复执行和通信中断处理；
- 可恢复快照、回滚或现场处置方案；
- 失败结果进入 `UNVERIFIED`/待人工裁决，而不是自动判定通过。

## 7. 对 SPC/制造项目的迁移判断

适合优先自动化：

- 读取机台、批次、曲线和统计结果；
- 生成分析查询、报告和候选异常解释；
- 在沙盒中重跑统计和规则；
- 生成 PCN、lot release 或维修工单草稿。

需要高门槛：

- 写入机台参数、测试程序、配方和寄存器；
- 修改生产数据库状态；
- 发布 PCN、放行 lot、关闭异常；
- 对真实设备、晶圆、芯片和产线发出执行动作。

## 8. 当前结论

1. 工具接入的关键不是协议名称，而是控制粒度、授权边界和读回审计。
2. 有确定性引擎时，AI 应负责编排和解释，事实判断回到专业工具。
3. 高风险场景优先采用“生成候选/脚本 + 人执行”，验证充分后再考虑直连。
4. 生产环境、真实硬件、不可逆写入和安全相关动作不应由 Agent 单独承担。
