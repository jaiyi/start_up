# 理想汽车案例治理矩阵

> 版本：v0.1 · 更新日期：2026-10-16
>
> 本矩阵是研究索引，不是理想汽车内部授权、生产架构或安全认证文件。除来源明确给出的内容外，未知字段均标为“待核验”。“已验证”只表示本文掌握了对应来源或运行证据，不代表适合直接迁移到生产环境。

## 使用规则

- **来源描述**：原始材料声称的能力，不能自动等同于事实或合规性。
- **研究判断**：本文作者基于材料形成的归纳和风险判断。
- **验证状态**：公开代码可复核、内部文章、用户提供材料、试点或未知，应分开记录。
- **权限分级**：只读 → 生成候选/草稿 → 低风险执行 → 敏感写入/不可逆操作。
- **人工责任**：AI 可以准备、提示和编排，但审批、发布、现场安全和真实硬件操作必须有明确责任人。
- **高风险默认**：没有工具级权限、审计、读回校验、失败补偿和回滚证据时，不得把案例直接迁移到生产。

## 高风险专题入口

### 1. 专业工具与真实硬件

优先对照三维装配路径校核、工艺设计合规评审和 DebugForge：

```text
确定性引擎/硬件做事实判断
→ AI 做编排和解释
→ 读回实际状态
→ 与预期比对
→ 异常降级为未验证或待人裁决
```

DebugForge 的写内存、写寄存器、烧录、擦除、执行脚本和复位等动作，当前只能作为待治理的敏感权限，不得因 MCP 工具存在就视为安全可用。

### 2. 设变与 ECR

设计变更助手、工艺设计合规评审和工程设变断点监控属于同一业务链的不同环节。后续专题应统一登记：规则版本、数据来源、评审证据、候选 ECR、人工审批、ECN 发布、执行断点和结果回流。自动发现问题不等于自动批准变更。

### 3. 安全生产与现场执行

工厂安全、设备维修和专业工具案例都必须把“现场执行”与“AI 建议”分开。作业许可、隔离、维修、验收、应急处置和安全签字需要明确人工责任主体；AI 预审记录的法律证据属性目前均为待核验。

### 4. 经验资产化

LI-PAS、DebugForge、Sage、工厂安全、知识共享和设变评审都涉及经验 → Skill/规则/剧本 → 复用。统一要求：原始轨迹留存，候选资产与已发布资产分开，指定 owner，经过验证和版本审批后再共享；失败路径不得自动固化。

## 待补证据清单

- 各案例实际部署环境、用户范围和生产状态；
